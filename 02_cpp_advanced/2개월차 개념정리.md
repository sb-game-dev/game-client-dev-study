### 1일차 (260409) c++개론, class
<details>
  <summary>c++개론</summary>

- 절차 지향 프로그래밍: ~하다(동사) 중심의 언어적 구성  
- 객체 지향 프로그래밍: 주어 중심의 언어적 구성, 프로그래밍을 구성하는 각 객체간의 소통  
- 객체 지향은 속도가 느리지만 유지보수가 편리함, 절차 지향 프로그래밍을 속도가 빠르지만 유지보수가 어려움.  
  
- 객체: 실세계를 구성하는 하나의 실체  
- 객체지향: 실세계를 그대로 프로그래밍에 구현  

- 객체: 인스턴스 + 클래스

- 추상화: 공통된 요소로 추출하는 과정 / 작업
- C++은 추상화!  
</details>

<details>
  <summary>클래스</summary>

> 클래스 = 데이터(변수, 상수) + 기능(함수)

> 클래스의 속성
1. 은닉화
2. 캡슐화
3. 상속성
4. 다형성

- 접근제어 지시자 (private, public): 변수 또는 함수의 접근을 제어하기 위해 만든 키워드.
- 멤버 변수는 private에 선언해야하고 private에 선언하는 경우 클래스 외부에서 접근할 수 없음
- 멤버 변수를 클래스 밖에서 접근하려면 access method를 통해 접근할 수 있다.
- access method를 제외한 멤버함수는 헤더파일에서 몸체를 만들 수 없으므로 cpp파일에서 만들 때는 Cobj:: 연산자를 사용  
```cpp
class CObj
{
private: //멤버 변수는 무조건 private
    int m_ix;
    int m_iy;
public: //access method, 멤버 변수별로 각각 만들어야 함.
    int GetX() {return m_ix};
    int SetX(int iX) {m_ix = iX};
public: //멤버 함수는 public으로(재사용)
    void Render();
};

void CObj::Render()
{
    cout << m_ix << endl;
}

int main()
{
    CObj Obj = {10,20};
    Obj.SetX(40);
    cout << Obj.GetX(); //access method를통해 x값 가져온 뒤 cout으로 출력 
    Obj.Render(); //멤버함수를 통해 값 출력
}
```

### 2일차 (260410) class 생성자, 소멸자

<details>
  <summary>class 규칙</summary>

1. Initialize()  
  - 객체 생성시 해야 할 작업들 모아놓는 함수  
  - 주로 멤버변수 초기화.  
2. Update()  
  - 매 프레임마다 실행해야 하는 작업들 모아놓는 함수  
  - 클래스 주요 기능들.   
3. Release()
  - 사용한 모든 메모리 반환하는 코드 모아놓는 함수  

위 세가지는 필요하지 않더라도 꼭 만들어야 함.
</details>


<details>
  <summary>생성자</summary>

- 생성자: 객체를 생성하고 멤버변수를 초기화하기 위해 존재  
- 객체 생성 과정: 메모리할당 -> 생성자 호출  
- default 생성자: 객체 생성 시점에 반드시 호출, 생성자가 하나라도 있다면 default 생성자는 호출되지 않음.  
- default 복사 생성자: 복사 생성자가 하나라도 있다면 호출되지 않음.  
```cpp
class CObj
{
public:
  CObj();
  CObj(int iNum); // 생성자는 매개변수가 있을 수 있다. 함수 오버로딩과 같은 방식으로 작동함. 
};
```
</details>

<details>
  <summary>소멸자</summary>

- 소멸자: 객체 사용이 더이상 이루어지지 않을 때 자동으로 호출.  
- 객체 소멸 과정: 소멸자 호출 -> 메모리 반환.
```cpp
class CObj
{
public:
  ~CObj(); // 소멸자는 매개변수X. 종료시 호출되기 때문. 
}

CObj::~CObj(){Release()}; // 보통 메모리 반환 함수 실행.
```
</details>

### 3일차 (260413) 상호 참조와 전방선언

<details>
  <summary>상호 참조와 전방선언</summary>

- 전방선언: 나중에 정의될 타입임을 먼저 밝히는 것  
- 상호참조: 클래스 A와 B가 서로를 참조하는 상황  
- 전방선언없이 상호참조를 하면 무한 의존 문제 발생
```
-> A객체를 생성하려면 메모리를 할당해야함. 
-> 이때 B클래스 자료형인 멤버변수의 메모리 크기를 알아야 하는데 이때 B클래스 접근을 하게됨.
-> 또 B클래스에 접근을 하면 A클래스의 자료형을 알아야 해서 A클래스에 접근을 하게 됨.
-> 무한 의존
```

- 해결방법 : 포인터 + 전방 선언

**1. 헤더파일 분리**
> A.h
```cpp
class B;

class A
{
  B* m_pB;
  // 포인터 타입으로 선언해야 함
  // 헤더파일의 경우 class A를 선언하는 부분이기 때문에 class B의 완전한 정보가 필요 없음
  // class A의 메모리 할당을 위해 포인터 + 전방 선언으로 의존성 최소화
}
```

>B.h
```cpp
class A;

class B
{
  A* m_pA; //포인터 타입으로 선언해야 함
}
```

**2. cpp에서 include**
```cpp
#include "A.h"
#include "B.h"
```

### 4일차 (260414) const, static, extern, this 포인터

<details>
  <summary>const와 클래스</summary>

> const 변수

- 멤버변수를 읽기 전용으로 사용하기 위해 const를 붙여서 사용.
- 선언과 동시에 초기화 할 수 있지만 이는 C++11 버전 부터 사용 가능
- 이니셜라이저 초기화 방식을 사용함.  
```cpp
class CObj
{
public:
  CObj(int iA, int iB):m_iA(iA),m_iB(iB){}//이니셜라이저 초기화 방식 
private:
  const int m_iA;
  const int m_iB; 
};
```

> const 함수

- 읽기 전용 함수이고 멤버변수의 가공을 막음
- 멤버 변경 금지의 의미이기 때문에 함수로 사용할 때는 () 마치고 뒤에 붙음.  
- 읽기전용 함수안에서 만든 변수들은 쓰기 가능  
- data영역 쓰기 가능  
- heap영역 쓰기 가능  
- stack영역 쓰기 가능    
- const 함수 내부에서는 const 함수만 호출 가능  
- const 함수가 아닌 경우 멤버 변수의 가공 가능성이 있다고 판단하여 컴파일러가 호출을 막음  
- 하지만 const 함수에서 멤버 변수를 변경할 수 있는 명령어가 있음 (mutable)
```cpp
class CObj
{
public:
	CObj(int iA,int iB) : m_iA(iA),m_iB(iB),m_iSum(iA+iB)
	{
	}

public:
	void Render() {cout << m_iA + m_iB << endl;}
	void Sum_100() const //const 함수
	{
		m_iSum = 100;
		cout << GetSum() << endl;
	}
	int GetSum()const { return m_iSum; }
private:
	const int m_iA;
	const int m_iB;
	mutable int m_iSum;
};

int main()
{
	CObj Obj(10,20);
	Obj.Sum_100();
	return 0;
}

```

- const에 따라 함수 오버로딩도 가능하다.
```cpp
class CObj
{
public:
	CObj(int iA, int iB) : m_iA(iA), m_iB(iB), m_iSum(iA + iB)
	{
	}

public:
	void Render() { cout << m_iA + m_iB << endl; }
	void Render() const { cout << "Hello World" << endl; }

private:
	const int m_iA;
	const int m_iB;
	mutable int m_iSum;
};

int main()
{
	CObj Obj(10, 20);
	Obj.Render(); // const를 안붙인 변수라서 m_iA + m_iB 값이 출력

	const CObj Temp(10, 20);
	Temp.Render(); // const를 붙인 변수라서 "Hello World" 출력
	return 0;
}
```
</details>

<details>
	<summary>static과 클래스</summary>
- static -> data메모리에 저장하겠다. 이후에도 같은 이름의 static 변수라면 같은 메모리를 사용하겠다.  
- 원래 클래스 내부에서 생성한 멤버 변수, 멤버 함수는 생성한 객체 소속이지만 static 키워드를 사용하여 소속을 객체가 아닌 클래스 소속으로 변경함.  
- 그래서 함수나 변수 앞에 static이 붙음.  

> static 변수
- 멤버 변수를 선언하고 초기화는 클래스 외부에서 해야 한다.  
- 객체를 선언하지 않고 사용할 수 있음.  
- 멤버변수가 아니라 클래스 변수라고 부름.  
```cpp
class CObj
{
public:
	CObj() {}
public:
public:
	static int m_iA;
};

int CObj::m_iA = 100;//멤버변수를 클래스 밖에서 초기화 해야 함. 

int main()
{
	cout<< CObj::m_iA << endl; //public 으로 만들어서 바로 접근 가능함.
	return 0;
}
```

> static 함수

- 멤버변수 읽기 쓰기 불가. (클래스 외부 사람이라 생각하면 됨)  
- 클래스 외부 사람이라 내부에 접근할 수 없음.  
- 즉, 멤버 변수에 접근할 수 없음. 다만 클래스 변수(static으로 선언한 변수)는 읽기 쓰기 가능  
- 객체를 안만들고 호출 가능(public으로 선언하는 경우)  
- 소속을 객체가 아니라 클래스로 변경한다는 의미이기 때문에 void 앞에 static이 붙음.  

```cpp
#include <iostream>
using namespace std;

class CObj
{
public:
    static void Func()
    {
        cout << m_iA << endl;
		m_iA = 200;
    }

private:
    static int m_iA;
};

int CObj::m_iA = 100;

int main()
{
    CObj::Func();          // 출력: 100
    cout << CObj::m_iA;    // 출력: 200
}
```
  
</details>

<details>
	<summary>exturn</summary>

- 다른 공간에 선언된 문법이 있음을 알려줌.
- 변수와 함수 모두 사용 가능
- 메모리 용량을 가지고 있지 않기 때문에 초기화 불가능.
- 선언한 자료형과 이름이 완벽히 일치한 상태로 만들어야 함. 

- 예시) main.cpp에 선언한 전역 변수와 전역 함수를 CTemp.cpp에 가져오기
> main.cpp
```cpp
int	g_iNumber = 100;

void	Print() { cout << "hello world" << endl; }

int main()
{
	CTemp		Temp;

	Temp.Render();

	return 0;
}
```

> CTemp.cpp
```cpp
extern int	g_iNumber;		
extern void Print();

void CTemp::Render()
{
	g_iNumber = 200;

	cout << g_iNumber << endl;

	Print();
}
```
</details>

<details>
	<summary>this 포인터</summary>

- this란? : 현재 객체의 주소를 담고있는 포인터
- 멤버함수가 호출될 때 자동으로 생김
```cpp
class CObj
{
privte:
	int Hp;
public:
	void SetHp(int Hp){this->Hp = Hp;} // 매개변수와 멤버변수의 이름이 같을 때 사용
}
```

- 자기자신을 반환할 때
```cpp
class Player
{
public:
    int hp;

    Player* SetHp(int hp)
    {
        this->hp = hp;
        return this;
    }
};
int main()
{
	p.SetHp(100)->SetHp(200);
}
```

- static 함수에서는 사용 불가(static은 객체 소속이 아니라 class 소속이라 현재 객체의 주소를 담는 this 사용 불가)
- this 포인터를 사용하여 객체를 delete 할 수 있음
```cpp
class CObj
{
private:
	CObj() {}
	~CObj() {}
public:
	static CObj* Create()
	{
		CObj* pObj = new CObj;
		return pObj;
	}
	void Destroy() { delete this; }
};


int main()
{
	CObj* Obj = CObj::Create();
	Obj->Destroy();
	return 0;
}
```

- this는 내부적으로 `CObj* const this;` 이 상태이기 때문에 값을 변경할 수 없음.
- 예를 들어 `delete this` 후에 `this = nullptr;` 같은 행위 불가능.

### 5일차 (260416) 복사 생성자, friend

<details>
	<summary>복사 생성자</summary>

- 객체를 새로 생성하면서 다른 객체로 초기화할 때 복사 생성자가 호출된다.  
- 또한 함수의 매개변수를 값으로 전달하거나, 객체를 값으로 반환할 때도 복사 생성자가 호출될 수 있다.  
- 클래스의 멤버 변수로 포인터가 있고, 해당 포인터가 동적 할당된 메모리를 가리키는 경우, default 복사 생성자는 포인터 값(주소)만 복사한다.  
- 이 경우 복사된 객체와 원본 객체가 같은 메모리를 공유하게 된다 (얕은 복사)  
- 만약 소멸자에서 해당 메모리를 delete 한다면, 한 객체가 먼저 메모리를 해제하고, 이후 다른 객체가 다시 delete 하면서 이중 해제 문제가 발생할 수 있다.  
- 따라서 이런 경우에는 default 복사 생성자를 사용하지 않고, 복사 생성자를 직접 정의하여 새로운 메모리를 할당하고 값을 복사하는 깊은 복사를 구현해야 한다.

```cpp
class CName
{
public:
	CName(const char* pName)
	{
		int iLength = strlen(pName) + 1;
		m_pName = new char[iLength];
		strcpy_s(m_pName, iLength, pName);
	}
	CName(const CName& rhs)					// 복사 생성자의 매개변수는 반드시 const참조형태(const CName&)로 받아야 한다. 안그러면 계속 복사가 발생함(매개변수니까)
	{
		//m_pName = rhs.m_pName;			 // 얕은 복사(shallow copy) 생성의 문제

		int iLength = strlen(rhs.m_pName) + 1;	// 깊은 복사(deep copy)
												// 사본과 원본이 소유한 포인터 서로 다른 주소를 소유하게 만들고, 주소가 아닌 값 복사를 하도록 코드를 변경해 준 복사 생성자
		m_pName = new char[iLength];
		strcpy_s(m_pName, iLength, rhs.m_pName);
	}
	~CName()	{		delete[] m_pName;	}
public:
	void		PrintN()	{		printf("%s\n", m_pName);	}
private:
	char* m_pName;
};

void	Print(CName temp){ temp.PrintN(); }

int main()
{
	CName	name("neo-peple");

	Print(&name);


	return 0;
}
```
</details>

### 6일차 (260417) 클래스 상속

<details>
	<summary>클래스 상속</summary>

- 상속: 부모 클래스의 멤버를 물려받아 확장하는 것
```cpp
class CObj
{
public:
	CObj()
	{
		m_iA = 100;
		cout<<m_iA<<endl;
	}
	~CObj();
protected:    //protected는 자식 클래스에서는 접근 가능하지만, 외부에서는 접근 불가
	int m_iA;
};
//#include "CObj.h" 다른 파일에 만들때는 반드시 헤더파일을 include 해야 함.
class CPlayer:public CObj //public상속 외에 private, protected 상속도 있지만 대부분 public 상속을 함.
{
public:
	CPlayer()
	{
		m_iA = 200;  //m_iA 멤버 변수는 부모 클래스인 CObj에서만 있지만 상속을 했기 때문에 쓸 수 있음
		cout<<m_iA<<endl;
	}
	~CPlayer();
}

int main()
{
	CObj Obj;
	CPlayer Player;
}
```
- 자식 객체 생성 과정  
	`1. 메모리 할당 2. 부모 생성자 호출 3. 자식 생성자 호출`  
	- 상속이 많은 경우(부모가 많은 경우) 모든 부모의 생성자를 호출해야 함.  
 	- 자식 객체 안에 부모 부분이 포함되어 함께 메모리가 할당됨 
  	- 부모의 멤버 변수를 private로 쓰는 경우 자식은 쓸 수 없지만 메모리는 차지하게 됨  
- 자식 객체 소멸 과정  
  	`1. 자식 소멸자 호출 2. 부모 소멸자 호출 3. 메모리 반환`  

- 부모 클래스의 멤버 변수로 포인터를 가지고 있다고 해서 자식 클래스에게 상속한 멤버 변수가 같은 메모리주소를 참조하는건 아님.
- 같은 주소를 가리키게 되는 경우는 복사/대입 때문이지 상속 때문이 아님
  
- 정적 바인딩: 컴파일 타임에 어떤 함수를 호출 할 수 있을 지 결정된 상태

### 7일차 (260417) 클래스 다형성(오버라이딩)

<details>
	<summary>다형성</summary>

- 부모 타입으로 자식 객체를 다룰 수 있는 성질  
- 포인터 타입 또는 참조를 통해 주로 사용 됨
```cpp
CObj* pPlayer = new CPlayer;
```
</details>

<details>
	<summary>오버라이딩</summary>

> 오버라이딩이란?

- 부모의 가상함수를 자식이 재정의

> 오버라이딩의 성립 조건

1. 동적 바인딩을 사용하려면 포인터 타입이어야 한다.  
2. 클래스의 상속 관계이어야 한다.
3. 부모 클래스와 자식의 함수 형식이 완벽하게 일치해야 한다.(반환타입, 매개변수)
4. 부모 클래스에 있는 함수 앞에 virtual 키워드를 붙여야 한다. -> 가상함수
</details>

<details>
	<summary>가상함수</summary>
	
> 가상함수

- 함수 앞에(void 앞) virtual을 붙이게 되면 가상 함수가 된다.  
- 가상함수를 통해 오버라이딩을 할 수 있게 된다.  
- 가상함수 실행 흐름: vptr → vtable → 함수(code 영역) → 실행  
- vtable은 data 영역(읽기 전용)에 저장됨, vptr은 객체가 저장된 영역을 따라가게 됨 (가상함수 포인터는 8byte) 
- 부모 클래스의 함수를 가상함수로 바꾸면 자식 함수도 가상 함수를 가지게 되고 vptr, vtable이 생성됨  
- 따라서 자식 객체마다 vptr이 추가된다. (64bit 기준 보통 8byte) 
</details>

<details>
	<summary>vtable 주소 관계</summary>
>같은 클래스

```cpp
new CPlayer;
new CPlayer;
```
- 같은 클래스의 객체라면 vtable을 공유하고, 그 객체들의 vptr 값(= vtable 주소)은 동일.

> 다른 클래스

```cpp
new CObj;
new CPlayer;
```
- 각자 vtable 따로 존재 (주소 다름)

> 형제 클래스

```cpp
class B : public A;
class C : public A;
```
- 각자 vtable 따로 존재 (주소 다름)

- vtable은 클래스 단위로 생성되며, 같은 클래스로 생성된 객체들은 이를 공유한다.
</details>

<details>
	<summary>일반 class 와 상속받은 class의 함수 호출 과정</summary>

> 일반 클래스
```cpp
class A
{
public:
    void Func() {}
};
int main()
{
	A a;
	a.Func();
}
```
- 컴파일 시점에
`A::Func 주소가 이미 결정됨`
- 실행 시
`code 영역에 있는 A::Func로 바로 점프`
- 흐름
`객체 → (바로) 함수 주소 → code 영역 → 실행`

> virtual 함수인 경우
```cpp
class A {
public:
    virtual void Func() {}
};
int main()
{
	A* p = new A;
	p->Func();
}
```
- 실제 동작
`객체 안에 vptr 존재`
- 흐름
`객체 → vptr → vtable → 함수 주소 → code 영역 → 실행`

</details>
