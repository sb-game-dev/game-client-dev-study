# 덕코프 구현 기능 정리


### 인벤토리
<details>
  <summary> 0. 개요 </summary>

- 원작 덕코프도 슬롯 칸을 이미지로 그리지 않는다. 유니티 `ProceduralImage`(셰이더로 그리는 둥근 사각형)로 그리고, 9-slice 스프라이트는 타이틀바·스크롤바 일부에만 쓴다.
- 그래서 모든 격자칸은 픽셀 셰이더(`InRoundRect` 판정)로 그린다.
- 칸마다 Draw콜을 하면 비용이 비싸기 때문에 인스턴싱을 활용한다. **사각형 1개 = 인스턴스 1개**이고, 인벤토리 전체(패널, 칸, 아이콘, 강조, 드래그 아이콘)를 `DrawIndexedInstanced` **한 번**으로 그린다.
- 좌표는 전부 **화면 픽셀, 좌상단 원점, y는 아래로**로 통일한다. 마우스 좌표(`Get_MousePos`)와 같은 좌표계라서 히트 테스트와 그리기가 같은 숫자를 쓴다. 직교 카메라 좌표(중심 원점, y 위)로 바꾸는 건 VS 안에서만 한다.

> VS_OUT 구조체

- float2 vLocal : 원점이 사각형 중심이고 크기만 곱해진 로컬 스페이스의 좌표, 둥근 테두리 밖인지 확인할 때 사용

> VS_MAIN

- vLocal -> 로컬 상태에서 크기만 곱해진 상태.
- vOrtho -> 직교 카메라 좌표(화면 중심 원점, y 위). 월드 행렬은 없고, 좌상단 기준 픽셀 좌표를 여기서 변환한다. vPosition을 계산할 때 사용됨
- VS_OUT.vPosition(SV_POSITION) = 뷰, 투영(직교) 행렬이 곱해진 클립 좌표. 픽셀 셰이더에서 사용하지는 않지만 **래스터라이저가 이 사각형이 화면의 어느 픽셀을 덮는지 정하는 값**이다. 이 값으로 PS가 불릴 픽셀이 정해지기 때문에 VS는 반드시 출력해야 한다.
- VS_OUT.vTexCoord = `lerp(vUV.xy, vUV.zw, 쿼드UV)`. 쿼드의 0~1 UV를 텍스처 안의 원하는 사각형 영역으로 바꾼다. 지금은 vUV가 항상 (0,0,1,1)이라 그대로 나오고, 아틀라스·좌우 뒤집기·잘린 이미지용으로 미리 뚫어 둔 것
- VS_OUT. vLocal = 픽셀 셰이더에서 둥근 테두리 밖인지 확인할 때 사용. 레스터라이저 단계에서 픽셀마다 값을 보간하기 때문에 픽셀값의 로컬 좌표가 들어감.

```hlsl
VS_OUT VS_MAIN(VS_IN In)
{
    VS_OUT Out;
    float2 vSize = In.vRect.zw;
    float2 vCenter = In.vRect.xy + vSize * 0.5f; 
    float2 vLocal = In.vPosition.xy * vSize;
    float2 vOrtho = float2(vCenter.x - g_vWinSize.x * 0.5f,
                            g_vWinSize.y * 0.5f - vCenter.y) + vLocal;

    Out.vPosition = mul(mul(float4(vOrtho, 1.f, 1.f), g_matView), g_matProj);
    Out.vLocal = vLocal;
    Out.vTexCoord = lerp(In.vUV.xy, In.vUV.zw, In.vTexCoord);
    Out.vColor = In.vColor;
    Out.vShape = In.vShape;
    Out.vSize = vSize;
    return Out;
}
```

> InRoundRect

- 픽셀의 로컬 좌표 p를 이용하여 사각형의 범위 안에 있는지 확인하는 함수

```hlsl
bool InRoundRect(float2 p, float2 vHalf, float r)
{
	// 모든 사분면에서 동일한 계산을 하므로 절댓값을 취해서 1사분면에서만 계산함
    p = abs(p);

	// 둥근 모서리계산하기 전에 이미 모서리 밖인 점들은 계산 안함
    if (p.x > vHalf.x || p.y > vHalf.y)
        return false;

	// 둥근 모서리 중심 = vHalf - r
	// 원의 중심 기준 1사분면 범위에 있다면
    if (p.x > (vHalf.x - r) && p.y > (vHalf.y - r))   
    {
        float x = p.x - (vHalf.x - r);
        float y = p.y - (vHalf.y - r);

		// 원 안에 있어야 한다.
        return x*x + y*y <= r*r;
    }
	// 둥근 모서리 부근이 아니고 사각형 안에 있는 점
    return true;
}
```

> PS_MAIN

- 아이콘을 그리는경우, 테두리없는 투명한 배경을 그리는 경우, 테두리만 그리는 경우가 있다.
- 아이콘을 그리는 경우는 In.vShape의 z값을 1로 설정하기 때문에 바로 return문을 호출하게 된다. 텍스처 배열에서 `float3(UV, 슬라이스 번호)`로 그 아이콘 한 장을 읽고, `vColor`를 곱해 알파를 조절한다. 모양은 아이콘 그림의 알파가 블렌딩으로 처리한다.
- 도형은 두 단계로 거른다: ① 래스터라이저가 `vPosition`으로 사각형이 덮는 픽셀 전부를 고름 → ② PS가 `vLocal`로 둥근 모서리 밖과 테두리 안쪽 구멍을 `discard` → ③ 남은 픽셀을 `vColor`로 칠함

```hlsl
float4 PS_MAIN(VS_OUT In) : SV_TARGET
{
    // 아이콘인 경우
    if (In.vShape.z > 0.5f)
        return g_IconArray.Sample(g_Sampler, float3(In.vTexCoord, In.vShape.w)) * In.vColor;

    float2 vHalf = In.vSize * 0.5f;
    float fRadius = min(In.vShape.x, min(vHalf.x, vHalf.y)); // 너무 크면 알약 모양
    float fBorder = In.vShape.y;

    // 테두리없는 투명한 배경을 그리는 경우 + 테두리만 그리는 경우
	// 두 경우 모두 둥근 모서리 밖의 픽셀은 탈락시켜야 한다.
    if (!InRoundRect(In.vLocal, vHalf, fRadius))
        discard;

    // 테두리만 그리는 경우 테두리 간격(fBorder) 안쪽 픽셀을 탈락 시켜야 한다.
    if (fBorder > 0.f && 
        InRoundRect(In.vLocal, vHalf - fBorder, max(fRadius - fBorder, 0.f)))
        discard; 

    return In.vColor;
}
```

  <summary> 4. 인스턴스 추가 방법 </summary>

- 인스턴스 정보들은 멤버 변수 `vector<VTXUI_INSTANCE> m_Instances;`에 모아놓는다.
- 인스턴스를 추가하는 방법은 총 4가지이다.

> Push_Rect()

- **둥근 사각형 인스턴스 하나**(채움 또는 테두리)를 넣는 가장 밑바닥 함수. 칸 바탕·테두리, 패널, 선택, 호버, 놓을 수 있는 칸 표시를 전부 이걸로 그린다.
- fBorder = 테두리 두께 (0이면 채움)
- **좌표를 정수로 반올림하는 이유:** 소수 좌표(예: 52.5)면 1px 테두리가 픽셀 중심 사이에 끼어서 군데군데 끊기거나 칸마다 굵기가 달라 보인다. 좌상단과 우하단을 각각 반올림해야 칸 사이 간격도 일정하게 유지된다.

```cpp
void CInven::Push_Rect(f32_t fLeft, f32_t fTop, f32_t fWidth, f32_t fHeight, float4_t vColor, f32_t fRadius, f32_t fBorder)
{
	// 좌상단과 우하단을 각각 정수 픽셀로 반올림
	f32_t fSnapLeft = floorf(fLeft + 0.5f);
	f32_t fSnapTop = floorf(fTop + 0.5f);
	f32_t fSnapRight = floorf(fLeft + fWidth + 0.5f);
	f32_t fSnapBottom = floorf(fTop + fHeight + 0.5f);

	m_Instances.push_back({ { fSnapLeft, fSnapTop, fSnapRight - fSnapLeft, fSnapBottom - fSnapTop },
							vColor, { fRadius, fBorder, 0.f, 0.f }, { 0.f, 0.f, 1.f, 1.f } });
}
```

> Push_Icon()

- 아이콘을 그리는 함수

```cpp
void CInven::Push_Icon(f32_t fLeft, f32_t fTop, f32_t fWidth, f32_t fHeight, int32_t iIcon, f32_t fAlpha)
```

> Push_ItemIcon()

- 아이템의 인덱스를 받아서 Push_Icon을 호출하는 함수.
- 아이템 아이콘의 크기를 슬롯 보다 작게 보정하여 Push_Icon의 매개변수로 전달한다.

```cpp
void CInven::Push_ItemIcon(const float4_t& vRect, const shared_ptr<ITEM>& pItem, f32_t fAlpha)
{
	if (nullptr == pItem)
		return;

	f32_t fIconSize = min(vRect.z, vRect.w) - 6.f;
	f32_t fIconLeft = vRect.x + (vRect.z - fIconSize) * 0.5f;
	f32_t fIconTop = vRect.y + (vRect.w - fIconSize) * 0.5f;
	Push_Icon(fIconLeft, fIconTop, fIconSize, fIconSize, pItem->iIconIndex, fAlpha);
}
```

> Push_Slot()

- SLOT_POS 정보를 받아서 슬롯 한 칸을 통째로(바탕 + 테두리 + 들어있는 아이템 아이콘) 그리는 함수
- `Push_Rect` 2번(바탕, 테두리) + `Push_ItemIcon` 1번을 호출한다. `Push_Icon`은 `Push_ItemIcon` 안에서 불린다.
- 끄는 동안에도 데이터상 아이템은 원래 칸에 그대로 있다(옮기는 건 `Drop`뿐). 그래서 원래 칸은 흐리게 그려서 "여기서 집었다"는 자리만 남긴다.
```cpp
void CInven::Push_Slot(const SLOT_POS& t)
{
	// 매개변수 t를 통째로 그리는 함수

	// 칸 그리기
	float4_t r = Get_SlotRect(t);
	Push_Rect(r.x, r.y, r.z, r.w, COLOR_SLOT_BG, RADIUS);			// 어두운 배경
	Push_Rect(r.x, r.y, r.z, r.w, COLOR_SLOT_FRAME, RADIUS, BORDER_FRAME);	// 밝은 흰색 테두리

	// 아이템 그리기
	// 드래그를 한 상태이고 현재 위치가 드래그를 시작한 위치라면 알파값을 0.3으로 설정하여 살짝 투명하게 그림
	// 드래그를 한 상태가 아니라면 현재 위치에 있는 아이템을 알파값 1로 설정하여 그린다.
	bool_t bDragSource = (m_eDragState == DRAG_STATE::DRAGGING && t == m_tDraggedItemSlot);
	Push_ItemIcon(r, Get_SlotItem(t), bDragSource ? ALPHA_DRAG_SOURCE : 1.f);
}
```

	<summary> 5. 슬롯 조회 함수 </summary>

> Get_SlotRect

- SLOT_POS → 화면 사각형 Rect정보(left, top, width, height)를 반환
```cpp
float4_t CInven::Get_SlotRect(const SLOT_POS& t)
{
	if (t.eArea == INVEN_AREA::BAG)
		return { BAG_LEFT + (t.iIndex % BAG_COLS) * BAG_STEP,
				 BAG_TOP + (t.iIndex / BAG_COLS) * BAG_STEP,
				 BAG_SIZE,
				 BAG_SIZE };

	if (t.eArea == INVEN_AREA::EQUIP)
		return { EQUIP_LEFT + (t.iIndex % EQUIP_COLS) * EQUIP_STEP_X,
				 EQUIP_TOP + (t.iIndex / EQUIP_COLS) * EQUIP_STEP_Y,
				 EQUIP_WIDTH,
				 EQUIP_HEIGHT };

	return float4_t();
}
```


> Get_SlotItem

- SLOT_POS → 슬롯 위치에 들어있는 아이템 포인터값
- 아이템의 정보를 확인하기 위해 사용
- **참조(`shared_ptr<ITEM>&`)로 돌려주는 이유:** 칸 안의 내용을 직접 바꿀 수 있어서, `Drop`에서 `swap(rSrcItem, rDstItem)` 한 줄로 장비↔가방 이동과 교환을 경우 구분 없이 처리한다.
- 읽기만 할 때는 `const shared_ptr<ITEM>&`로 받는다(복사하면 참조 카운트가 올라갔다 내려감).
```cpp
shared_ptr<ITEM>& CInven::Get_SlotItem(const SLOT_POS& t)
{
	if (t.eArea == INVEN_AREA::EQUIP)
		return m_pEquipSlots[t.iIndex];
	return m_vecBackPack[t.iIndex];
}
```

> Is_InRect	

- 마우스 위치와 Rect정보를 전달하여 사각형 안에 들어있는지 확인하는 함수
```cpp
bool_t CInven::Is_InRect(POINT pt, const float4_t& vRect)
{
	return pt.x >= vRect.x && pt.x < vRect.x + vRect.z
		&& pt.y >= vRect.y && pt.y < vRect.y + vRect.w;
}
```

> Find_CollidedSlot

- 화면 좌표를 전달하여 모든 슬롯 + 패널 + 인벤토리 밖인지 확인후 슬롯 위치(SLOT_POS)를 반환
```cpp
CInven::SLOT_POS CInven::Find_CollidedSlot(POINT pt)
{
	for (int32_t i = 0; i < ETOI(EQUIP_SLOT::END); ++i)
	{
		if (Is_InRect(pt, Get_SlotRect({ INVEN_AREA::EQUIP, i })))
			return { INVEN_AREA::EQUIP, i };
	}
	for (int32_t i = 0; i < (int32_t)m_vecBackPack.size(); ++i)
	{
		if (Is_InRect(pt, Get_SlotRect({ INVEN_AREA::BAG, i })))
			return { INVEN_AREA::BAG, i };
	}
	if (Is_InRect(pt, { PANEL_LEFT, PANEL_TOP, PANEL_WIDTH, PANEL_HEIGHT }))
	{
		return { INVEN_AREA::END, -1 };
	}
	return { INVEN_AREA::OUTSIDE, -1 };
}
```

	<summary> 6. Build_Instances & Render </summary>

> Build_Instances

- 인스턴스는 **뒤에 넣을수록 위에** 그려진다(한 드로우콜 안에서는 인스턴스 순서대로 블렌딩). 그래서 순서가 중요하고, 드래그 아이콘은 반드시 맨 마지막이다.

- 0. 인스턴스 초기화
	- 인스턴스 벡터 컨테이너를 채우기 전에 초기화함
	
- 1. 패널 그리기 
	- 상수로 설정한 패널의 좌표, 크기, 색상, 둥근 모서리 값을 매개변수로 넣고 Push_Rect를 호출한다.
	
- 2. 장비칸 그리기
	- 장비 슬롯 10개를 그린다.
 	- 장비 칸을 통째로 그리는 것이기 때문에 Push_Slot을 호출한다.
	
- 3. 가방칸 그리기
	- 장비칸을 그린것 같이 정해진 가방 칸 만큼 그린다 (Push_Slot 호출).
	
- 4. 선택된 칸 주황 테두리 강조
	- 클릭을 할 때 선택된 칸에 m_tHoveredSlot -> m_tDraggedItemSlot -> m_tSelectedSlot 이 순서로 들어가게 되는데
 	- 이때 m_tHoveredSlot은 Find_CollidedSlot(m_ptMouse) 함수를 이용하여 값 갱신을 하게 됨
  	- Find_CollidedSlot함수가 { INVEN_AREA::END, -1 } 이나 { INVEN_AREA::OUTSIDE, -1 } 값을 반환했다면 슬롯이 아니기 때문에 주황 테두리가 나오면 안된다.
  	- 따라서 m_tSelectedSlot이 장비칸이나 가방칸인지 확인 후 Push_Rect 호출

- 5. 마우스 호버 칸 강조
	- m_tHoveredSlot이 장비칸이나 가방칸인지 확인 후 Push_Rect호출

- 6. 드래그 중인 경우
	- 6-1. 마우스 위치에 아이콘을 그린다. 아이콘의 크기를 계산한 뒤 Push_ItemIcon 호출
	- 6-2. 아이템이 장비칸에 착용 가능한지(`CanPlace`) 확인 후, 착용 가능하다면 그 장비칸에 초록 안쪽 배경 + 흰 테두리를 그린다. (원작 `SlotDisplay`의 PluggableIndicator: 흰 테두리 + 초록 안쪽 글로우. 칸 배경색과 섞여서 파란 칸이면 청록색으로 보인다)
	- 이때 **원래 칸은 제외**한다(`tDstEquipSlot == m_tDraggedItemSlot`). 원래 칸에 다시 놓으면 `Drop`이 아무것도 안 하기 때문
```cpp
void CInven::Build_Instances()
{
	// 0. 인스턴스 초기화
	m_Instances.clear();

	// 1. 패널 그리기
	Push_Rect(PANEL_LEFT, PANEL_TOP, PANEL_WIDTH, PANEL_HEIGHT, COLOR_PANEL, RADIUS);
	
	// 2. 장비칸 그리기
	for (int32_t i = 0; i < ETOI(EQUIP_SLOT::END); ++i)        
		Push_Slot({ INVEN_AREA::EQUIP, i });
	
	// 3. 가방칸 그리기
	for (int32_t i = 0; i < (int32_t)m_vecBackPack.size(); ++i) 
		Push_Slot({ INVEN_AREA::BAG, i });

	// 4. 선택된 칸 주황 테두리 강조
	if (Is_Slot(m_tSelectedSlot))
	{
		float4_t r = Get_SlotRect(m_tSelectedSlot);
		Push_Rect(r.x, r.y, r.z, r.w, COLOR_SELECTED, RADIUS, BORDER_SELECTED);
	}

	// 5. 마우스 호버 칸 강조
	if (Is_Slot(m_tHoveredSlot))
	{
		float4_t r = Get_SlotRect(m_tHoveredSlot);
		Push_Rect(r.x, r.y, r.z, r.w, COLOR_HOVER, RADIUS);
	}

	// 6. 드래그 중인경우
	// 6-1. 마우스에 아이콘을 그린다.
	// 6-2. 드래그중인 아이템이 장비칸에 장착 가능한 아이템이라면 
	// 장착 가능한 부위를 확인 후 장비칸에 초록색 테두리로 표현
	if (m_eDragState == DRAG_STATE::DRAGGING)
	{
		// 마우스가 잡고 있는 아이템 아이콘
		float4_t rFromSlot = Get_SlotRect(m_tDraggedItemSlot);		
		float4_t rDraggedIcon = { m_ptMouse.x - rFromSlot.z * 0.5f,     
								  m_ptMouse.y - rFromSlot.w * 0.5f,
								  rFromSlot.z, rFromSlot.w };			
		Push_ItemIcon(rDraggedIcon, Get_SlotItem(m_tDraggedItemSlot), ALPHA_DRAGGED);

		// 이 아이템이 들어갈 수 있는 장비 칸을 초록 테두리로 표현
		const shared_ptr<ITEM>& pDraggedItem = Get_SlotItem(m_tDraggedItemSlot);
		for (int32_t i = 0; i < ETOI(EQUIP_SLOT::END); ++i)
		{
			SLOT_POS tDstEquipSlot = { INVEN_AREA::EQUIP, i };
			if (tDstEquipSlot == m_tDraggedItemSlot || false == CanPlace(pDraggedItem, tDstEquipSlot))
				continue;

			float4_t r = Get_SlotRect(tDstEquipSlot);
			Push_Rect(r.x, r.y, r.z, r.w, COLOR_PLACEABLE_GLOW, RADIUS);	// 초록 배경(두께를 디폴트 매개변수인 0으로 설정)
			Push_Rect(r.x, r.y, r.z, r.w, COLOR_PLACEABLE_LINE, RADIUS, BORDER_PLACEABLE); // 초록색 외곽 선
		}
	}
}
```

> Render

- 매 프레임 `Build_Instances`로 인스턴스 벡터를 새로 채우고, 인스턴스 버퍼에 통째로 복사한 뒤 한 번에 그린다.
- `Map(D3D11_MAP_WRITE_DISCARD)`: 이전 내용을 버리고 새로 쓴다. GPU가 이전 프레임 버퍼를 쓰는 중이어도 기다리지 않고 새 메모리를 받는다. 그래서 버퍼를 `D3D11_USAGE_DYNAMIC` + `D3D11_CPU_ACCESS_WRITE`로 만든다.
- 정점 버퍼를 **2개** 묶는다. 슬롯 0 = 쿼드 정점 4개(`VTXNORM`), 슬롯 1 = 인스턴스 데이터(`VTXUI_INSTANCE`). stride도 각각 넘긴다.
- `DrawIndexedInstanced(인덱스 6개, 인스턴스 개수, 0, 0, 0)`: 쿼드(삼각형 2개)를 인스턴스 개수만큼 그린다.
- 블렌드 상태는 `Renderer::Render_Alpha_UI`가 켜 준다(`ALPHA_UI` 그룹에 등록했기 때문). 카메라 상수버퍼(b1)도 UI 패스 직전에 `Set_MainCamera(L"COrthographic_Cam")`가 직교 카메라로 바인딩해 준다.

```cpp
HRESULT CInven::Render()
{
	Build_Instances();
	if (m_Instances.empty())
		return S_OK;
	uint32_t iCount = min((uint32_t)m_Instances.size(), m_iMaxInstance);

	// 인스턴스 벡터 -> 인스턴스 버퍼
	D3D11_MAPPED_SUBRESOURCE tMapped{};
	if (FAILED(m_pContext->Map(m_pInstanceVB.Get(), 0, D3D11_MAP_WRITE_DISCARD, 0, &tMapped)))
		return E_FAIL;
	memcpy(tMapped.pData, m_Instances.data(), sizeof(VTXUI_INSTANCE) * iCount);
	m_pContext->Unmap(m_pInstanceVB.Get(), 0);

	// 정점 버퍼 2개: [0] 쿼드, [1] 인스턴스
	ID3D11Buffer* pVBs[] = { m_pVB.Get(), m_pInstanceVB.Get() };
	uint32_t iStrides[] = { sizeof(VTXNORM), sizeof(VTXUI_INSTANCE) };
	uint32_t iOffsets[] = { 0, 0 };
	m_pContext->IASetVertexBuffers(0, 2, pVBs, iStrides, iOffsets);
	m_pContext->IASetIndexBuffer(m_pIB.Get(), DXGI_FORMAT_R32_UINT, 0);
	m_pContext->IASetPrimitiveTopology(D3D11_PRIMITIVE_TOPOLOGY_TRIANGLELIST);

	m_pContext->IASetInputLayout(m_pVSCom->Get_InputLayout().Get());
	m_pContext->VSSetShader(m_pVSCom->Get_Shader().Get(), nullptr, 0);
	m_pContext->PSSetShader(m_pPSCom->Get_Shader().Get(), nullptr, 0);

	if (m_pIconTexCom)
		m_pIconTexCom->Set_TexturePS(0, 0);          // t0: 아이콘 텍스처 배열

	m_pContext->PSSetSamplers(0, 1, m_pSampler.GetAddressOf());
	m_pContext->RSSetState(m_pRS.Get());

	// 쿼드 하나(인덱스 6개)를 인스턴스 개수만큼
	m_pContext->DrawIndexedInstanced(m_iIndexCnt, iCount, 0, 0, 0);
	return S_OK;
}
```

	<summary> 7. Update_DragState </summary>

> enum class DRAG_STATE

- 기본상태(IDLE), 클릭 상태(PRESSED), 드래그 중인 상태로 구분(DRAGGING)
- PRESSED를 따로 두는 이유: 누르자마자 드래그로 넘어가면 클릭(선택)을 할 방법이 없다. 손은 누를 때 1~2px 흔들리므로 4px 넘게 움직였을 때만 드래그로 본다.
- 드래그를 취소할 때(Tab으로 닫기 등)는 상태만 IDLE로 돌리면 된다. 끄는 동안 데이터는 원래 칸에 그대로 있으니 자동으로 원래 자리에 보인다.

```
            아이템 있는 칸에서 Mouse_Down                 4px 넘게 움직임
  IDLE  ──────────────────────────────▶  PRESSED  ─────────────────────▶  DRAGGING
   ▲                                       │                                │
   │         안 움직이고 Mouse_Up = "클릭"   │      Mouse_Up = "놓기"(Drop)    │
   └───────────────────────────────────────┴────────────────────────────────┘
```
```cpp
	enum class DRAG_STATE { IDLE, PRESSED, DRAGGING, END };
```

> Update_DragState()

- IDLE 상태에서 
	- 누름이 감지됐다면 장비 or 가방칸을 눌렀는지 확인 + 아이템이 있는 칸인지 확인
 		- PRESSED 상태로 변경
 		- 클릭인지 드래그인지 아직 모르기 때문에 우선 m_tDraggedItemSlot에 m_tHoveredSlot을 저장
   		- 드래그인지 판정하기 위해 클릭한 좌표를 m_ptPress에 저장
	- 장비 or 가방칸도 아니고 아이템이 없는 일반 칸이라면
		- m_tSelectedSlot을 비운다.
- PRESSED 상태에서 
	- 버튼을 땠다면
 		- 드래그가 아니라 클릭이므로 m_tDraggedItemSlot에 저장했던 값을 m_tSelectedSlot로 설정
 		- IDLE 상태로 변경.
   - 클릭을 시작한 좌표인 m_ptPress에서 4픽셀 떨어졌다면 드래그로 판정
   		- DRAGGING 상태로 변경.
- DRAGGING 상태에서
	- 버튼을 땠다면
		- m_tDraggedItemSlot(Src)을 m_tHoveredSlot(Dst)에 놓는다.
  		- IDLE 상태로 변경
```cpp
void CInven::Update_DragState()
{
	bool_t bPressed = CGameInstance::Get().Mouse_Down(DIM::LB);    // 눌린 순간
	bool_t bReleased = CGameInstance::Get().Mouse_Up(DIM::LB);     // 뗀 순간

	switch (m_eDragState)
	{
	case DRAG_STATE::IDLE:
		if (false == bPressed)
			break;
		// 장비 or 가방칸을 눌렀는지 확인 + 아이템이 있는 칸인지 확인
		if (Is_Slot(m_tHoveredSlot) && nullptr != Get_SlotItem(m_tHoveredSlot))
		{
			// 아이템 있는 칸을 누름 -> 아직 클릭인지 드래그인지 모름
			m_eDragState = DRAG_STATE::PRESSED;
			m_tDraggedItemSlot = m_tHoveredSlot;
			m_ptPress = m_ptMouse;
		}
		else
		{
			m_tSelectedSlot = {};
		}
		break;

	case DRAG_STATE::PRESSED:
		if (bReleased)
		{
			// 안 움직이고 뗌 = 클릭 -> m_tDraggedItemSlot을 선택했다고 판정 + 누르기 종료
			m_tSelectedSlot = m_tDraggedItemSlot;
			m_tDraggedItemSlot = {};
			m_eDragState = DRAG_STATE::IDLE;
		}
		else if (labs(m_ptMouse.x - m_ptPress.x) + labs(m_ptMouse.y - m_ptPress.y) > 4)
		{
			// 누른 채로 4픽셀 넘게 움직임 = 드래그 시작
			m_eDragState = DRAG_STATE::DRAGGING;
		}
		break;

	case DRAG_STATE::DRAGGING:
		if (bReleased)
		{
			// 마우스 아래 칸에 놓기
			Drop(m_tDraggedItemSlot, m_tHoveredSlot);
			m_eDragState = DRAG_STATE::IDLE;
		}
		break;
	}
}
```

<details>
	<summary> 8. CanPlace & Drop </summary>

> CanPlace()

```cpp
bool_t CInven::CanPlace(const shared_ptr<ITEM>& pItem, const SLOT_POS& tDstSlot)
{
	// CanPlace -> pItem을 tDstSlot에 넣을 수 있는지를 확인하는 함수

	// 놓을 칸이 비어있다면 비어있는 칸의 pItem은 nullptr이 들어온다 -> CanPlace(nullptr, tSrcSlot)이 불린다.
	// Drop에서 빈 칸에 놓을 때, 놓은 칸의 "빈 것"이 집은 칸으로 가는지 검사하므로 필요
	// (예: 장착한 총을 빈 가방 칸으로 → 총 칸이 비게 됨 = 허용)
	if (nullptr == pItem)                       // 빈 슬롯은 어디든 놓을 수 있음
		return true;

	if (tDstSlot.eArea == INVEN_AREA::BAG)     // 가방 칸에는 뭐든 들어감
		return true;

	// 장비 칸의 규칙(장비칸에서의 iIndex -> 장비칸 슬롯 정보)
	switch (static_cast<EQUIP_SLOT>(tDstSlot.iIndex))  
	{
	case EQUIP_SLOT::GUN_1:
	case EQUIP_SLOT::GUN_2:
		return pItem->eItemType == ITEM_TYPE::GUN;

	case EQUIP_SLOT::MELEE:
		return pItem->eItemType == ITEM_TYPE::MELEE;

	case EQUIP_SLOT::HEAD:
		return pItem->eItemType == ITEM_TYPE::ARMOR
			&& static_pointer_cast<ARMOR>(pItem)->eSlot == ARMOR_SLOT::HEAD;

	case EQUIP_SLOT::BODY:
		return pItem->eItemType == ITEM_TYPE::ARMOR
			&& static_pointer_cast<ARMOR>(pItem)->eSlot == ARMOR_SLOT::BODY;

	case EQUIP_SLOT::BACKPACK:
		return pItem->eItemType == ITEM_TYPE::BACKPACK;

	case EQUIP_SLOT::TOTEM_1:
	case EQUIP_SLOT::TOTEM_2:
		return pItem->eItemType == ITEM_TYPE::TOTEM;

	default: // FACE, HEADSET: 아직 맞는 아이템 타입이 없음
		return false;
	}
}
```

> Drop()

- 놓을 때 무슨 일이 일어나야 하는지 순서

```
Drop(집은 칸, 놓은 칸)
 ├─ 놓은 곳이 패널 밖(OUTSIDE) ──────────────▶ 버리기 (집은 칸 비우기)
 ├─ 놓은 곳이 칸이 아님(END) / 같은 칸 ───────▶ 아무것도 안 함 (원위치)
 ├─ 이 아이템이 그 칸에 못 들어감 (CanPlace) ─▶ 아무것도 안 함 (원위치)
 ├─ 같은 아이템 + 겹치기 가능 + 자리 남음 ───▶ 합치기
 └─ 그 외: Dst칸 아이템이 Src칸에 들어갈 수 있으면 swap (빈칸이면 이동, 아니면 교환)
```

- "아무것도 안 함"이 곧 원위치다. 끄는 동안 데이터를 안 바꾸므로 되돌릴 코드가 필요 없다.
- 5번의 반대 방향 검사가 필요한 이유: 장비 칸의 총을 가방의 방탄복 위에 놓으면, 총은 가방에 들어가지만 방탄복은 총 칸에 못 들어간다. 이 검사가 없으면 방탄복이 총 칸에 들어가 버린다.
- 0번 `nullptr` 검사는 지금 흐름에서는 걸리지 않지만(PRESSED로 넘어갈 때 아이템 있는 칸만 허용), 나중에 퀵슬롯 사용·우클릭 메뉴·자동 정렬처럼 다른 곳에서 `Drop`을 부르거나 끄는 중에 아이템이 사라질 수 있어서 남겨 둔다.

```cpp
void CInven::Drop(const SLOT_POS& tSrcSlot, const SLOT_POS& tDstSlot)
{
	// 0. 마우스로 잡은 슬롯에 아이템이 없다면(nullptr) return
	shared_ptr<ITEM>& rSrcItem = Get_SlotItem(tSrcSlot);
	if (nullptr == rSrcItem)
		return;

	// 1. 패널 밖 -> 버리기
	if (tDstSlot.eArea == INVEN_AREA::OUTSIDE)
	{
		// 나중에 월드에 아이템 오브젝트를 떨어뜨리기
		rSrcItem = nullptr;
		// 선택한 슬롯의 아이템을 떨어트릴 수 있으니 m_tSelectedSlot 초기화하여 주황색 표시 없애기
		if (m_tSelectedSlot == tSrcSlot)
			m_tSelectedSlot = {};
		return;
	}

	// 2. 칸이 아닌 곳(칸 사이 틈) 또는 같은 칸 -> 원위치
	if (false == Is_Slot(tDstSlot) || tDstSlot == tSrcSlot)
		return;


	// 3. 집은 아이템이 놓은 칸에 못 들어감 -> 원위치
	if (false == CanPlace(rSrcItem, tDstSlot))
		return;

	// 4. 같은 아이템 + 겹치기 가능 -> 합치기
	shared_ptr<ITEM>& rDstItem = Get_SlotItem(tDstSlot);
	// 목적지 슬롯에 아이템이 있다 && 목적지 아이템이 겹칠 수 있다 && 목적지 아이템과 소스 아이템의 아이템 타입이 같다.
	if (nullptr != rDstItem && rDstItem->bStackable && rDstItem->iTypeID == rSrcItem->iTypeID)
	{
		int32_t iSpace = rDstItem->iMaxStack - rDstItem->iCount;        // 놓을 칸에 남은 자리
		int32_t iItemCnt = min(rSrcItem->iCount, iSpace);				// 실제로 옮길 개수

		if (iItemCnt > 0)
		{
			rDstItem->iCount += iItemCnt;
			rSrcItem->iCount -= iItemCnt;
			if (rSrcItem->iCount <= 0)                             		// Src의 개수를 다 옮겼으면 Src 칸 비우기
				rSrcItem = nullptr;
			return;
		}
		// 놓은 칸이 이미 꽉 차 있어서 못옮긴다면 (iItemCnt == 0) 
		// 아래로 내려가서 교환 swap(rSrcItem, rDstItem);
	}

	// 5. 이동 또는 교환
	//    놓은 칸에 아이템이 있으면, 그게 집은 칸으로 갈 수 있어야 함
	//    DstItem이 SrcSlot에 이동 가능한 지 확인 (반대방향 검사)
	if (false == CanPlace(rDstItem, tSrcSlot))
		return;
	swap(rSrcItem, rDstItem);

	// 선택 테두리가 아이템을 따라가게
	if (m_tSelectedSlot == tSrcSlot)
		m_tSelectedSlot = tDstSlot;
	else if (m_tSelectedSlot == tDstSlot)
		m_tSelectedSlot = tSrcSlot;
}
```

> ITEM 구조체 (Client_Defines.h)

```cpp
typedef struct Item
{
	ITEM_TYPE			eItemType;		    // 아이템 타입
	wstring_t		    strItemName;		// 이름
	wstring_t           strDesc;            // 아이템 설명
	bool_t				bStackable;		    // 중첩 가능 여부
	int32_t				iCount;			    // 개수
	f32_t				fWeight;			// 무게
	int32_t             iPrice;             // 가격


	int32_t				iTypeID;			// 같은 아이템인지 판단 (스택 합치기)
	int32_t				iMaxStack;			// 최대 겹침 수
	int32_t				iIconIndex;			// 아이콘 텍스처 배열 슬라이스
	int32_t				iQuality;			// 1~6

}ITEM;
```

- `iTypeID`는 원작 아이템 번호(`Resource/Inventory/items.csv`, `IconArray/icon_index.csv`). 합치기가 typeID로 같은 아이템을 판단하므로 **서로 다른 아이템에 같은 값(예: 0)을 넣으면 합쳐져 버린다.**

> ARMOR로 만들어야 하는 이유

- **방어구는 반드시 `make_shared<ARMOR>()`로 만든다.** `CanPlace`가 `static_pointer_cast<ARMOR>`로 `eSlot`(머리/몸)을 꺼내기 때문에, `ITEM`으로 만들고 타입만 ARMOR로 바꾸면 캐스팅이 깨진다.
- 토템은 전용 구조체가 없고 `eItemType`만 보므로 `ITEM`으로 만들어도 된다.

```cpp
auto pHelmet = make_shared<ARMOR>();            // 실제 객체가 ARMOR
pHelmet->eItemType = ITEM_TYPE::ARMOR;
pHelmet->eSlot = ARMOR_SLOT::HEAD;
m_vecBackPack[5] = pHelmet;                     // shared_ptr<ITEM>으로 자동 변환되어 들어감

// CanPlace: eItemType이 ARMOR인 걸 먼저 확인했으니 실제 객체가 ARMOR라는 게 보장됨
return pItem->eItemType == ITEM_TYPE::ARMOR
	&& static_pointer_cast<ARMOR>(pItem)->eSlot == ARMOR_SLOT::HEAD;
```
