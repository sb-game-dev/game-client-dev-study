# 애니메이션 점검 질문

> 답은 직접 코드를 보면서 채워 넣기. 막히는 질문 = 다시 봐야 할 부분.
> 참고 코드: 덕코프 `Game/Engine` (Model / Animation / Channel / Bone), 수업 코드 `08_DX11_2/1117_AnimDone/Engine`

## 1. 구조 (Animation / Channel / KeyFrame)
1. `aiScene` → `aiAnimation` → `aiNodeAnim` → 키(Scaling/Rotation/Position) 구조가 각각 엔진의 어떤 클래스·구조체로 옮겨지나?
2. 모델 하나에 애니메이션이 여러 개(`mNumAnimations`)일 수 있다. 애니메이션 하나는 무엇을 의미하나? (예: Idle, Run …)
3. 채널(Channel) 하나는 무엇인가? 채널 개수(`mNumChannels`)와 모델 전체 본 개수는 같아야 하나?
4. 채널이 없는 본은 애니메이션이 재생되는 동안 어떤 행렬을 유지하나?
5. `Ready_Animation`은 왜 `Ready_Bones`보다 뒤에 호출되어야 하나?
6. 채널은 자기가 움직일 본을 무엇으로 찾고, 무엇으로 저장해 두나? 못 찾으면 어떻게 되나?

## 2. 시간 (Duration / TickPerSecond / TrackPosition)
7. `mDuration`의 단위는 초인가? 아니라면 무엇인가?
8. `m_fCurrentTrackPosition += m_fTickPerSecond * fDeltaTime` — 이 식에서 `fDeltaTime`을 곱하는 이유는? 빼면 무엇이 달라지나?
9. 애니메이션을 2배 빠르게 재생하고 싶다면 어떤 값을 건드리면 되나?
10. 키프레임의 `fTrackPosition`과 `m_fCurrentTrackPosition`은 같은 단위인가? 왜 같아야 하나?

## 3. 키프레임 만들기 (Channel::Initialize)
11. `m_iNumKeyFrames`를 Scaling/Rotation/Position 키 개수 중 최댓값으로 잡는 이유는?
12. `vScale`, `vRotation`, `vPosition`을 반복문 밖에 선언한 이유는? 어떤 키가 다른 키보다 개수가 적을 때 무슨 일이 생기나?
13. `tKeyFrame.fTrackPosition`은 세 종류 키 중 어느 키의 시간으로 최종 결정되나? 세 키의 시간이 서로 다르면 어떤 문제가 생길 수 있나?
14. 회전은 왜 오일러 각이 아니라 쿼터니언(float4)으로 저장되나?

## 4. 보간 (Channel::Update_TransformMatrix)
15. 현재 재생 위치가 마지막 키프레임 시간 이후라면 왜 보간하지 않고 마지막 키프레임 값을 그대로 쓰나?
16. "왼쪽 키프레임 인덱스"는 무엇을 가리키나? `fRatio`는 무엇을 0~1로 나타낸 값인가?
17. 왼쪽 키프레임을 찾을 때 `if`가 아니라 `while`을 쓰는 이유는? (fDeltaTime이 아주 크게 튄 프레임을 생각해 보기)
18. 매 프레임 처음부터 키프레임을 찾지 않고 이전 인덱스를 이어서 쓰는 이유는?
19. 크기·위치는 `XMVectorLerp`, 회전은 `XMQuaternionSlerp`를 쓴다. 회전에 Lerp를 쓰면 어떻게 되나?
20. `XMMatrixAffineTransformation(vScale, 원점, vRotation, vPosition)`의 각 인자는 무엇인가? 결과 행렬은 Bone의 어떤 행렬에 들어가나? (Combined인가, Transform인가?)

## 5. 재생 상태 (루프 / 종료 / 전환)
21. 루프할 때 재생 위치만 0으로 되돌리고 왼쪽 키프레임 인덱스를 0으로 안 되돌리면 어떻게 되나?
    - 수업 코드는 이걸 어디서 처리하나? (`Channel.cpp`의 `0.f == fCurrentTrackPosition`) 덕코프는 어디서 처리하나? (`Reset_Animaition`)
22. 루프가 아닌 애니메이션이 끝나면 본들은 어떤 포즈로 남아 있나?
23. 덕코프 `CAnimation`의 `m_isFinished` 초기값은 `true`다. 애니메이션을 한 번도 Reset하지 않은 상태에서 `Is_Animation_End()`를 부르면 무엇이 반환되나? 의도한 동작인가?
24. 덕코프 `SetCurrentAnimIndex`는 애니메이션이 바뀔 때 `Reset_BoneTransformMatrix()`로 본들을 초기 행렬로 되돌린다. 이걸 안 하면 어떤 본이 이상해지나? (4번 질문과 연결)
25. 애니메이션을 바꾸는 순간 포즈가 "툭" 끊기는 이유는? 부드럽게 바꾸려면 무엇과 무엇을 보간해야 할까?

## 6. 한 프레임의 흐름
26. `PlayAnimation`(덕코프) / `Play_Animation`(수업) 안에서 일어나는 두 단계는 무엇이고, 순서가 왜 그래야 하나?
27. Update에서 `PlayAnimation` → Render에서 `Bind_BoneMatrix` → `Render`. 이 셋 중 하나라도 빠지거나 순서가 바뀌면 각각 어떻게 보이나?
28. `Channel → Bone.Transform → Bone.Combined → Mesh(Offset × Combined) → 셰이더` — 각 화살표에서 무엇이 무엇으로 바뀌는지 한 줄씩 말할 수 있나?

## 7. 클론과 애니메이션 상태
29. 애니메이션 재생 중에 매 프레임 바뀌는 "상태" 값들을 모두 나열해 보면? (본 쪽, 애니메이션 쪽)
30. 수업 코드에서는 `m_LeftKeyFrameIndices`가 Channel이 아니라 Animation에 있다(Channel의 멤버는 주석 처리). 왜 옮겼을까? 덕코프 `CChannel`에 남아 있는 `m_iLeftKeyFrameIndex`는 쓰이고 있나?
31. 수업 코드 `CModel` 복사 생성자는 `m_Bones`와 `m_Animations`를 하나씩 `Clone()`한다. 덕코프 복사 생성자는 어떻게 하고 있나? 플레이어 같은 애님 객체를 두 개 띄우면 덕코프에서는 어떻게 보일까?
32. `CAnimation::Clone()`은 얕은 복사다. 그러면 Channel(키프레임 데이터)은 클론끼리 공유된다. 공유해도 괜찮은 이유는? (30번과 연결)

## 8. 최종 확인
