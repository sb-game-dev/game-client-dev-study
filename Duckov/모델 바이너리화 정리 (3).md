## 1. 설계

### 1-1. 누가 어느 블록을 읽나: "aiMesh* 자리에 FILE*"
기존 코드는 `CModel`이 장면을 읽고, 부품마다 `aiMesh*`, `aiMaterial*`을 넘겨서 각자 만들게 한다. .bin도 같은 모양으로 간다.

| | FBX (기존) | .bin (추가) |
|---|---|---|
| CModel | `ReadFile` → `aiScene` | `_wfopen_s` → `FILE*` |
| CMesh | `Create(..., const aiMesh*, PreTransform)` | `Create(..., FILE*, PreTransform)` |
| CMaterial | `Create(..., 경로, const aiMaterial*)` | `Create(..., 경로, FILE*)` |

- 변환기의 `Write_` 함수가 쓴 블록을 같은 클래스 단위로 **같은 순서로** 읽는다. 쓰는 쪽과 읽는 쪽이 1:1로 대응해서 비교하기 쉽다.

| (2)편 변환기 | (3)편 엔진 |
|---|---|
| `Write_Header` | `CModel::Read_Header` |
| `Write_Meshes`의 메시 개수 | `CModel::Read_Meshes` |
| `Write_Meshes`의 메시 하나 | `CMesh::Initialize_Prototype(FILE*)` |
| `Write_Materials`의 머티리얼 개수 | `CModel::Read_Materials` |
| `Write_Materials`의 머티리얼 하나 | `CMaterial::Initialize(경로, FILE*)` |
| `To_TextureType` | `CMaterial::To_AiTextureType` |

- 파일 커서가 자동으로 앞으로 가니, `CModel`이 같은 `FILE*`를 메시 0 → 메시 1 → … → 머티리얼 0 순서로 넘기기만 하면 된다((1)편 규칙 ①).

### 1-2. 확장자로 나누기
- `Initialize_Prototype` 맨 앞에서 `_splitpath_s`로 확장자만 꺼내 `.bin`이면 `Load_Binary`로 간다.
- 기존 FBX 코드는 **한 줄도 바꾸지 않는다.** 애니메이션 수업은 계속 FBX로 한다.

### 1-3. 로드할 때 하는 일 (변환기에서 안 한 것)
| 할 일 | 위치 | 이유 |
|---|---|---|
| `PreTransformMatrix` 곱하기 | CMesh | (1)편 결정 7 (모델마다 다른 선택) |
| AABB 계산 | CMesh | (1)편 3-1 (정점으로 다시 계산) |
| 텍스처 경로 = .bin 폴더 + 파일 이름 | CMaterial | (1)편 결정 5 |
| `TEXTURE_TYPE` → `aiTextureType` | CMaterial | `m_Materials[]`와 `Bind_Material`이 아직 aiTextureType 기준. **임시** 번역 |
| GPU 버퍼, SRV 생성 | CMesh, CMaterial | 저장할 수 없음 ((1)편 규칙 ③) |

### 1-4. 실패 처리
변환기와 같은 원칙이다. **파일은 어떤 길로 나가든 한 곳에서 닫는다.**
```
Load_Binary
 ├ 타입이 NONANIM이 아님 → return E_FAIL
 ├ 열기 실패            → return E_FAIL
 ├ hr = Read_Header
 ├ 성공이면 hr = Read_Meshes
 ├ 성공이면 hr = Read_Materials
 ├ 성공이면 남은 바이트 검사
 ├ fclose               ← 항상
 └ return hr
```
- 엔진 스타일대로 `HRESULT`와 `MSG_BOX`를 쓴다.
- 읽기는 실패해도 지울 파일이 없어서 변환기보다 단순하다.

### 1-5. 읽을 때마다 검사하는 이유
- 파일에는 칸 구분이 없어서((1)편 1-3), **앞에서 1바이트만 어긋나도 뒤의 개수가 전부 쓰레기 값**이 된다.
- 쓰레기 개수를 그대로 믿으면 수십 GB 할당, 버퍼 넘침으로 이어진다(참고: 이번 편에서 만난 버그).
- 그래서 매직, 버전, 타입, Stride, 이름 길이를 읽자마자 검사하고, 마지막에 남은 바이트까지 본다.

### 2-4. Load_Binary
```cpp
HRESULT CModel::Load_Binary(const char_t* pModelFilePath, fmatrix_t PreTransformMatrix)
{
    // ① 지금 .bin은 NONANIM만 있다
    if (MODEL::NONANIM != m_eType)
    {
        MSG_BOX("Binary Model : NONANIM only");
        return E_FAIL;
    }

    // ② 열기 (읽기 + 바이너리)
    wchar_t szWidePath[MAX_PATH] = {};
    MultiByteToWideChar(CP_ACP, 0, pModelFilePath, -1, szWidePath, MAX_PATH);

    FILE*   pFile = { nullptr };
    if (0 != _wfopen_s(&pFile, szWidePath, L"rb") || nullptr == pFile)
    {
        MSG_BOX("Failed to Open : Binary Model");
        return E_FAIL;
    }

    // ③ 쓴 순서 그대로 읽기
    HRESULT hr = Read_Header(pFile);
    if (SUCCEEDED(hr))
        hr = Read_Meshes(pFile, PreTransformMatrix);
    if (SUCCEEDED(hr))
        hr = Read_Materials(pFile, pModelFilePath);

    // ④ 다 읽었는데 남은 바이트가 있으면 포맷이 어긋난 것 (4장에서 추가)
    if (SUCCEEDED(hr) && EOF != fgetc(pFile))
    {
        MSG_BOX("Binary Model : Extra Bytes (Format Mismatch)");
        hr = E_FAIL;
    }

    // ⑤ 성공이든 실패든 닫기
    fclose(pFile);
    return hr;
}
```
- **① 타입 검사:** Loader가 ANIM으로 .bin을 부르면 바로 거절한다. 지금 .bin에는 뼈가 없어서 ANIM으로 읽으면 애니메이션 코드가 빈 뼈를 찾다가 터진다.
- **② `L"rb"`:** 읽기 + 바이너리. 파일이 없으면 실패하고, `w`와 달리 내용을 지우지 않는다.
- **③ `SUCCEEDED(hr)` 사슬:** 변환기의 `&&`와 같은 역할이다. 앞이 실패하면 뒤를 부르지 않는다. `HRESULT`라 `&&`로 잇지 않고 `if`로 풀었다.
- **④ 남은 바이트:** `fgetc`는 1바이트를 읽어 돌려주고, 파일 끝이면 `EOF`를 돌려준다. 끝에 정확히 도착하지 않았다면 쓰는 쪽과 읽는 쪽이 어딘가 어긋난 것이다. (2)편의 "크기 검산"을 로드할 때마다 자동으로 하는 셈이다.
- **⑤ 한 곳에서 닫기:** 실패할 때마다 `return E_FAIL`로 바로 나가면 `fclose`가 빠진다. 파일이 게임이 끝날 때까지 열려 있어서, 그동안 ModelConverter로 다시 변환하면 열기 실패가 난다.

### 2-5. Read_Header
```cpp
HRESULT CModel::Read_Header(FILE* pFile)
{
    char_t      szMagic[4] = {};
    uint32_t    iVersion = {};
    uint32_t    iType = {};

    if (1 != fread(szMagic, sizeof(szMagic), 1, pFile) ||
        1 != fread(&iVersion, sizeof(uint32_t), 1, pFile) ||
        1 != fread(&iType, sizeof(uint32_t), 1, pFile))
    {
        MSG_BOX("Failed to Read : Header");
        return E_FAIL;
    }

    if (0 != memcmp(szMagic, ModelFile::MAGIC, sizeof(szMagic)))
    {
        MSG_BOX("Not a Model File (Magic)");
        return E_FAIL;
    }
    if (ModelFile::VERSION != iVersion)
    {
        MSG_BOX("Model File Version Mismatch : Reconvert");
        return E_FAIL;
    }
    if (static_cast<uint32_t>(ModelFile::MODEL_TYPE::NONANIM) != iType)
    {
        MSG_BOX("Model File Type Mismatch");
        return E_FAIL;
    }
    return S_OK;
}
```
- (2)편 `Write_Header`를 그대로 뒤집은 모양이다. `fwrite` → `fread`, 순서는 같다.
- **`sizeof(szMagic)` = 4.** `sizeof(char_t)`(= 1)로 쓰면 `'D'`만 읽고 뒤가 전부 3바이트씩 밀린다(참고 참조).
- 매직은 `memcmp`로 비교한다. `MAGIC`은 `'\0'`이 없는 4글자라 `strcmp`를 쓰면 끝을 못 찾고 뒤쪽 메모리까지 읽는다.
- 검사 순서는 **매직 → 버전 → 타입.** 우리 파일이 아니면 버전 칸도 쓰레기 값이니 매직부터 본다((1)편 결정 1).

## 3. 메시 읽기

### 3-1. 이번 장에서 할 일
(2)편 5장 `Write_Meshes`를 뒤집어 읽는다.

| (2)편 Write_Meshes | (3)편 | 누가 |
|---|---|---|
| `fwrite(NumMeshes)` | `fread(NumMeshes)` | CModel::Read_Meshes |
| 메시마다 반복 | 메시마다 `CMesh::Create(FILE*)` | CModel::Read_Meshes |
| MaterialIndex, Stride, NumVertices | 같은 순서 + Stride 검사 | CMesh |
| aiMesh → `VERTEX_STATIC[]` → `fwrite` | `fread` → `VTXMESH[]` → PreTransform → 정점 버퍼 | CMesh |
| NumIndices, Indices | `fread` → 인덱스 버퍼 | CMesh |

엔진 `Mesh.cpp`의 FBX 버전과 비교하면 **"aiMesh에서 복사"가 "파일에서 fread"로 바뀌는 것**뿐이고, 버퍼를 만드는 부분은 똑같다.

**미리 막아야 하는 것:** 이번 장에서는 머티리얼을 아직 안 읽어서 `m_Materials`가 비어 있다. `Tree_Instance`는 메시마다 `Bind_Material`을 부르므로, 그대로 두면 `m_Materials[0]`에서 범위 밖 접근으로 터진다(3-6).

### 3-3. Mesh.cpp: Initialize_Prototype(FILE*)
```cpp
HRESULT CMesh::Initialize_Prototype(FILE* pFile, fmatrix_t PreTransformMatrix)
{
#pragma region DATA
    // ① 메시 앞부분 3개
    if (1 != fread(&m_iMaterialIndex, sizeof(uint32_t), 1, pFile) ||
        1 != fread(&m_iVertexStride, sizeof(uint32_t), 1, pFile) ||
        1 != fread(&m_iNumVertices, sizeof(uint32_t), 1, pFile))
    {
        MSG_BOX("Failed to Read : Mesh Info");
        return E_FAIL;
    }

    // ② 정점 모양 검사
    if (sizeof(VTXMESH) != m_iVertexStride || 0 == m_iNumVertices)
    {
        MSG_BOX("Vertex Stride Mismatch : Reconvert");
        return E_FAIL;
    }

    m_iNumVertexBuffers = 1;
    m_iIndexStride = 4;
    m_eIndexFormat = DXGI_FORMAT_R32_UINT;
    m_ePrimitiveTopology = D3D11_PRIMITIVE_TOPOLOGY_TRIANGLELIST;
#pragma endregion

#pragma region VERTEX_BUFFER
    // ③ 정점 한 번에 읽기
    shared_ptr<VTXMESH[]> pVertices = make_shared<VTXMESH[]>(m_iNumVertices);
    if (m_iNumVertices != fread(&pVertices[0], sizeof(VTXMESH), m_iNumVertices, pFile))
    {
        MSG_BOX("Failed to Read : Vertices");
        return E_FAIL;
    }

    // ④ PreTransformMatrix 적용 (변환기에서 안 한 것)
    for (uint32_t i = 0; i < m_iNumVertices; ++i)
    {
        XMStoreFloat3(&pVertices[i].vPosition,
            XMVector3TransformCoord(XMLoadFloat3(&pVertices[i].vPosition), PreTransformMatrix));
        XMStoreFloat3(&pVertices[i].vNormal,
            XMVector3TransformNormal(XMLoadFloat3(&pVertices[i].vNormal), PreTransformMatrix));
        XMStoreFloat3(&pVertices[i].vTangent,
            XMVector3TransformNormal(XMLoadFloat3(&pVertices[i].vTangent), PreTransformMatrix));
        XMStoreFloat3(&pVertices[i].vBinormal,
            XMVector3TransformNormal(XMLoadFloat3(&pVertices[i].vBinormal), PreTransformMatrix));
    }

    // ⑤ 정점 버퍼 (FBX 버전과 같음)
    D3D11_BUFFER_DESC   VertexBufferDesc{};
    VertexBufferDesc.ByteWidth = m_iVertexStride * m_iNumVertices;
    VertexBufferDesc.Usage = D3D11_USAGE_DEFAULT;
    VertexBufferDesc.BindFlags = D3D11_BIND_VERTEX_BUFFER;
    VertexBufferDesc.CPUAccessFlags = 0;
    VertexBufferDesc.MiscFlags = 0;
    VertexBufferDesc.StructureByteStride = m_iVertexStride;

    D3D11_SUBRESOURCE_DATA VertexInitialData{};
    VertexInitialData.pSysMem = pVertices.get();

    if (FAILED(m_pDevice->CreateBuffer(&VertexBufferDesc, &VertexInitialData, &m_pVB)))
        return E_FAIL;

    // ⑥ AABB (FBX 버전과 같음, 반드시 ④ 뒤에)
    m_bUseCulling = true;
    BoundingBox::CreateFromPoints(m_tLocalBox, m_iNumVertices, &pVertices[0].vPosition, sizeof(VTXMESH));
#pragma endregion

#pragma region INDEX_BUFFER
    // ⑦ 인덱스 개수 + 인덱스
    if (1 != fread(&m_iNumIndices, sizeof(uint32_t), 1, pFile))
    {
        MSG_BOX("Failed to Read : NumIndices");
        return E_FAIL;
    }

    shared_ptr<uint32_t[]>  pIndices = make_shared<uint32_t[]>(m_iNumIndices);
    if (m_iNumIndices != fread(&pIndices[0], sizeof(uint32_t), m_iNumIndices, pFile))
    {
        MSG_BOX("Failed to Read : Indices");
        return E_FAIL;
    }

    // ⑧ 인덱스 버퍼 (FBX 버전과 같음)
    D3D11_BUFFER_DESC           IndexBufferDesc{};
    IndexBufferDesc.ByteWidth = m_iIndexStride * m_iNumIndices;
    IndexBufferDesc.Usage = D3D11_USAGE_DEFAULT;
    IndexBufferDesc.BindFlags = D3D11_BIND_INDEX_BUFFER;
    IndexBufferDesc.CPUAccessFlags = 0;
    IndexBufferDesc.MiscFlags = 0;
    IndexBufferDesc.StructureByteStride = m_iIndexStride;

    D3D11_SUBRESOURCE_DATA          IndexInitialData{};
    IndexInitialData.pSysMem = pIndices.get();

    if (FAILED(m_pDevice->CreateBuffer(&IndexBufferDesc, &IndexInitialData, &m_pIB)))
        return E_FAIL;
#pragma endregion
    return S_OK;
}
```

### 3-4. 줄별 설명
**① 메시 앞부분**
- `m_iMaterialIndex`, `m_iVertexStride`, `m_iNumVertices`를 멤버에 **바로** 읽어 넣는다.

**② Stride 검사** ((2)편 5-3에서 VertexStride를 남겨 둔 이유)
- 파일의 56과 지금 엔진의 `sizeof(VTXMESH)`가 다르면, 정점 구조가 바뀌었는데 VERSION을 안 올리고 예전 파일을 읽는 경우다. 여기서 거른다.
- 앞에서 바이트가 어긋나 쓰레기 값이 들어와도 여기서 한 번 더 걸린다.
- `0 == m_iNumVertices`도 막는다. ⑥의 `pVertices[0]`과 크기 0 `CreateBuffer`가 실패한다.

**③ 정점 한 번에 읽기**
- `VTXMESH`로 **바로** 읽는다. `VERTEX_STATIC` → `VTXMESH`로 옮겨 담지 않아도 되는 이유:
  - 멤버 순서와 타입이 같고, 2-1의 `static_assert`가 크기를 보장한다.
  - `VTXMESH` 안의 `Elements[]`, `iNumElements`는 `static`이라 구조체 크기에 들어가지 않는다. 정점 하나는 float 14개(56바이트)뿐이다.
- (1)편 1-4의 "사진을 다시 메모리에 붙여넣기"가 이 한 줄이다. 정점 611개를 반복 없이 한 번에 읽는다.

**④ PreTransformMatrix**
- FBX 버전의 `Ready_Meshes_For_NonAnim`과 같은 계산이다. 위치는 `TransformCoord`(이동 포함), 방향 벡터 셋은 `TransformNormal`(이동 제외).
- UV는 변환하지 않는다.

**⑤⑧ 버퍼**
- `CreateBuffer`가 끝나면 GPU로 복사가 끝난다. 임시 배열은 함수를 나갈 때 해제된다((1)편 0-4 "읽고 나면 임시 배열만 해제").

**⑥ AABB**
- PreTransform을 적용한 **뒤의** 위치로 계산해야 컬링이 맞다.

**⑦ 인덱스**
- 변환기에서 면을 펴서 저장해 뒀으니 엔진은 **면 루프 없이** 그대로 읽는다. (1)편 0-4의 "무거운 일은 변환할 때 한 번만"이 여기서 보인다.

### 4-1. 이번 장에서 할 일
(2)편 6장 `Write_Materials`를 뒤집어 읽는다.

### 4-3. To_AiTextureType (임시 번역)
```cpp
bool_t CMaterial::To_AiTextureType(ModelFile::TEXTURE_TYPE eType, aiTextureType& eOutType)
{
	switch (eType)
	{
	case ModelFile::TEXTURE_TYPE::DIFFUSE:	eOutType = aiTextureType_DIFFUSE;	return true;
	case ModelFile::TEXTURE_TYPE::NORMALS:	eOutType = aiTextureType_NORMALS;	return true;
	case ModelFile::TEXTURE_TYPE::SPECULAR:	eOutType = aiTextureType_SPECULAR;	return true;
	case ModelFile::TEXTURE_TYPE::EMISSIVE:	eOutType = aiTextureType_EMISSIVE;	return true;
	default:								return false;
	}
}
```
- 변환기 `To_TextureType`의 거울이다.
- **임시인 이유:** `m_Materials[]` 배열과 `Bind_Material(…, aiTextureType, …)`이 아직 aiTextureType 기준이라 엔진 안에서는 다시 assimp 번호로 바꿔야 한다. assimp를 뺄 때 `m_Materials[TEXTURE_TYPE::END]`로 바꾸면 이 함수는 없어진다.
- **파일 안에는 assimp 번호가 없다.** 엔진 쪽을 바꿔도 .bin을 다시 만들 필요가 없다.
- 번호가 다르다는 점에 주의한다. `TEXTURE_TYPE::DIFFUSE` = 0, `aiTextureType_DIFFUSE` = 1.

### 4-4. Material.cpp: Initialize(FILE*)
```cpp
HRESULT CMaterial::Initialize(const char_t* pModelFilePath, FILE* pFile)
{
	// ① 모델 폴더 (텍스처는 .bin과 같은 폴더에 있다)
	char_t	szDrive[MAX_PATH] = {};
	char_t	szDir[MAX_PATH] = {};
	_splitpath_s(pModelFilePath, szDrive, MAX_PATH, szDir, MAX_PATH, nullptr, 0, nullptr, 0);

	// ② 텍스처 개수
	uint32_t	iNumTextures = {};
	if (1 != fread(&iNumTextures, sizeof(uint32_t), 1, pFile))
	{
		MSG_BOX("Failed to Read : NumTextures");
		return E_FAIL;
	}

	for (uint32_t i = 0; i < iNumTextures; ++i)
	{
		// ③ 종류, 이름 길이 + 검사
		uint32_t	iType = {};
		uint32_t	iLength = {};
		if (1 != fread(&iType, sizeof(uint32_t), 1, pFile) ||
			1 != fread(&iLength, sizeof(uint32_t), 1, pFile))
		{
			MSG_BOX("Failed to Read : Texture Info");
			return E_FAIL;
		}

		aiTextureType	eAiType = {};
		if (false == To_AiTextureType(static_cast<ModelFile::TEXTURE_TYPE>(iType), eAiType) ||
			0 == iLength || iLength >= MAX_PATH)
		{
			MSG_BOX("Invalid Texture Info : Reconvert");
			return E_FAIL;
		}

		// ④ 이름 (길이만큼, '\0' 없이 저장됨)
		char_t	szFileName[MAX_PATH] = {};
		if (iLength != fread(szFileName, sizeof(char_t), iLength, pFile))
		{
			MSG_BOX("Failed to Read : Texture Name");
			return E_FAIL;
		}

		// ⑤ 경로 조립 (FBX 버전과 같음)
		char_t	szTempFilePath[MAX_PATH] = {};
		strcpy_s(szTempFilePath, szDrive);
		strcat_s(szTempFilePath, szDir);
		strcat_s(szTempFilePath, szFileName);

		wchar_t	szPerfectPath[MAX_PATH] = {};
		MultiByteToWideChar(CP_ACP, 0, szTempFilePath, -1, szPerfectPath, MAX_PATH);

		// ⑥ 확장자로 로더 고르기 (FBX 버전과 같음)
		char_t	szExt[MAX_PATH] = {};
		_splitpath_s(szFileName, nullptr, 0, nullptr, 0, nullptr, 0, szExt, MAX_PATH);

		HRESULT		hr = {};
		ComPtr<ID3D11ShaderResourceView>	pSRV = { nullptr };

		if (0 == strcmp(szExt, ".dds"))
			hr = CreateDDSTextureFromFile(m_pDevice.Get(), szPerfectPath, nullptr, &pSRV);
		else if (0 == strcmp(szExt, ".tga"))
			hr = E_FAIL;
		else
			hr = CreateWICTextureFromFile(m_pDevice.Get(), szPerfectPath, nullptr, &pSRV);

		if (FAILED(hr))
		{
			MSG_BOX("Failed to Load : Texture");
			return E_FAIL;
		}

		m_Materials[eAiType].push_back(pSRV);
	}
	return S_OK;
}
```

### 4-5. 줄별 설명
**① 모델 폴더**
- `pModelFilePath`는 이제 `.bin` 경로다. .bin은 FBX와 같은 폴더에 있으니 텍스처도 같은 폴더에서 찾는다.
- FBX 버전은 텍스처마다 다시 계산하지만, 모델 경로는 바뀌지 않으니 루프 밖에서 한 번만 한다.

**③ 종류와 길이 검사**
- `iLength >= MAX_PATH`면 거절한다. `szFileName`이 고정 버퍼라 넘치면 메모리를 덮어쓴다. `>=`인 이유는 끝에 `'\0'` 자리 1칸이 남아야 해서다.
- 모르는 종류 번호(4 이상)도 거절한다. 변환기는 지원하는 4종만 쓰니 다른 값이 나오면 파일이 깨진 것이다.
- `To_AiTextureType`의 반환값을 버리면, 실패했을 때 `eAiType`이 0(`aiTextureType_NONE`)으로 남아 엉뚱한 칸에 들어간다.

**④ 이름**
- (2)편 6-6 ⑤의 "길이 → 글자" 약속대로 길이만큼만 읽는다.
- 버퍼를 `{}`로 0 초기화해서, 17글자를 읽으면 18번째가 이미 `'\0'`이다. 바로 C 문자열로 쓸 수 있다.

**⑤⑥ 경로와 SRV**
- FBX 버전과 같은 코드다. 이름에 확장자가 붙어 있으니 `szFileName` 하나만 붙인다.
- ⑤⑥이 FBX 버전과 중복이다. 나중에 `Load_Texture(aiTextureType, const char_t* pFullPath)` 같은 private 함수로 빼면 두 `Initialize`가 같이 쓸 수 있다.

- 이 이름표를 쓰는 곳이 여러 군데다.
  - `Player.cpp`: Boss_Wu 이름표로 `Add_Component`
  - `Tree_Instance.cpp`: 나무 이름표로 `Add_Component`
  - `StaticProp::Change_Model`: 넘겨받은 메시 경로를 이름표로 `Has_Prototype` 검사 → 저장된 맵 데이터의 `.fbx` 이름으로 찾는다
- 그래서 **이름표는 `.fbx`로 두고 두 번째 경로만 바꾼다.** 이름표 정리(확장자 없는 이름 등)는 assimp를 뺄 때 한 번에 한다.

**MapTool에서 한 번에 바꾸기:** 이 파일만 열고 Ctrl+H로 `.fbx"))))` → `.bin"))))`, 대상은 **현재 문서**. 이름표 줄은 `.fbx")),`로 끝나서 걸리지 않는다.

auto tStart = chrono::steady_clock::now();

## 6. 정리

### 6-1. 완성된 흐름
```
FBX 수정/추가 → ModelConverter.exe에 드래그 → .bin 생성 → Loader에 .bin 경로
                                                         (이름표는 그대로)
```
Client와 MapTool의 모든 NONANIM 모델에 적용된 상태다.

| | 전 (FBX 직접) | 후 (.bin) |
|---|---|---|
| 로딩 | assimp 해석 + 후처리 매번 | `fread` + 버퍼 생성 |
| 메모리 | `aiScene`이 CModel에 계속 남음 | 임시 배열만 쓰고 해제 |
| 면 → 인덱스 펴기 | 매번 | 변환할 때 한 번 |
| 잘못된 파일 | - | 매직/버전/타입/Stride/길이/남은 바이트로 거절 |

### 6-2. 이번 편에서 정한 것
| 결정 | 이유 |
|---|---|
| aiMesh*/aiMaterial* 자리에 FILE* (오버로드) | 변환기의 Write_ 함수와 1:1 대응 |
| 확장자로 분기, FBX 코드는 그대로 | 애니메이션은 계속 FBX로 학습 |
| `.bin`은 NONANIM만 허용 | 뼈 정보가 없음 |
| 파일은 한 곳에서 닫기 | 어느 길로 나가든 잠긴 파일이 남지 않게 |
| 읽자마자 검사 | 1바이트 어긋남이 쓰레기 개수 → 거대 할당으로 번지는 것을 막음 |
| `VTXMESH`로 바로 `fread` | `static_assert`로 모양을 보장. 옮겨 담기 불필요 |
| `TEXTURE_TYPE` → `aiTextureType`은 임시 | 파일에는 assimp 번호가 없어서, 엔진을 바꿔도 재변환 불필요 |
| Bind_Material 범위 검사 | 잘못된 MaterialIndex로 터지지 않게 |
| 이름표는 `.fbx` 유지 | Player, Tree_Instance, 맵 데이터가 같은 이름으로 찾음 |

### 6-3. 코드와 이 문서의 차이 (보강하면 좋은 곳)
이 문서의 코드는 검사를 모두 넣은 버전이다. 커밋 `d7595395b` 시점의 코드에는 아래가 빠져 있다. 지금 .bin 7개는 정상이라 동작에는 문제가 없지만, 잘못된 파일을 만나면 거르지 못한다.

### 6-4. 남은 것 (다음 단계)

## 참고: 이번 편에서 만난 버그

### 매직을 1바이트만 읽음
```cpp
fread(szMagic, sizeof(char_t), 1, pFile)     // 1바이트 × 1개 = 1바이트  ✗
fread(szMagic, sizeof(szMagic), 1, pFile)    // 4바이트 × 1개           ✓
```
`'D'`만 읽고 `'K','M','D'`가 다음 칸으로 넘어가 뒤가 전부 3바이트씩 밀렸다.

| 읽은 칸 | 실제 바이트 위치 | 들어간 값 |
|---|---|---|
| szMagic | 0 | `'D'` |
| iVersion | 1~4 (`4B 4D 44 01`) | 쓰레기 값 |
| iType | 5~8 | 쓰레기 값 |
| NumMeshes | 9~12 (`00 00 00 01`) | **16,777,216** |
| VertexStride | 17~20 (`00 00 00 38`) | **939,524,096** |
| NumVertices | 21~24 (`00 00 00 63`) | **1,660,944,384** |

→ `make_shared<VTXMESH[]>(16억 개)` = 약 93GB 할당 시도.

**교훈**
- 매직 검사(2-5)가 있었다면 `"D\0\0\0" ≠ "DKMD"`로 **첫 단계에서 걸렸다.** (1)편 결정 1에서 매직을 맨 앞에 둔 이유가 이것이다.
- Stride 검사(3-3 ②)가 있었다면 메시 단계에서 한 번 더 걸렸다. (2)편 5-3에서 VertexStride를 남긴 이유다.
- 바이너리 읽기 버그는 **에러 없이 엉뚱한 값**으로 나타난다((1)편 규칙 ①). 그래서 읽자마자 검사한다.
