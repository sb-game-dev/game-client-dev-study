# 총알 이동구간 레이 검사 정리

## 0. 문제 상황
- 총알을 쏘면 **타겟 더미가 가끔 안 맞는다.** 가까이 가서 쏘면 맞는다.
- 원인은 콜라이더 크기 자체가 아니라 **터널링(Tunneling)** 이다.

| 항목 | 값 | 위치 |
|---|---|---|
| 총알 속도 | `100.f` | `Weapon.cpp` `Update_GunAttack` |
| 60fps 기준 한 프레임 이동 거리 | 약 **1.67** | 100 / 60 |
| 총알 콜라이더 Extents | `0.25f` (반지름 → 전체 크기 0.5) | `Bullet.h` `m_fWidth` |
| 충돌 검사 방식 | 매 프레임 **현재 위치끼리만** `Intersects` | `Level.cpp` `Process_Collision` |

```
 프레임 N        프레임 N+1
    ●  ┌────┐       ●        ← 두 프레임 모두 박스와 안 겹침 → 충돌 판정 없음
       │더미│
       └────┘
   |<----- 1.67 ----->|
```

- `총알 크기 + 더미 두께 < 한 프레임 이동 거리`이면 앞에서 뒤로 **건너뛴다.**
- 맞고 안 맞고가 "총알이 우연히 어느 위치에서 샘플링되느냐"에 달려 있어서 **가끔** 빗나간다.
- 가까이서 쏘면 맞는 이유: 총구에서 생성된 첫 프레임 위치가 이미 더미와 겹치거나 아주 가깝기 때문이다.
- 프레임이 떨어지면 한 프레임 이동 거리가 커져서 더 자주 빠진다.

> 빠른 확인법: 총알 속도를 `100 → 20`으로 낮춰보고, 멀리서도 잘 맞으면 터널링이 맞다.

## 1. 해결 아이디어: 이동구간 레이 검사
총알의 **이번 프레임 시작 위치 → 끝 위치**를 선분으로 보고, 그 선분이 더미 OBB를 지나갔는지 레이로 검사한다.
속도나 fps와 상관없이 놓치지 않는다.

```
 이전 위치 ●━━━━━━━━━━━━━━━━━━━━━━━● 현재 위치
                 ┌─────┐
                 │더미 │  ← 레이가 fDist에서 박스에 닿고, fDist <= 이동거리면 명중
                 └─────┘
```

1. 총알이 움직이기 **전** 위치를 저장한다 (`m_vPrevPos`).
2. `이전 위치 → 현재 위치` 벡터에서 **길이(fLen)** 와 **정규화된 방향(vDir)** 을 구한다.
3. 각 대상 OBB에 `Intersects(vStart, vDir, fDist)` 레이 검사를 한다.
4. `fDist <= fLen`이면 이번 프레임 이동 구간 안에서 맞은 것이다.
5. 여러 개가 걸리면 **가장 가까운 것(fDist 최소)** 만 맞힌다.

## 2. Bullet: 이전 위치 저장

**Bullet.h**
```cpp
public:
    vector_t Get_PrevPos() const { return XMLoadFloat3(&m_vPrevPos); }
    vector_t Get_CurPos()  const { return m_pTransformCom->Get_State(STATE::POSITION); }
    void     On_Hit(shared_ptr<CGameObject> pTarget);   // 명중 처리
private:
    float3_t m_vPrevPos = {};
```

**Bullet.cpp**
```cpp
void CBullet::Priority_Update(f32_t fDeltaTime)
{
    __super::Priority_Update(fDeltaTime);

    // 움직이기 "전" 위치를 저장
    XMStoreFloat3(&m_vPrevPos, m_pTransformCom->Get_State(STATE::POSITION));

    m_pTransformCom->Go_Straight(fDeltaTime);
    ...
}

void CBullet::Bullet_Active(...)
{
    ...
    m_pTransformCom->Set_State(STATE::POSITION, vPosition);
    XMStoreFloat3(&m_vPrevPos, vPosition);   // 발사 시점에도 초기화 (이전 총알 위치가 남지 않게)
    ...
}

void CBullet::On_Hit(shared_ptr<CGameObject> pTarget)
{
    for (auto& pHit : m_Hit_Targets)
        if (pHit.lock() == pTarget) return;

    pTarget->Take_Damage(m_tDamageDesc);
    m_Hit_Targets.push_back(pTarget);
    m_bActive = false;     // 관통 안 시킬 거면 여기서 끔
}
```

> `Bullet_Active`에서 `m_vPrevPos`를 초기화하지 않으면, 풀링된 총알이 **이전에 사라진 위치 → 새 총구 위치**로 긴 레이를 쏴서 엉뚱한 대상이 맞을 수 있다.

## 3. Level_ZeroZone::Update: 총알만 레이로 검사
총알은 `Process_Collision`의 `Objects`에서 빼고 따로 검사한다. 무기(근접) 판정은 기존처럼 둔다.

```cpp
// 기존: for (auto& Bullet : Bullets) Objects.push_back(Bullet);   ← 이 줄 제거

for (auto& pBullet : Bullets)
{
    if (nullptr == pBullet || !pBullet->Is_Active() || pBullet->Is_Dead())
        continue;

    vector_t vStart = pBullet->Get_PrevPos();
    vector_t vSeg   = pBullet->Get_CurPos() - vStart;
    f32_t    fLen   = XMVectorGetX(XMVector3Length(vSeg));
    if (fLen < 1e-5f)
        continue;
    vector_t vDir = vSeg / fLen;            // Intersects는 방향이 반드시 정규화돼 있어야 함

    shared_ptr<CGameObject> pClosest = nullptr;
    f32_t fClosest = FLT_MAX;

    for (auto& [strName, pObj] : *GamePlayLevelObjects)
    {
        if (nullptr == pObj || !pObj->Is_Active() || pObj->Is_Dead())
            continue;

        shared_ptr<CCube_Collider> pCube;
        if (FAILED(pObj->Get_Component(pCube)) || !pCube->Get_Active())
            continue;

        f32_t fDist = 0.f;
        if (pCube->Get_Info().Intersects(vStart, vDir, fDist)
            && fDist <= fLen            // 이번 프레임 이동 구간 안에서 맞았는지
            && fDist < fClosest)        // 여러 개 겹치면 제일 가까운 것만
        {
            fClosest = fDist;
            pClosest = pObj;
        }
    }

    if (pClosest)
        pBullet->On_Hit(pClosest);
}
```

### 포인트
- **`fDist <= fLen` 비교가 핵심.** 없으면 레이가 무한히 뻗어서 멀리 있는 더미까지 맞는다.
- **가장 가까운 대상만 맞히기** → 더미 두 개가 일렬로 있을 때 뒤의 것이 먼저 맞는 문제를 막는다.
- `Get_Component`가 `CCube_Collider` 타입으로 안 잡히면 `CCollider`로 받은 뒤 `dynamic_pointer_cast<CCube_Collider>` 한다.
- 시작점이 이미 박스 안에 있으면 `fDist`가 0 근처로 나온다. `<= fLen` 조건을 통과하므로 근접 사격도 정상 판정된다.
- 레이는 총알 **중심선**만 검사한다(총알 두께 무시). 총알이 가늘어서 실제로는 거의 차이가 없다.
- 이 방식으로 바꾸면 `CBullet::TriggerEnter`는 더 이상 호출되지 않으니 비우거나 지워도 된다.

## 4. 더미 콜라이더 높이 맞추기
레이 판정이 정확해져도 **박스 위치가 틀리면** 빗나간다.

- 설계 의도: AABB에서는 **크기만** 가져오고, 위치는 **소유자 위치**를 쓴다.
- `Cube_Collider::Get_Info()`는 박스 **중심**을 소유자 원점에 둔다.
- 더미 모델의 원점(피벗)은 보통 **발밑**이다 → 박스가 Extents.y만큼 내려가서 **절반이 땅속**에 들어간다.
- 총구 높이로 날아가는 총알이 박스 윗면 근처를 지나가면 빗나간다.

### 해결: `Set_Offset`으로 AABB 중심 높이만큼 올리기
`Get_Info()`에서 `vTrans + m_vOffset`으로 더해지므로, 의도(위치 = 소유자)를 유지하면서 높이만 보정할 수 있다.

```cpp
// TargetDummy::Ready_Components
const BoundingBox& AABB = m_pBodyTargetDummy->Get_AABB();
m_pCube_Collider->Set_OBBSize(AABB);
m_pCube_Collider->Set_Offset({ 0.f, AABB.Center.y, 0.f });   // 발밑 → 몸통 중앙
```

### 확인할 것
1. **스케일**: `Get_Info()`는 `XMMatrixDecompose`로 얻은 `vScale`을 버린다.
   - 모델 로드 때 PreTransform으로 스케일이 정점에 적용돼 있으면 괜찮다.
   - 더미 Transform에 `Set_Scale`을 걸었다면 박스 크기와 오프셋 모두 그 배율만큼 틀어진다.
2. **오프셋은 회전이 적용되지 않는다**: 월드 공간에서 그냥 더해진다.
   - y축 오프셋만 쓰면 더미가 회전해도 문제없다.
   - `AABB.Center.x/z`까지 넣으면 회전 시 박스가 어긋난다.
3. **눈으로 확인**: `Render_Collider`는 지금 코너만 구하고 그리지 않는다. 디버그 라인 렌더링을 붙여 박스가 몸통에 맞게 씌워지는지 확인하면 좋다.

## 5. 콜라이더는 부모, 모델은 자식 구조
`CTargetDummy`(부모, ContainerObject)가 콜라이더를 갖고, `CBody_TargetDummy`(자식, PartObject)가 모델을 갖는 구조는 **문제없고, 이 경우엔 오히려 더 맞다.**

### 부모에 두는 게 좋은 이유
- 판정 결과(`TriggerEnter`, `Take_Damage`)가 콜라이더 소유자에게 가는데, **HP·HP바를 관리하는 것이 부모**이므로 자식 → 부모로 다시 전달할 필요가 없다.
- `Level_ZeroZone::Update`는 `Layer_GameObject`에 있는 오브젝트의 컴포넌트만 검사한다. **파트 오브젝트는 레이어에 없으므로** 자식에 콜라이더를 달면 아예 검사되지 않는다.
- 헬멧·아머 등 파트가 붙어도 판정은 부모 하나로 관리할 수 있다.

### 주의할 점
1. **자식 로컬 변환과의 어긋남**: 콜라이더는 부모 Transform을 따르고 크기만 자식 모델 AABB에서 가져온다. Body 파트에 부모 기준 로컬 오프셋·회전·스케일이 있으면 그만큼 어긋난다.
2. **애니메이션 미반영**: AABB는 바인드 포즈 기준 고정 크기다. 허수아비처럼 살짝 흔들리는 정도는 괜찮지만, 숙이거나 구르는 캐릭터는 **뼈 소켓에 붙인 부위별 콜라이더**를 고려해야 한다.
3. **초기화 순서**: `Ready_PartObjects()` → `Ready_Components()` 순서여야 `Get_AABB()`가 유효하다. (현재 코드는 맞는 순서)

## 6. 기타
- `Bullet.cpp` `Priority_Update`에서 `m_fMoveDistance >= 100`이면 비활성화되므로, **사거리 100 밖의 대상은 원래 맞지 않는다.**
- 다른 대안
  - **스윕 박스**: 총알 Extents를 진행 방향으로 "한 프레임 이동 거리의 절반 이상" 늘린다. 기존 충돌 시스템을 그대로 쓸 수 있지만 속도·fps가 바뀌면 값을 다시 맞춰야 한다.
  - **서브스텝**: 한 프레임 이동을 여러 번으로 쪼개서 이동·검사를 반복한다. 비용이 늘어난다.
  - 정확도와 비용을 함께 보면 **레이 검사가 가장 깔끔하다.**
