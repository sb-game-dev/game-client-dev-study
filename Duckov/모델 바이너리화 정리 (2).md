| 장 | 끝나면 나와야 하는 크기 |
|---|---|
| 3. Convert | 0 bytes |
| 4. Write_Header | 12 bytes |
| 5. Write_Meshes | 45144 bytes |
| 6. Write_Materials | 45177 bytes |

## 1. CConverter 설계

### 1-1. 멤버 변수로 들고 있는 것
| 멤버 | 하는 일 | 멤버인 이유 |
|---|---|---|
| `Assimp::Importer m_Importer` | FBX를 읽는 객체 | 장면(`aiScene`)의 주인이다. Importer가 사라지면 장면도 사라진다 |
| `const aiScene* m_pScene` | 읽은 결과 | `Write_Meshes`, `Write_Materials`가 꺼내 쓴다 |
| `FILE* m_pFile` | 열린 .bin 파일 (리모컨) | `Write_` 함수들이 인자 없이 쓸 수 있다 |
| `MODEL_TYPE m_eType` | NONANIM / ANIM | `Write_Header`가 파일에 기록한다 |

- `Write_Header(FILE* pFile, const aiScene* pScene, ...)`처럼 매번 넘겨도 되지만, 세 함수가 전부 같은 것을 쓰니 멤버로 둔다.

### 1-2. 엔진과 같은 생성 패턴
```cpp
private:
	CConverter() = default;
public:
	static shared_ptr<CConverter> Create();
```
- 생성자를 `private`로 막고 `Create`로만 만든다. 엔진 객체들(`CModel::Create` 등)과 같은 모양이다.
- `Create` 안에서 `Initialize`를 부르고, 실패하면 `nullptr`을 돌려준다.

### 1-3. 반환형은 `bool`
- 엔진은 `HRESULT`(`S_OK`, `E_FAIL`)를 쓰지만, 변환기는 `Engine.dll`을 링크하지 않는 독립 프로그램이다.
- 성공/실패만 알면 되니 `bool`이면 충분하다.

### 1-4. 경로는 `string`(char)으로 받는다
- assimp의 `ReadFile`은 `char` 경로를 받는다.
- 파일을 여는 `_wfopen_s`는 `wchar_t` 경로를 받으니, 열기 직전에 한 번만 바꾼다(3장).
- 변환기의 각 단계가 어떤 문자열 타입을 쓰는지는 **(1)편 부록 A-4-2**.

### 1-5. 함수 목록
| 함수 | 하는 일 | 장 |
|---|---|---|
| `Convert(FBX 경로, 타입)` | 읽기 → 열기 → 쓰기 → 닫기 → 실패 처리 | 3 |
| `Write_Header` | 매직, 버전, 타입 | 4 |
| `Write_Meshes` | 메시 블록 | 5 |
| `Write_Materials` | 머티리얼 블록 | 6 |
| `To_TextureType` (static) | `aiTextureType` → 엔진 `TEXTURE_TYPE` | 6 |
| `Dump` | .bin을 다시 읽어 출력 (선언만, 이번 편에서는 구현하지 않음) | - |

### 1-6. Convert 흐름과 실패 처리
```
Convert(FBX 경로, 타입)
 ├ 1. FBX 읽기            실패 → return false (정리할 것 없음)
 ├ 2. .bin 경로 만들기     실패 → 장면 해제 후 return false
 ├ 3. 파일 열기            실패 → 장면 해제 후 return false
 ├ 4. Write_Header && Write_Meshes && Write_Materials
 │      (하나라도 false면 나머지는 건너뛴다)
 ├ 5. 크기 기록, 파일 닫기  ┐ 성공이든 실패든 항상
 ├ 6. 장면 해제            ┘
 ├ 7. 실패했으면 파일 삭제
 └ 8. 완료 출력
```
- **"있으면 완전한 파일, 아니면 없음."** 헤더만 있고 메시가 반쯤 써진 파일이 남으면, 엔진이 매직과 버전은 통과시키고 내용을 읽다가 이상해진다. 그래서 실패하면 지운다.
- 정리(5, 6)는 성공/실패 갈림길(7) **앞에** 둔다. 어느 길로 나가든 빠지지 않게 하기 위해서다.

### 1-7. 파일 추가
솔루션 탐색기 → ModelConverter → 추가 → 새 항목. **위치를 직접 바꾼다.**

| 파일 | 위치 |
|---|---|
| `Converter.h` | `Game\ModelConverter\Public\` |
| `Converter.cpp` | `Game\ModelConverter\Private\` |

- `Public`은 (1)편 6-4에서 포함 디렉터리로 잡아 두어서 `#include "Converter.h"`로 바로 찾는다.
- 다른 소스처럼 **CP949**(또는 BOM 있는 UTF-8)로 저장한다. BOM 없는 UTF-8이면 콘솔 한글이 깨진다.

### 1-8. `Model_Format.h`에 `MODEL_TYPE` 추가
```cpp
enum class TEXTURE_TYPE	{ DIFFUSE, NORMALS, SPECULAR, EMISSIVE, END };
enum class MODEL_TYPE	{ NONANIM, ANIM };
```
- 엔진의 `MODEL` enum과 같은 의미지만, 변환기는 엔진 헤더(`Engine_Defines.h`)를 include하지 않으니 약속 파일에 따로 둔다.
- 엔진을 빌드하면 PostBuild로 `EngineSDK/Inc/`에 복사된다. **두 파일이 같은지 확인한다.** (3)편에서 엔진 쪽이 SDK 헤더로 읽기 때문이다.
- 파일에 쓸 때는 `uint32_t`로 바꿔서 쓴다(4장). `enum class`의 기본 크기는 `int`(4바이트)라서 지금도 맞지만, 크기를 확실히 고정하고 싶으면 `enum class MODEL_TYPE : uint32_t`처럼 적는다.

### 1-9. `Converter.h`
```cpp
#pragma once
#include <iostream>
#include <string>
#include <memory>
#include <cstdio>

#include "Assimp/Importer.hpp"
#include "Assimp/scene.h"
#include "Assimp/postprocess.h"
#include "Model_Format.h"
using namespace std;
using namespace Engine::ModelFile;

class CConverter
{
private:
	CConverter() = default;
public:
	~CConverter();

public:
	bool	Initialize();
	bool	Convert(const string& strFbxPath, MODEL_TYPE eType);
	bool	Dump(const string& strBinPath);

private:
	Assimp::Importer	m_Importer;
	const aiScene*		m_pScene = { nullptr };
	FILE*				m_pFile = { nullptr };
	MODEL_TYPE			m_eType = { MODEL_TYPE::NONANIM };

private:
	bool	Write_Header();
	bool	Write_Meshes();
	bool	Write_Materials();

	static bool	To_TextureType(aiTextureType eAiType, TEXTURE_TYPE& eOutType);

public:
	static shared_ptr<CConverter> Create();
};
```
- `using namespace Engine::ModelFile;` 덕분에 `MODEL_TYPE`, `VERTEX_STATIC`, `MAGIC`을 접두사 없이 쓴다.
- **주의:** 헤더에 `using namespace std;`가 있으면 이 헤더를 include하는 모든 파일에 퍼진다. 3-3의 `byte` 충돌이 이것 때문에 생긴다.

### 1-10. `Converter.cpp` 뼈대
```cpp
CConverter::~CConverter()
{
	if (nullptr != m_pFile)
	{
		fclose(m_pFile);
		m_pFile = nullptr;
	}
}

bool CConverter::Initialize()						{ return true; }

```
- **소멸자의 안전장치:** Convert 도중 예외 등으로 파일이 열린 채 객체가 사라져도 닫히게 한다. 평소에는 Convert가 직접 닫고 `nullptr`로 돌려두므로 여기서 할 일이 없다.
- `make_shared` 대신 `shared_ptr<CConverter>(new CConverter())`인 이유: 생성자가 `private`라서 `make_shared`가 생성자를 부를 수 없다. 클래스 안의 `Create`는 부를 수 있다.

## 3. Convert — FBX 읽기, 파일 열기/닫기, 실패 처리

### 3-1. 이번 장에서 할 일
1-6의 흐름도를 코드로 옮긴다. `Write_` 함수들은 아직 빈 함수(`return true`)라서, 이번 장이 끝나면 FBX 옆에 **0바이트 `.bin`** 이 생긴다.

### 3-2. 새로 쓰는 도구
| 도구 | 어디에 있나 | 하는 일 |
|---|---|---|
| `_splitpath_s` | C 런타임 | 경로를 드라이브 / 폴더 / 파일 이름 / 확장자로 쪼갠다 |
| `strcpy_s`, `strcat_s` | C 런타임 | 문자열 복사, 이어 붙이기 (버퍼 크기를 넘으면 멈춤) |
| `MultiByteToWideChar` | Windows | `char` 문자열 → `wchar_t` 문자열 |
| `MAX_PATH` | Windows | 경로 최대 길이 260 |
| `ftell` | C 런타임 | 파일 커서의 현재 위치 = 지금까지 쓴 바이트 수 |
| `_wremove` | C 런타임 | 파일 삭제 (wide 경로) |

엔진 `Material.cpp`가 텍스처 경로를 만들 때 쓰는 도구들과 같다.

**`_splitpath_s`가 경로를 쪼개는 모습** (`../../../Resource/Mesh/Tree/Pfb_Tree_01_1.fbx`)

| 받을 칸 | 결과 |
|---|---|
| 드라이브 | `""` (상대경로라 없음. 절대경로면 `C:`) |
| 폴더 | `../../../Resource/Mesh/Tree/` |
| 파일 이름 | `Pfb_Tree_01_1` |
| 확장자 | `.fbx` |

- 필요 없는 칸은 `nullptr, 0`을 넘기면 받지 않는다.

### 3-3. 경로를 쪼갰다가 다시 잇는 이유
**확장자만 `.fbx` → `.bin`으로 바꾸기 위해서다.**
```
쪼개기:   ""  +  "../../../Resource/Mesh/Tree/"  +  "Pfb_Tree_01_1"  +  ".fbx"(버림)
다시 잇기: ""  +  "../../../Resource/Mesh/Tree/"  +  "Pfb_Tree_01_1"  +  ".bin"
결과:     ../../../Resource/Mesh/Tree/Pfb_Tree_01_1.bin
```
- .bin은 **FBX와 같은 폴더, 같은 이름**에 생긴다. 엔진이 FBX 경로만 알면 .bin 위치도 바로 안다.
- "뒤에서 4글자 자르기"보다 `_splitpath_s`가 안전하다. 폴더 이름의 `.`(`../`)이나 대문자 `.FBX`도 헷갈리지 않고 마지막 확장자만 떼어 낸다.

### 3-4. include
```cpp
#include <Windows.h>
#include "Converter.h"
#include <vector>
```
- `MAX_PATH`, `MultiByteToWideChar`, `CP_ACP`가 `<Windows.h>`에 있다.
- 헤더가 아니라 `.cpp`에서 include한다. `<Windows.h>`는 아주 크고 `min`, `max` 같은 매크로까지 정의해서 다른 코드와 부딪히기도 한다.
- `<vector>`는 5, 6장에서 쓴다.

**`<Windows.h>`를 반드시 먼저 include하는 이유 (`C2872: 'byte': 모호한 기호`)**
```
#include "Converter.h"   // using namespace std;  → std::byte가 그냥 byte로 보이게 됨
#include <Windows.h>     // rpcndr.h: typedef unsigned char byte;  → 전역 byte
                         // 바로 다음 줄에서 byte를 쓰는데, ::byte인지 std::byte인지 모름 → C2872
```
- `<Windows.h>`를 먼저 읽으면, 그때는 아직 `std`가 풀려 있지 않아서 `byte`가 하나뿐이다.
- 근본 해결은 헤더에서 `using namespace std;`를 빼고 `.cpp`의 include 뒤로 옮기는 것이다.

### 3-5. 코드: Convert

**① 타입 저장, assimp 플래그 정하기**
```cpp
bool CConverter::Convert(const string& strFbxPath, MODEL_TYPE eType)
{
	m_eType = eType;
	uint32_t	iFlag = { aiProcess_ConvertToLeftHanded | aiProcessPreset_TargetRealtime_Fast };
	if (MODEL_TYPE::NONANIM == m_eType)
		iFlag |= aiProcess_PreTransformVertices;
```
- `m_eType`은 4장의 `Write_Header`가 쓴다. 그래서 가장 먼저 저장한다.
- 플래그는 엔진의 `CModel::Initialize_Prototype`과 **완전히 같다.** 다른 플래그로 읽으면 엔진이 FBX를 직접 읽었을 때와 정점이 달라진다.

**② FBX 읽기**
```cpp
	m_pScene = m_Importer.ReadFile(strFbxPath, iFlag);
	if (nullptr == m_pScene)
	{
		cout << "[Convert] 읽기 실패 : " << strFbxPath << '\n';
		cout << "          " << m_Importer.GetErrorString() << '\n';
		return false;
	}
```
- 실패하면 assimp가 알려주는 이유(`GetErrorString`)도 같이 출력한다.
- 아직 .bin을 만들기 전이라 지울 것도, 닫을 것도 없어서 바로 나간다.
- 출력 앞의 `[Convert]`는 여러 파일을 연달아 변환할 때(7장) 어느 단계의 로그인지 구분하기 위해서다.

**③ .bin 경로 만들기**
```cpp
	char	szDrive[MAX_PATH] = {};
	char	szDir[MAX_PATH] = {};
	char	szFileName[MAX_PATH] = {};

	if (0 != _splitpath_s(strFbxPath.c_str(), szDrive, MAX_PATH, szDir, MAX_PATH, szFileName, MAX_PATH, nullptr, 0))
	{
		cout << "[Convert] 경로 분해 실패 : " << strFbxPath << '\n';
		m_Importer.FreeScene();
		m_pScene = nullptr;
		return false;
	}

	char	szBinPath[MAX_PATH] = {};
	strcpy_s(szBinPath, szDrive);
	strcat_s(szBinPath, szDir);
	strcat_s(szBinPath, szFileName);
	strcat_s(szBinPath, ".bin");
```
- 확장자 칸은 `nullptr, 0`으로 받지 않는다(어차피 `.bin`으로 바꿀 거라서).
- 버퍼를 `{}`로 0 초기화해서, 받은 내용이 없으면 빈 문자열이 되게 한다. 상대경로라 `szDrive`가 비는 경우가 여기에 해당한다.
- 반환값이 0이 아니면 실패다(경로가 `MAX_PATH`보다 길 때 등). 엔진 `Material.cpp`는 이 검사를 하지 않지만, 변환기는 실패를 알리고 ②에서 읽은 장면을 해제한 뒤 나간다.
- `_s` 버전은 결과가 버퍼를 넘으면 그 자리에서 멈춘다(디버그에서는 경고 창). 버퍼 밖 메모리를 덮어쓰는 사고를 막는다.

**④ wide 경로로 바꾸고 파일 열기**
```cpp
	wchar_t	szWideBinPath[MAX_PATH] = {};
	MultiByteToWideChar(CP_ACP, 0, szBinPath, -1, szWideBinPath, MAX_PATH);

	if (0 != _wfopen_s(&m_pFile, szWideBinPath, L"wb") || nullptr == m_pFile)
	{
		cout << "[Convert] 파일 열기 실패 : " << szBinPath << '\n';
		m_Importer.FreeScene();
		m_pScene = nullptr;
		return false;
	}
```
- `MultiByteToWideChar(코드페이지, 옵션, 원본, 원본 길이, 결과 버퍼, 결과 버퍼 크기)`
  - `CP_ACP`: 원본이 시스템 기본 코드페이지(한국어 Windows는 CP949)라는 뜻. 엔진 `Material.cpp`와 같다.
  - 원본 길이 `-1`: 끝의 `'\0'`까지 알아서 세라는 뜻. 결과에도 `'\0'`이 들어간다.
- **경로 합치기는 "주소를 적는 것"일 뿐이고, 디스크에 파일이 생기는 건 `_wfopen_s`를 부르는 순간이다.**
- `L"wb"`: 쓰기 + 바이너리.
  - `w`: 파일이 없으면 **새로 만들고**, 있으면 **내용을 비우고** 연다. 다시 변환하면 항상 최신 내용으로 덮어써진다.
  - `b`: 바이트를 그대로 쓴다((1)편 2-2).
- 열린 파일(리모컨)을 멤버 `m_pFile`에 받는다. `Write_` 함수들이 인자 없이 쓰기 위해서다(1-1).
- `szWideBinPath`는 ⑦에서 파일을 지울 때 다시 쓴다.

**⑤ 블록 쓰기**
```cpp
	bool	bSuccess = Write_Header() && Write_Meshes() && Write_Materials();
```
- `A && B && C`는 왼쪽부터 계산하다가 `false`가 나오면 나머지를 **아예 부르지 않는다**(단락 평가). 1-6 흐름도의 "하나라도 false면 나머지는 건너뛴다"를 한 줄로 쓴 것이다.
- 바로 `return`하지 않고 `bSuccess`에 담아 둔다. 그 전에 ⑥ 정리를 해야 하기 때문이다.

**⑥ 정리: 크기 기록, 파일 닫기, 장면 해제 (성공이든 실패든)**
```cpp
	long	iFileSize = ftell(m_pFile);

	fclose(m_pFile);
	m_pFile = nullptr;

	m_Importer.FreeScene();
	m_pScene = nullptr;
```
- 처음부터 순서대로 쓰기만 했으니 **다 쓴 뒤의 커서 위치 = 파일 크기**다. 닫은 뒤에는 `m_pFile`을 쓸 수 없어서 `ftell`이 먼저다.
- `fclose`를 해야 버퍼에 남은 내용이 디스크에 써지고, ⑦에서 파일을 지울 수 있다(열려 있는 파일은 지울 수 없다).
- `nullptr`로 돌려두면 소멸자의 안전장치가 이미 닫은 파일을 또 닫지 않는다. 다음 `Convert`도 깨끗한 상태에서 시작한다(7장).
- `FreeScene`은 assimp가 들고 있던 장면 메모리를 바로 해제한다.

**⑦ 실패했으면 덜 써진 파일 지우기**
```cpp
	if (false == bSuccess)
	{
		_wremove(szWideBinPath);
		cout << "[Convert] 쓰기 실패, 파일 삭제 : " << szBinPath << '\n';
		return false;
	}
```
- `_wremove`는 `_wfopen_s`와 짝이 되는 wide 경로 삭제 함수다.

**⑧ 완료 출력**
```cpp
	cout << "[Convert] 완료 : " << szBinPath << " (" << iFileSize << " bytes)\n";
	return true;
}
```
- 탐색기를 열지 않고 콘솔에서 바로 크기를 확인한다.
- **함수 끝의 `return true;`를 빠뜨리면** 빌드는 되지만 경고 C4715가 뜨고 반환값이 정해지지 않는다(종료 코드가 0일지 -1일지 모름).

## 4. Write_Header (12바이트)

### 4-1. 쓸 것
| 순서 | 내용 | 크기 | 값 |
|---|---|---|---|
| 1 | `MAGIC` | 4 | `'D','K','M','D'` |
| 2 | `VERSION` | 4 | `1` |
| 3 | 모델 타입 (`m_eType`) | 4 | `NONANIM` = 0 |

### 4-2. 코드
```cpp
bool CConverter::Write_Header()
{
	if (1 != fwrite(MAGIC, sizeof(MAGIC), 1, m_pFile))
		return false;
	if (1 != fwrite(&VERSION, sizeof(VERSION), 1, m_pFile))
		return false;

	uint32_t	iType = static_cast<uint32_t>(m_eType);
	if (1 != fwrite(&iType, sizeof(iType), 1, m_pFile))
		return false;

	return true;
}
```
- `fwrite(주소, 한 개 크기, 개수, 파일)`은 실제로 쓴 **개수**를 돌려준다. 1개를 쓰라고 했는데 1이 아니면 실패다.
- `MAGIC`은 배열이라 이름 자체가 주소다. `VERSION`, `iType`은 변수라서 `&`가 필요하다.
- enum을 `uint32_t`로 바꿔서 쓴다. 파일 포맷에서는 크기를 명시적으로 고정하는 게 안전하다.

### 4-3. 확인
- 콘솔: `(12 bytes)`
- hex: `44 4B 4D 44  01 00 00 00  00 00 00 00` ("DKMD", 1, 0)

## 5. Write_Meshes (45144바이트)

### 5-1. 쓸 것 (포맷 표의 메시 블록)
```
uint32       NumMeshes
[NumMeshes 번 반복]
  uint32     MaterialIndex
  uint32     VertexStride     (56)
  uint32     NumVertices
  VERTEX_STATIC[] Vertices    (56 × NumVertices)
  uint32     NumIndices
  uint32[]   Indices          (4 × NumIndices)
```

### 5-2. 엔진 Mesh.cpp와 비교
| | 엔진 `Ready_Meshes_For_NonAnim` | 변환기 |
|---|---|---|
| 정점 채우기 | `memcpy`로 위치, 노멀, 탄젠트, 바이노멀, UV 복사 | 똑같이 복사 |
| `PreTransformMatrix` 곱하기 | 함 | **안 함.** 로드할 때 적용 ((1)편 3-2 결정 7) |
| 담는 곳 | `shared_ptr<VTXMESH[]>` → GPU 버퍼 | `vector<VERTEX_STATIC>` → `fwrite` |
| 인덱스 | 면마다 `mIndices[0~2]` | 똑같음 |

### 5-3. VertexStride를 기록하는 이유
`ModelType`만 보면 정점 구조를 알 수 있으니 정보로서는 중복이다. 그래도 넣는 이유는 **사람이 VERSION 올리는 걸 깜빡하는 경우**를 잡기 위해서다.
```
1. VTXMESH에 vColor(16바이트) 추가 → 72바이트
2. VERSION은 1 그대로 (깜빡함)
3. 엔진이 예전 .bin(56바이트 정점)을 읽음 → 매직/버전/타입 검사 통과
4. 72바이트씩 잘라 읽음 → 화면이 깨지거나 인덱스 개수 자리에 쓰레기 값
```
- `VertexStride`가 있으면 3번에서 "파일은 56, 엔진은 72 → 다시 변환하세요"로 걸러낼 수 있다.
- `static_assert(sizeof(VTXMESH) == sizeof(VERTEX_STATIC))`로는 못 잡는다. 그건 **지금 빌드 안의** 두 구조체만 비교하고, **예전에 만든 파일**과는 비교하지 않는다.
- 한계: 크기만 비교한다. 크기는 같고 멤버 순서만 바뀐 경우는 `VERSION`으로 막아야 한다.
- 비용은 메시당 4바이트다.

### 5-4. 코드
```cpp
bool CConverter::Write_Meshes()
{
	// ① 메시 개수
	uint32_t	iNumMeshes = m_pScene->mNumMeshes;
	if (1 != fwrite(&iNumMeshes, sizeof(uint32_t), 1, m_pFile))
		return false;

	for (uint32_t i = 0; i < iNumMeshes; ++i)
	{
		const aiMesh*	pAiMesh = m_pScene->mMeshes[i];

		// ② 메시 앞부분 3개
		uint32_t	iMaterialIndex = pAiMesh->mMaterialIndex;
		uint32_t	iVertexStride = sizeof(VERTEX_STATIC);
		uint32_t	iNumVertices = pAiMesh->mNumVertices;

		if (1 != fwrite(&iMaterialIndex, sizeof(uint32_t), 1, m_pFile) ||
			1 != fwrite(&iVertexStride, sizeof(uint32_t), 1, m_pFile) ||
			1 != fwrite(&iNumVertices, sizeof(uint32_t), 1, m_pFile))
			return false;

		// ③ 정점 (PreTransformMatrix는 .bin을 읽는 쪽에서 적용)
		vector<VERTEX_STATIC>	Vertices(iNumVertices);
		for (uint32_t j = 0; j < iNumVertices; ++j)
		{
			memcpy(&Vertices[j].vPosition, &pAiMesh->mVertices[j], sizeof(DirectX::XMFLOAT3));
			memcpy(&Vertices[j].vNormal, &pAiMesh->mNormals[j], sizeof(DirectX::XMFLOAT3));
			memcpy(&Vertices[j].vTangent, &pAiMesh->mTangents[j], sizeof(DirectX::XMFLOAT3));
			memcpy(&Vertices[j].vBinormal, &pAiMesh->mBitangents[j], sizeof(DirectX::XMFLOAT3));
			memcpy(&Vertices[j].vTexcoord, &pAiMesh->mTextureCoords[0][j], sizeof(DirectX::XMFLOAT2));
		}
		if (iNumVertices != fwrite(Vertices.data(), sizeof(VERTEX_STATIC), iNumVertices, m_pFile))
			return false;

		// ④ 인덱스 개수
		uint32_t	iNumIndices = pAiMesh->mNumFaces * 3;
		if (1 != fwrite(&iNumIndices, sizeof(uint32_t), 1, m_pFile))
			return false;

		// ⑤ 인덱스
		shared_ptr<uint32_t[]>	pIndices = make_shared<uint32_t[]>(iNumIndices);
		uint32_t	iIndex = {};
		for (uint32_t j = 0; j < pAiMesh->mNumFaces; ++j)
		{
			pIndices[iIndex++] = pAiMesh->mFaces[j].mIndices[0];
			pIndices[iIndex++] = pAiMesh->mFaces[j].mIndices[1];
			pIndices[iIndex++] = pAiMesh->mFaces[j].mIndices[2];
		}
		if (iNumIndices != fwrite(pIndices.get(), sizeof(uint32_t), iNumIndices, m_pFile))
			return false;

		cout << "[Write_Meshes] " << i << "번 : 정점 " << iNumVertices << ", 인덱스 " << iNumIndices << '\n';
	}
	return true;
}
```

### 5-5. 줄별 설명
**① 메시 개수**
- 읽는 쪽이 "몇 번 반복할지"를 먼저 알아야 해서 맨 앞에 쓴다((1)편 규칙 ②).

**② 메시 앞부분**
- `iVertexStride = sizeof(VERTEX_STATIC)`: 숫자 56을 직접 쓰지 않는다. 구조체가 바뀌면 값도 같이 바뀐다(5-3).
- `||`도 `&&`처럼 단락 평가를 한다. 앞에서 실패(`true`)가 나오면 뒤의 `fwrite`는 부르지 않는다.

**③ 정점**
- `mTextureCoords[0][j]`는 `aiVector3D`(x, y, z 12바이트)지만 `sizeof(XMFLOAT2)` = 8바이트만 복사하니 x, y만 들어간다. 엔진과 같다.
- `fwrite(Vertices.data(), 56, 개수, ...)`로 **한 번에** 쓴다. `&Vertices`가 아니라 `data()`다((1)편 규칙 ③).
- 반환값은 쓴 **개수**라서 `iNumVertices`와 비교한다.

**④⑤ 인덱스**
- 플래그에 Triangulate가 들어 있어서 면은 항상 삼각형이다. 그래서 `mNumFaces * 3`이다.
- 엔진 `CMesh::Initialize_Prototype`의 인덱스 펴기 코드와 같은 모양이다.
- 안쪽 루프 변수는 `j`로 쓴다. `i`를 또 선언하면 바깥 메시 번호를 가린다.

### 5-6. 확인
```

### 5-7. 문제가 생기면

		}
```

## 6. Write_Materials (45177바이트)

### 6-1. 쓸 것
```
uint32       NumMaterials
[NumMaterials 번 반복]
  uint32     NumTextures
  [NumTextures 번 반복]
    uint32   TextureType      (TEXTURE_TYPE 값)
    uint32   FileNameLength
    char[]   FileName         (파일 이름 + 확장자만, '\0' 없이)
```

### 6-2. 엔진 Material.cpp와 비교
| | 엔진 `CMaterial::Initialize` | 변환기 |
|---|---|---|
| 텍스처 순회 | `aiTextureType` 0 ~ MAX 전부 | 똑같음 |
| 경로 | `_splitpath_s`로 파일 이름 + 확장자만 꺼냄 | 똑같음 |
| 모델 폴더 붙이기 | 함 | **안 함.** 로드할 때 .bin 폴더를 붙임 ((1)편 3-2 결정 5) |
| 종류 저장 | `aiTextureType` 그대로 | **엔진 enum `TEXTURE_TYPE`으로 바꿈** (결정 6) |

### 6-3. 개수를 먼저 써야 하는 문제
- 포맷상 `NumTextures`를 텍스처 내용보다 **먼저** 써야 한다.
- 그런데 `To_TextureType`이 지원하지 않는 종류(예: `aiTextureType_AMBIENT`)는 건너뛰니, 실제로 쓸 개수는 다 돌아 보기 전에는 모른다.
- 그래서 **① vector에 모으기 → ② 개수(`size()`) 쓰기 → ③ 모은 것 쓰기** 로 나눈다.

### 6-4. To_TextureType
```cpp
bool CConverter::To_TextureType(aiTextureType eAiType, TEXTURE_TYPE& eOutType)
{
	switch (eAiType)
	{
	case aiTextureType_DIFFUSE:
		eOutType = TEXTURE_TYPE::DIFFUSE;
		return true;
	case aiTextureType_NORMALS:
		eOutType = TEXTURE_TYPE::NORMALS;
		return true;
	case aiTextureType_SPECULAR:
		eOutType = TEXTURE_TYPE::SPECULAR;
		return true;
	case aiTextureType_EMISSIVE:
		eOutType = TEXTURE_TYPE::EMISSIVE;
		return true;
	default:
		return false;
	}
}
```
- 반환값은 "엔진이 쓰는 종류인가"라는 뜻이다. `false`는 실패가 아니라 **건너뛰기**다.
- 결과는 참조 인자 `eOutType`으로 돌려준다. 반환값을 이미 "지원하는가"에 쓰고 있어서다.
- `static`이다. 멤버를 쓰지 않고 입력만 보고 답하는 변환 함수다.
- 이 함수 덕분에 `.bin` 안에는 assimp 번호가 없다. 나중에 엔진에서 assimp를 빼도 다시 변환할 필요가 없다.

### 6-5. 코드
```cpp
bool CConverter::Write_Materials()
{
	// ① 머티리얼 개수
	uint32_t	iNumMaterials = m_pScene->mNumMaterials;
	if (1 != fwrite(&iNumMaterials, sizeof(uint32_t), 1, m_pFile))
		return false;

	for (uint32_t i = 0; i < iNumMaterials; ++i)
	{
		const aiMaterial*	pAiMaterial = m_pScene->mMaterials[i];

		// ② 쓸 텍스처 모으기
		vector<pair<TEXTURE_TYPE, string>>	Textures;

		for (uint32_t j = 0; j < AI_TEXTURE_TYPE_MAX; ++j)
		{
			aiTextureType	eAiType = static_cast<aiTextureType>(j);
			TEXTURE_TYPE	eType = {};
			if (false == To_TextureType(eAiType, eType))
				continue;

			uint32_t	iNumTextures = pAiMaterial->GetTextureCount(eAiType);
			for (uint32_t k = 0; k < iNumTextures; ++k)
			{
				aiString	strTexturePath = {};
				if (AI_SUCCESS != pAiMaterial->GetTexture(eAiType, k, &strTexturePath))
				{
					cout << "[Write_Materials] " << i << "번 머티리얼 텍스처 경로 읽기 실패\n";
					return false;
				}

				// ③ 파일 이름 + 확장자만 꺼내기
				char	szFileName[MAX_PATH] = {};
				char	szExt[MAX_PATH] = {};
				_splitpath_s(strTexturePath.C_Str(), nullptr, 0, nullptr, 0, szFileName, MAX_PATH, szExt, MAX_PATH);

				Textures.push_back({ eType, string(szFileName) + szExt });
			}
		}

		// ④ 텍스처 개수
		uint32_t	iNumTextures = static_cast<uint32_t>(Textures.size());
		if (1 != fwrite(&iNumTextures, sizeof(uint32_t), 1, m_pFile))
			return false;

		// ⑤ 텍스처마다 종류, 이름 길이, 이름
		for (const auto& Texture : Textures)
		{
			uint32_t	iType = static_cast<uint32_t>(Texture.first);
			uint32_t	iLength = static_cast<uint32_t>(Texture.second.size());

			if (1 != fwrite(&iType, sizeof(uint32_t), 1, m_pFile) ||
				1 != fwrite(&iLength, sizeof(uint32_t), 1, m_pFile) ||
				iLength != fwrite(Texture.second.data(), sizeof(char), iLength, m_pFile))
				return false;

			cout << "[Write_Materials] " << i << "번 : 종류 " << iType << ", " << Texture.second << '\n';
		}
	}
	return true;
}
```

### 6-6. 줄별 설명
**② 모으기**
- 바깥 루프는 `aiTextureType` 0부터 끝까지 돈다. 엔진과 같다.
- `To_TextureType`이 `false`면 `continue`로 그 종류를 통째로 건너뛴다. `GetTextureCount`를 부르기 전에 거른다.
- `pair<TEXTURE_TYPE, string>`: 종류와 파일 이름을 한 쌍으로 든다. 이름은 `string`이라 길이만큼만 메모리를 쓴다.
- 머티리얼(`i`), 종류(`j`), 텍스처(`k`)로 변수 이름을 나눈다.

**③ 파일 이름만 꺼내기**
- FBX 안의 텍스처 경로는 모델러 PC의 절대경로(`D:\Work\...\T_Plants_01_C.png`)인 경우가 많다. 내 PC에는 없으니 이름과 확장자만 남긴다.
- 엔진 `Material.cpp`의 두 번째 `_splitpath_s`와 같은 모양이다. 3장과 반대로 **파일 이름과 확장자 칸만** 받는다.
- `string(szFileName) + szExt`: char 배열 두 개는 `+`로 이을 수 없어서 앞쪽을 `string`으로 만든다.
- `aiString`이 무엇이고 왜 통째로 `fwrite`하지 않는지는 **(1)편 부록 A-1-2**, 파일 안 문자열 규칙은 **A-4-3**.

**④ 개수**
- 모은 뒤라서 정확한 개수를 안다.
- 텍스처가 0개인 머티리얼도 `0`을 쓴다. 그래야 읽는 쪽이 "텍스처 없음"으로 읽고 다음 머티리얼로 넘어간다.

**⑤ 문자열 쓰기 ((1)편 3-2 결정 4: 길이 + 글자)**
- `iLength = size()`: `'\0'`은 세지 않는다. 길이를 따로 저장하니 끝 표시가 필요 없다.
- `Texture.second.data()`: `string`도 `vector`처럼 글자가 따로 있는 곳을 가리킨다. `&Texture.second`를 넘기면 string 객체 자체(포인터, 길이 등)가 써진다((1)편 규칙 ③).
- 읽는 쪽은 길이를 먼저 읽고, 그만큼 `string`을 `resize`해서 `fread`로 채운다.

## 7. 실행 인자 — 경로를 코드에서 빼기

### 7-1. 이번 장에서 할 일
지금 main은 나무 경로가 코드에 박혀 있어서, 모델을 바꾸려면 다시 빌드해야 한다. 경로를 **실행할 때 넘기도록** 바꾼다.
```
ModelConverter.exe  A.fbx  B.fbx  C.fbx
                    └──────┬──────┘
                    argv[1] ~ argv[3]
```

### 7-2. main의 매개변수 `argc`, `argv`

**main은 누가 부르나**
```
① 실행: cmd에서 "ModelConverter.exe A.fbx B.fbx", 또는 F5, 또는 exe 위로 드래그
② Windows가 명령줄 전체를 문자열 한 줄로 저장
③ C 런타임 시작 함수(mainCRTStartup)가 먼저 실행
   - 전역 변수, cout 준비
   - 명령줄을 공백 기준으로 쪼개서 문자열 배열 만들기
   - main(조각 개수, 배열) 호출        ← argc, argv가 채워짐
④ 내 main 실행
⑤ main의 return 값 → 프로세스 종료 코드
```
- 일반 함수는 **내가** 인자를 넣어서 부르지만, main은 **C 런타임이** 명령줄을 쪼개서 넣어 준다.
- 들어올 때는 `argc`/`argv`, 나갈 때는 `return` 값(종료 코드)이다.
- 지금까지의 `int main()`은 "인자를 안 받겠다"는 뜻이었다. Windows는 똑같이 넘기지만 버려졌다.

**메모리 모양** (`ModelConverter.exe A.fbx B.fbx`)
```
argc = 3

argv ──▶ ┌──────────┐
         │ argv[0] ─┼──▶ "ModelConverter.exe\0"    ← exe 자신 (항상)
         ├──────────┤
         │ argv[1] ─┼──▶ "A.fbx\0"
         ├──────────┤
         │ argv[2] ─┼──▶ "B.fbx\0"
         ├──────────┤
         │ argv[3]  │   nullptr  (끝 표시)
         └──────────┘
```
- `argc`(argument count): 조각 개수. **exe 자신도 포함**해서, 아무것도 안 넘기면 1이다.
- `argv`(argument vector): `char*`들의 배열. 각 칸이 실제 글자를 가리킨다. `char* argv[]`와 `char** argv`는 같은 뜻이다.
- 마지막 칸 `argv[argc]`는 항상 `nullptr`이다.

**쪼개는 규칙**
| 입력 | 결과 |
|---|---|
| `exe A.fbx B.fbx` | `argv[1]="A.fbx"`, `argv[2]="B.fbx"` |
| `exe A.fbx    B.fbx` | 위와 같음 (공백 여러 개 = 하나) |
| `exe "My Model.fbx"` | `argv[1]="My Model.fbx"` (따옴표 안 공백은 안 쪼갬, 따옴표는 빠짐) |
| `exe My Model.fbx` | `argv[1]="My"`, `argv[2]="Model.fbx"` ← 실수하기 쉬움 |
| `exe` | `argc=1`, `argv[1]`은 `nullptr` |

**왜 `char*`인가**
- `argv`는 시스템 코드페이지(CP949) `char` 문자열이다.
- assimp `ReadFile`도 `char`를 받고, 3장의 `MultiByteToWideChar(CP_ACP, ...)`와도 코드페이지가 같아서 그대로 이어진다.
- wide 버전 `wmain(int argc, wchar_t* argv[])`도 있지만, assimp에 넘길 때 다시 `char`로 바꿔야 한다. (`char`/wide 함수 짝은 **(1)편 부록 A-3-2**)

### 7-3. 코드: ModelConverter.cpp
```cpp
#include "Converter.h"
using namespace Engine;

static void Print_Usage()
{
	cout << "사용법 : ModelConverter.exe <FBX 경로> [<FBX 경로> ...]\n";
	cout << "  예)   ModelConverter.exe ../../../Resource/Mesh/Tree/Pfb_Tree_01_1.fbx\n";
	cout << "  FBX 파일들을 exe 위로 끌어다 놓아도 됩니다.\n";
}

int main(int argc, char* argv[])
{
	// ① 인자가 없으면 사용법 출력
	if (argc < 2)
	{
		Print_Usage();
		return -1;
	}

	auto pConverter = CConverter::Create();
	if (nullptr == pConverter)
		return -1;

	// ② 넘어온 경로를 하나씩 변환
	uint32_t	iNumFailed = 0;
	for (int i = 1; i < argc; ++i)
	{
		if (false == pConverter->Convert(argv[i], MODEL_TYPE::NONANIM))
			++iNumFailed;
	}

	// ③ 결과 요약
	uint32_t	iNumTotal = static_cast<uint32_t>(argc - 1);
	cout << "\n[Result] 성공 " << (iNumTotal - iNumFailed) << " / 실패 " << iNumFailed << '\n';

	return 0 == iNumFailed ? 0 : -1;
}
```

### 7-4. 줄별 설명
**① 사용법**
- `argc`가 1이면 exe만 실행된 것이다(그냥 더블클릭).
- 인자 없이 `argv[1]`을 쓰면 `nullptr`을 `string`으로 만들다가 터지니, 먼저 검사한다.

**② 하나씩 변환**
- `i`는 1부터. 0은 exe 자신이다.
- 하나가 실패해도 **멈추지 않고 다음 파일로** 넘어간다.
- `CConverter`는 하나만 만들어서 계속 쓴다. 3장 ⑥에서 매번 `fclose`, `FreeScene`을 하고 `nullptr`로 돌려두니, 다음 Convert가 깨끗한 상태에서 시작한다.
- `argv[i]`(`char*`)는 `const string&` 자리에 넘기면 임시 `string`으로 자동 변환된다.

**③ 종료 코드**
- 하나라도 실패하면 -1. 배치 파일이나 빌드 이벤트에서 부를 때 종료 코드로 실패를 알 수 있다.

**타입은 NONANIM 고정**
- 지금 `Write_Meshes`는 `VERTEX_STATIC`만 쓴다. ANIM을 받으면 헤더는 ANIM인데 내용은 STATIC인 엉터리 파일이 나온다.
- ANIM은 VERSION 2를 구현할 때 옵션으로 추가한다((1)편 4-4 로드맵).

### 8-1. 최종 파일 지도 (`Pfb_Tree_01_1.bin`, 45177바이트)

| `0x0008` | `00 00 00 00` | NONANIM |
| `0x000C` | `01 00 00 00` | 메시 1개 |
| `0x0010` | `00 00 00 00` | MaterialIndex 0 |
| `0x0014` | `38 00 00 00` | Stride 56 |
| `0x0018` | `63 02 00 00` | 정점 611 |
| `0x001C` | `80 49 2D BF ...` | 정점[0] 위치 x = -0.6769 |
| `0x85C4` | `A4 0A 00 00` | 인덱스 2724 |
| `0x85C8` | `02 00 00 00 01 00 00 00 00 00 00 00` | 첫 삼각형 (2, 1, 0) |

### 8-2. 이번 편에서 정한 것
| 결정 | 이유 |
|---|---|
| .bin은 FBX와 같은 폴더, 같은 이름 | FBX 경로만 알면 .bin 위치를 안다 |
| 실패하면 .bin 삭제 | "있으면 완전한 파일, 아니면 없음" |
| 정리는 성공/실패 갈림길 앞에 | 어느 길로 나가든 빠지지 않게 |
| assimp 플래그는 엔진과 완전히 같게 | FBX 직접 읽기와 정점이 같아야 비교 가능 |
| `PreTransformMatrix`는 안 곱함 | 로드할 때 적용 ((1)편 결정 7) |
| VertexStride 기록 | VERSION 올리는 걸 깜빡해도 잡아냄 |
| 텍스처 종류는 엔진 enum으로 | assimp를 빼도 다시 변환 불필요 |
| 경로는 실행 인자로, 사용은 드래그 | 재빌드 없이 아무 FBX나 변환 |

### 8-3. 남은 것
- **`Dump`**: 선언과 빈 함수(`return false`)만 있다. 쓰지 않을 거면 지워도 된다.
- **null 검사**: 5-7 참고. UV/노멀 없는 FBX를 변환할 일이 생기면 넣는다.
- **ANIM 모델 주의**: `Resource/Characters/.../0_CharacterModel_Boss_Wu.bin`처럼 애니메이션 모델을 드래그하면 NONANIM으로 변환된다(뼈 없음, 노드 변환이 정점에 구워짐). VERSION 2 전까지는 ANIM FBX를 변환하지 않거나, 생긴 .bin은 쓰지 않는다.
- **`Model_Format.h` 두 벌**: `Engine/Public`과 `EngineSDK/Inc`가 같은지 엔진 빌드 후 확인한다.
