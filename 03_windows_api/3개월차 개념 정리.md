<details>
    <summary>메시지 루프</summary>

- windows 프로그램은 **이벤트 기반**으로 동작
- 사용자가 키 입력('A' 입력) -> windows가 메시지 생성(WM_KEYDOWN) -> 메시지 큐에 넣음

> GetMessage

- 메시지 큐에서 하나 꺼냄`GetMessage(&msg,nullptr,0,0)`
- 꺼낸 결과를 `MSG msg에 저장`
```cpp
WM_KEYDOWN
WM_MOUSEMOVE
WM_PAINT
```

> MSG 구조체
```cpp
struct MSG
{
    HWND hwnd;
    UNIT message;
    WPARAM wParam;
    LPARAM lParam;
};
```
- 시작시 `msg.message = WM_NULL;` 넣어서 쓰레기값이 들어가는 것을 방지
- 만약 'A'키 입력시
```cpp
message = WM_KEYDOWN
wParam = 'A'
```
> TranslateMessage

- 키보드 입력 메시지를 문자 메시지로 변환
```cpp
TranslateMessage(&msg);
```
- WM_KEYDEOWN -> WM_CHAR로 변환
- 보통 항상 넣음

> DispatchMessage


```cpp
DispatchMessage(&msg);
```
- **메시지를 실제 처리 함수(WndProc)로 보내라**를 수행함
- 내부적으로 아래와 같은 느낌으로 WndProc를 호출
```
WndProc(
    msg.hwnd,
    msg.message,
    msg.wParam,
    msg.lParam
);
```

<details>
    <summary>1. 메인 함수 변경점 </summary>

> while문 조건 수정

- GetMessage()는 메시지 올 때까지 멈춤(blocking)
- 즉, 키 입력 없으면 게임 정지 -> while문의 조건에 적합하지 않음
- PeekMessage()는 입력 없어도 계속 Update/Render 가능 -> PeekMessage 사용
- GetMessage(&msg, nullptr, 0, 0) -> PeekMessage(&msg, nullptr, 0, 0, PM_REMOVE) 
- PeekMessage를 통해 종료 메세지가 발생할 때 whlile문을 벗어남

- PeekMessage : 메세지 큐에 메세지가 없는 경우 거짓을 반환
- PM_REMOVE   : 메세지 큐에 메세지가 있을 경우, 가지고 오면서 큐로부터 메세지를 삭제
- PM_NOREMOVE : 메세지 큐에 메세지 유무 상태만 파악, 만약 큐에 있는 메세지를 가져오려면 개별적으로 GetMessage 함수를 다시 호출해야 함

> while문 몸체

- while(true)로 조건 수정하고 while문에서 if(PeekMessage(*msg, nullptr, 0, 0, PM_REMOVE)) else 사용
```cpp
DWORD   dwTime = GetTickCount();    
if(PeekMessage(*msg, nullptr, 0, 0, PM_REMOVE))
{
    // 키보드 입력이 있는 경우 실행할 코드 -> 입력 처리
    if(msg.message == WM_QUIT)
        break;
    if(!TranslateAccelerator(msg.hwnd, hAccelTable, &msg))
    {
        TranslateMessage(&msg);
        DispatchMessage(&msg);
    }
}
else
{
    // 키보드 입력이 없는 경우 실행할 코드 
    if (dwTime + 10 < GetTickCount())              // 너무 빠르게 화면이 렌더링되면 안되니까 GetTickCount()로 조정
    {    
        MainGame.Update();                         // 계산이나 이동
        MainGame.Render();                         // 그리기
        dwTime = GetTickCount();
    }
}
```

<details>
    <summary>3. CMainGame 추가</summary>

> 중요 변경점

- 기존 TextRPG와 달리 화면이 생겨서 Initialize(),Update(),Release() 함수 외에 Render() 함수가 추가됨
- Render() 함수는 객체를 그리는 함수이고 각 객체의 Render(HDC hDC) 함수를 호출하는 부분
- 객체를 그릴 때는 DC가 필요하기 때문에 DC핸들을 매개변수로 받아야 함.
- 이때 이 매개변수는 전역변수인 g_hWnd핸들로부터 GetDC를 통해 뽑아옴

> Initialize()

- 기존 TextRPG와 동일하게 멤버 변수(포인터)에 동적할당된 주소를 넣어주거나 Set함수를 사용해서 다를 객체를 각 클래스에 넣어줌(Bullet)
- 동적할당을 완료했다면 기존과 동일하게 각 객체의 Initialize()함수를 호출
```cpp
void CMainGame::Initialize()
{
	if (!m_pPlayer)
	{
		m_pPlayer = new CPlayer;
		m_pPlayer->Initialize();
	}
	dynamic_cast<CPlayer*> (m_pPlayer)->SetBullet(&m_BulletList);
	if (!m_pMonster)
	{
		m_pMonster = new CMonster;
		m_pMonster->Initialize();
	}
}
```

> Update()

- 각 객체멤버의 Update() 함수를 호출하거나 매 프레임마다 작동해야 할 코드를 작성.
- Bullet리스트의 경우 반복문을 사용해 각 요소의 Update를 호출.
```cpp
void CMainGame::Update()
{
	m_pPlayer->Update();
	m_pMonster->Update();
	for (auto iter = m_BulletList.begin(); iter != m_BulletList.end();)
	{
		(*iter)->Update();
		if (dynamic_cast<CBullet*> (*iter)->CheckCollison())
		{
			SafeDelete(*iter);
			iter = m_BulletList.erase(iter);
		}
		else
		{
			++iter;
		}
	}
}
```

> Render()

- 각 객체를 그리는 함수를 모아놓는 곳
- 객체가 이동할 때 이전 위치의 객체를 지우는 방식이 아닌 이전 위치의 객체는 배경으로 덮어서 지워지는 것처럼 보이게 함
- 따라서 가장 큰 배경을 제일 먼저 그리고 객체를 그리는 방식을 사용
- 객체의 Render(HDC hDC) 함수를 호출하고 이때 hDC는 CMainGame이 GetDC(g_HWnd)를 통해 뽑아온 m_hDC를 넣어주게 됨
- Bullet리스트의 경우 반복문을 사용해 각 요소의 Render를 호출
```cpp
void CMainGame::Render()
{
	Rectangle(m_hDC, 0, 0, WINCX, WINCY);

	Rectangle(m_hDC, 50, 50, WINCX-50, WINCY-50);

	m_pPlayer->Render(m_hDC);
	m_pMonster->Render(m_hDC);
	for (auto& pBullet : m_BulletList)
		pBullet->Render(m_hDC);
}
```

> Release()

- TextRPG와 동일하게 동적할당한 메모리를 반환하는 함수를 모아놓는 함수
```cpp
void CMainGame::Release()
{
	ReleaseDC(g_hWnd, m_hDC);
	SafeDelete(m_pPlayer);
	SafeDelete(m_pMonster);
	for (auto ptr : m_BulletList)
		SafeDelete(ptr);
	m_BulletList.clear();
}
```

	<summary>4. CObj</summary>

> 주요 변경점

- TextRPG와는 다르게 Initialize(), Update(), Render(HDC hDC), Release()를 만들고 virtual 키워드와 PURE매크로를 사용하여 순수 가상함수로 만듬
- 모든 객체는 위치와 크기를 갖기 때문에 INFO 구조체를 Define.h에 생성하여 x좌표(fX), y좌표(fY), 가로 크기(fCX), 세로크기(fCY)를 생성하고 멤버로 선언.
- RECT자료형 m_tRect를 멤버로 생성하여 UpdateRect()및 Render(HDC hDC)에서 그릴 수 있도록 함.
- m_fSpeed 를 선언하여 객체의 속도를 설정할 수 있도록 함
- SetPos(float fX, float fY) 함수를 선언하여 m_tInfo.fX, m_tInfo.fY를 초기화함.

> CObj.h
```cpp
#pragma once
#include "Define.h"
class CObj
{
public:
	CObj();
	virtual ~CObj();

public:
	void SetPos(float fX, float fY)
	{
		m_tInfo.fX = fX;
		m_tInfo.fY = fY;
	}
	INFO GetInfo()
	{
		return m_tInfo;
	}

public:
	virtual void Initialize()	PURE;
	virtual void Update()		PURE;
	virtual void Render(HDC hDC)PURE; // 그리기를 할 때는 dc가 필요하다 dc는 메인함수에 있기 때문에 매개변수로 입력받아서 사용
	virtual void Release()		PURE;

public:
	void		UpdateRect();

protected:
	INFO		m_tInfo;
	RECT		m_tRect;

	float		m_fSpeed;
};
```

> CObj.cpp
```cpp
#include "pch.h"
#include "CObj.h"

CObj::CObj():m_fSpeed(0)
{
	ZeroMemory(&m_tInfo, sizeof(INFO));
	ZeroMemory(&m_tRect, sizeof(RECT));
}

CObj::~CObj()
{
}

// UpdateRect() 함수에서는 나중에 m_tInfo의 x,y 좌표만을 사용해서
// 객체의 left,top,right,bottom의 위치를 자동으로 계산할 수 있도록 함
// m_tRect의 자료형이 RECT이고 각 멤버는 LONG타입이지만 나중에 DX배울 때를 대비하여 m_tInfo의 x,y 좌표는 float로 선언
void CObj::UpdateRect() 
{
	m_tRect.left	= LONG(m_tInfo.fX - (m_tInfo.fCX / 2.f));
	m_tRect.top		= LONG(m_tInfo.fY - (m_tInfo.fCY / 2.f));
	m_tRect.right	= LONG(m_tInfo.fX + (m_tInfo.fCX / 2.f));
	m_tRect.bottom	= LONG(m_tInfo.fY + (m_tInfo.fCY / 2.f));
}
```

	<summary>5. CPlayer</summary>

> 주요 변경점

- Initialize() 			: 생성시 위치와 크기 설정 (m_tInfo값 설정).
- Update()				: 키보드 입력 + UpdateRect() 호출하여 left, top, right, bottom값 계산

- Release()				: 부모 객체인 CObj에서 순수가상함수로 생성해서 만들었지만 반환할 메모리는 없음.
- 멤버변수 m_BulletList	: 총알은 CMainGame 소유이지만 발사는 플레이어가 하기 때문에 리스트에 총알 추가는 플레이어가 해야함
- SetBullet()			: CMainGame 소유의 총알 리스트를 참조하기 위한 Setter
- KeyInput()			: 키보드 입력으로 이동 + 총알 발사를 구현하기 위한 함수. Update()에 넣어서 CMainGame 클래스의 Update()에서 호출될 예정
- CreateBullet()		: 기본 방향으로 발사하기 위해 만든 default 총알 추가 함수. 반환값을 CObj*로 설정하여 리스트의 push_back()의 매개변수에 넣음
- CreateBullet(char)	: 기본 방향이 아닌 다른 방향으로 발사하기 위한 총알 추가 함수. 입력한 키보드를 매개변수로 받아서 Bullet 클래스의 두 번째 생성자를 호출
- m_BulletListP			: 포인터로 만들어서 MainGame 소유의 총알 리스트를 참조하게 됨. m_BulletListP -> push_back(CreateBullet()) 처럼 -> 를 사용해서 함수 호출

> CPlayer.cpp
```cpp
#include "pch.h"
#include "CPlayer.h"

CPlayer::CPlayer():m_BulletList(nullptr)
{
}

CPlayer::~CPlayer()
{
	Release();
}

void CPlayer::Initialize()
{
	m_tInfo = { float(WINCX >> 1),float(WINCY >> 1),100.f,100.f };
	m_fSpeed = 10.f;
}

void CPlayer::Update()
{
	KeyInput();

	__super::UpdateRect(); //상속 관계에서 최상위 클래스를 지칭하는 지시자
}

void CPlayer::Render(HDC hDC)
{
	Rectangle(hDC,
		m_tRect.left,
		m_tRect.top,
		m_tRect.right,
		m_tRect.bottom);
}

void CPlayer::Release()
{
}

void CPlayer::KeyInput()
{
	if (GetAsyncKeyState(VK_RIGHT) & 0x8000)
		m_tInfo.fX += m_fSpeed;
	if (GetAsyncKeyState(VK_LEFT) & 0x8000)
		m_tInfo.fX -= m_fSpeed;
	if (GetAsyncKeyState(VK_UP) & 0x8000)
		m_tInfo.fY -= m_fSpeed;
	if (GetAsyncKeyState(VK_DOWN) & 0x8000)
		m_tInfo.fY += m_fSpeed;

	if (GetAsyncKeyState(VK_SPACE) & 0x8000)
	{
		m_BulletList->push_back(CreateBullet());
		m_BulletList->push_back(CreateBullet('A'));
		m_BulletList->push_back(CreateBullet('D'));
	}
	if (GetAsyncKeyState('W') & 0x8000)
		m_BulletList->push_back(CreateBullet());
	if (GetAsyncKeyState('A') & 0x8000)
		m_BulletList->push_back(CreateBullet('A'));
```

### 3일차 (260514) LateUpdate 추가, Update 반환값 추가, CObj 멤버변수 추가, 폰트 출력, 디자인 패턴

<details>
	<summary>LateUpdate 추가</summary>

> 주요 변경점

- 객체간의 충돌을 Update에서 확인하게 되면 다른 객체간의 Update순서를 생각하면서 확인해야 함.
- 프로젝트가 커지면 서로 영향을 주는 요소들이 많아서 복잡해짐
- LateUpdate() 기능을 만들어서 1차 행동정리(Update) -> 최종 행동정리(LastUpdate) 구조 설계
- 순서 의존성을 줄이기 위한 설계

> Update에서 할 일 vs LastUpdate에서 할 일

```cpp
## Update()
- 입력 처리
- 이동
- AI 동작
- 상태 변경

## LateUpdate()
- 충돌 처리
- 카메라 추적
- 객체 삭제
- 정렬 처리
- 후처리
```

> 메인함수 실행 순서
```
MainGame.Upate();
MainGame.LastUpdate();
MainGame.Render();
```
</details>

<details>
	<summary>Update 반환값 추가</summary>

> 주요 변경점

- Update에 반환값을 추가함(bool타입)
- NOEVENT -> 0 , DEAD -> 1
- 각 객체는 LastUpdate()에서 m_bDead의 변수값을 DEAD or NOEVENT로 설정하고 죽었다면 Update의 반환값으로 return함
- MainGame 클래스의 Update에서 각 객체의 Update()함수의 리턴값을 확인하여 객체 삭제 진행

</details>

<details>
	<summary>CObj 멤버변수 추가</summary>

> 주요 변경점

- m_eDir 변수를 추가하여 객체의 이동 방향을 설정
- 이후 Update()함수에서 switch-case문으로 객체의 x,y좌표를 변경
- m_bDead 변수를 추가하여 객체를 삭제해야하는지를 결정함
- m_bDead의 값은 LastUpdate() 함수에서 값을 변경
- 이후 Update() 함수 시작부분에 m_Dead의 값이 true면 1을 반환하고 Update() 함수 종료.
- MainGame클래스의 Update() 함수에서 각 객체의 Update()함수의 반환값이 true면 객체 삭제
</details>

> 반복자 패턴

- 내부 표현 방식은 공개하지 않고 순차적인 접근 방법을 제공
- MainGame에서 오브젝트들을 따로 변수들을 만들지 않고 list<CObj*> 탸입의 배열에 저장해서 한 번에 관리
```cpp
//멤버 변수로 오브젝트 리스트 타입의 배열 생성
list<CObj*> m_ObjList

// 실제 사용 (객체 Update를 한 번에)
// 2중 반복문을 사용하여 배열의 각 객체들을 한 번에 Update함.
for(auto i = 0; i<OBJ_END;i++)
{
	for(auto iter = m_ObjList[i].begin();iter!=m_ObjList.end();)
	{
		int iResult = (*iter)->Update();
		if(iResult)
		{
			Safe_Delete((*iter));
			iter = m_ObjList[i].erase(iter);
		}
		else
		{
			++iter;
		}
	}
}
```
