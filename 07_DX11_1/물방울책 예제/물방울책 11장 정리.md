# DX11 공부 정리(물방울책) - 11장

### Chapter10. 기하 셰이더 - 빌보드

<details>
  <summary> 0. 기하셰이더란 </summary>

- 기하셰이더는 레스터라이저 단계와 버텍스 셰이더 단계 사이에 있는 렌더링 파이프라인 단계이다.
- 버텍스 셰이더는 정점 하나를 입력받고 정점 하나를 반환하지만 기하셰이더에서는 정점 하나를 입력 받고 여러 정점을 내보낼 수 있다.
- 출력이 바로 래스터라이저로 가야하므로 위치는 동차 클립 공간이어야 함. (투영 행렬까지 곱한 결과이어야 함)

</details>

<details>
  <summary> 1. 기하 셰이더의 구조 </summary>

```hlsl
[maxvertexcount(4)]
void GS(point VertexOut gin[1],
        inout TriangleStream<GeoOut> triStream)
{
    GeoOut v;
    // ... v 채우기
    triStream.Append(v);
}
```

> 입력 한정자 `point VertexOut gin[1]`

- 입력 배열의 크기는 프리미티브 종류에 따라 정해진다.

| 한정자 | 정점 수 |
|---|---|
| `point` | 1 | 
| `line` | 2 | 
| `triangle` | 3 |
| `lineadj` | 4 | 
| `triangleadj` | 6 | 

> 출력 스트림 `inout TriangleStream<GeoOut> triStream`

- `PointStream`, `LineStream`, `TriangleStream` 중 하나이고, `Append()`로 정점을 추가할 수 있다.
- 출력은 항상 스트립(띠 형태)로 나감. 리스트 처럼 끊으려면 `RestartStrip()`을 호출해야 함.

> `maxvertexcount`

- 한 번 호출에서 내보낼 최대 정점 수이며 반드시 지정해야 합니다. 성능상 작을수록 좋습니다.

> 입출력 타입

- 입력 정점 타입과 출력 정점 타입은 달라도 된다.
- 입력이 점이고 출력이 삼각형이어도 된다.
  
</details>

<details>
  <summary> 2. 나무 빌보드 예제 - 개요 </summary>

- 멀리있는 나무는 메시 대신 항상 카메라를 향하는 사각형(빌보드)에 텍스처를 입혀 그린다.
- CPU에서는 나무 하나당 점 하나만 보내고, 기하 셰이더가 점을 사각형으로 확장한다.
- 나무가 눕지 않도록 y축은 고정하고 xz 평면에서만 카메라를 향하게 한다.

</details>

<details>
	<summary> 2. 나무 빌보드 예제 - 셰이더 코드 </summary>

- 버텍스 셰이더에서는 들어온 버텍스의 정보를 그대로 기하 셰이더로 보낸다.
- 기하 셰이더에서 는 버텍스 셰이더로부터 전달받은 정보인 중점과 가로,세로 길이를 이용하여 정점 4개를 만든다
- 이때 정점 4개로 이루어진 평면의 법선 벡터는 `중심점 - Camera` 가 되고 Up(0,1,0)과 외적을 이용하여 Right벡터를 얻는다.
- 이렇게 얻은 Up과 Right벡터를 연산하여 정점 4개를 만든다.
- 정점 4개에 각각 뷰, 투영 행렬을 곱한 뒤 스트림에 추가한다.

```hlsl
// 버텍스 셰이더 반환값
struct VS_OUT
{
    float3 CenterW : POSITION;
    float2 SizeW : SIZE;
};

// 기하 셰이더 반환 값
struct GeoOut
{
    float4 PosH : SV_POSITION;
    float3 PosW : POSITION;
    float3 NormalW : NORMAL;
    float2 Tex : TEXCOORD;
    uint PrimID : SV_PrimitiveID;
};


// 버텍스 셰이더
VS_OUT VS_MAIN(VS_IN In)
{
    VS_OUT vout;
    
    vout.CenterW = In.PosW;
    vout.SizeW = In.SizeW;

    return vout;
}

// 픽셀 셰이더
[maxvertexcount(4)]
void GS_MAIN(point VS_OUT gin[1],
        uint primID : SV_PrimitiveID,	// 
        inout TriangleStream<GeoOut> triStream)
{
	// Look, Right 구하기
    float3 up = float3(0.0f, 1.0f, 0.0f);
    float3 look = g_vEye - gin[0].CenterW;
    look.y = 0.0f; // y-axis aligned, so project to xz-plane
    look = normalize(look);
    float3 right = cross(up, look);

	// 너비, 높이 길이와 Up,Right 를 연산하여 정점 4개 구하기
    float halfWidth = 0.5f * gin[0].SizeW.x;
    float halfHeight = 0.5f * gin[0].SizeW.y;
	
    float4 v[4];
    v[0] = float4(gin[0].CenterW + halfWidth * right - halfHeight * up, 1.0f);
    v[1] = float4(gin[0].CenterW + halfWidth * right + halfHeight * up, 1.0f);
    v[2] = float4(gin[0].CenterW - halfWidth * right - halfHeight * up, 1.0f);
    v[3] = float4(gin[0].CenterW - halfWidth * right + halfHeight * up, 1.0f);

	//
	// 뷰, 투영 행렬을 곱한 뒤 스트림에 추가 
	//
    GeoOut gout;
	[unroll]
    for (int i = 0; i < 4; ++i)
    {
        gout.PosH = mul(mul(v[i], g_matView),g_matProj);
        gout.PosW = v[i].xyz;
        gout.NormalW = look;
        gout.Tex = g_TexC[i];
        gout.PrimID = primID;
		
        triStream.Append(gout);
    }
}

```

- `uint primID : SV_PrimitiveID` : primID는 "지금 처리 중인 프리미티브가 이번 드로우 콜에서 몇 번째인가" 를 알려주는 번호.
- `SV_PrimitiveID` 라는 시스템 시맨틱을 붙이면 입력 조립기가 자동으로 채워준다.
- 드로우 콜마다 0부터 시작해서 프리미티브 하나당 1씩 증가한다.

<details>
	<summary> 2. 나무 빌보드 예제 - Tree클래스 </summary>

- Tree클래스에서는 버텍스버퍼로 전달할 버텍스 버퍼와 조명에 사용할 머티리얼을 준비하면 된다.

> 버텍스 버퍼 준비

- 지형의 복제본으로부터 높이를 받아와야 하기 때문에 Initialize() 함수에서 버텍스버퍼를 설정한다.
- `m_iTreeCnt` 변수를 `static const uint32_t`로 선언하여 배열의 크기값으로 전달할 수 있도록 한다.
- 나무의 개수(`m_iTreeCnt`)만큼 버텍스 버퍼의 크기를 설정한다.
- 인덱스 버퍼는 없어도 된다. 기하 셰이더에서 인덱스를 설정하기 때문에.
- IA 단계에서 인덱스 버퍼를 연결할 필요도 없고 그림을 그릴때 `DrawIndexed()`가 아닌 `Draw()`함수를 호출한다.
- 따라서 `Render()`에서 `m_pContext->DrawIndexed(m_iTreeCnt, 0, 0);` 처럼 매개변수로 나무의 개수인 `m_iTreeCnt`를 전달한다.

```cpp
HRESULT CTree::Initialize(void* pArg)
{
    if (FAILED(__super::Initialize(pArg)))
        return E_FAIL;
    TREEPOINTSPRITE v[m_iTreeCnt] = {};
    auto pHill = static_pointer_cast<CHill>(CGameInstance::Get().Find_GameObject(ETOUI(LEVEL::GAMEPLAY), L"Layer_GameObject", TEXT("GameObject_Hill")));
    for (UINT i = 0; i < m_iTreeCnt; ++i)
    {
        float x = f32_t(rand() % 21 - 10.f);
        float z = f32_t(rand() % 21 - 10.f);

        float y = pHill->GetHeight(x, z);

        y += 5.0f;

        v[i].vPos = XMFLOAT3(x, y, z);
        v[i].Size = XMFLOAT2(16.0f, 16.0f);
    }

    D3D11_BUFFER_DESC vbd;
    vbd.Usage = D3D11_USAGE_IMMUTABLE;
    vbd.ByteWidth = sizeof(TREEPOINTSPRITE) * m_iTreeCnt;
    vbd.BindFlags = D3D11_BIND_VERTEX_BUFFER;
    vbd.CPUAccessFlags = 0;
    vbd.MiscFlags = 0;
    D3D11_SUBRESOURCE_DATA vinitData;
    vinitData.pSysMem = v;
    if (FAILED(m_pDevice->CreateBuffer(&vbd, &vinitData, &m_pVB)))
        return E_FAIL;
    return S_OK;
}
```

> Camera::Bind()

- 기존에는 버텍스 버퍼에서 뷰,투영 변환을 했지만 지금은 기하 셰이더에서 하기 때문에 기하셰이더에서도 변환 행렬을 사용할 수 있도록 상수버퍼 바인딩을 해야한다.

```cpp
HRESULT CCamera::Bind()
{
	CB_CAMERA	cbData;
	XMStoreFloat4x4(&cbData.ViewMatrix, XMMatrixTranspose(XMLoadFloat4x4(&m_matView)));
	XMStoreFloat4x4(&cbData.ProjMatrix, XMMatrixTranspose(XMLoadFloat4x4(&m_matProj)));
	cbData.vEye = m_vEye;

	m_pContext->UpdateSubresource(m_pCB.Get(), 0, nullptr, &cbData, 0, 0);
	m_pContext->VSSetConstantBuffers(1, 1, m_pCB.GetAddressOf());
	m_pContext->GSSetConstantBuffers(1, 1, m_pCB.GetAddressOf());
	m_pContext->PSSetConstantBuffers(1, 1, m_pCB.GetAddressOf());
	return S_OK;
}
```
