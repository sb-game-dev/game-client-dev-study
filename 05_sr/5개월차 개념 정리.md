### 1일차 솔루션 구성 순서

<details>
  <summary>솔루션 구성 순서</summary>

> 최종 솔루션 구성

```cpp
- Client
    - Bin
    - Code
    - Header
    - Include
- Engine
    - Bin
    - Code
    - Header
    - Include
- Reference
    - Header
    - Library
- Base
```

> 생성 과정

1. 빈 솔루션 생성
2. 솔루션 → 추가 → 새 솔루션 폴더 → 00. Client | 01. Engine | 02. Base 각각 생성
3. 솔루션의 저장 폴더에 Base | Reference 폴더 각각 생성 → Reference 폴더에서 Header, Library 폴더 생성
4. 00. Client 폴더에서 추가 → 새 프로젝트 → Window 데스크탑 마법사 → 프로젝트 이름은 Client로 → 데스크톱 애플리케이션과 미리 컴파일된 헤더 설정
5. Client 프로젝트를 솔루션에서 제거 → 솔루션의 저장 폴더에서 Client 폴더로 → Client 폴더에 Bin | Code | Header | Include 폴더를 각각 생성
6. Client 폴더에서 기존에 있던 파일들은 Include 폴더로 이동
7. 00. Client 솔루션 폴더에서 추가 → 기존 프로젝트 → Client/Include/.vcxproj 선택
8. Client 프로젝트 경로 설정 (모든 구성으로 설정)
    1. 일반 → 출력 디렉터리 → ../Bin\
    2. VC++ 디렉터리 →
        1. 포함 디렉터리 → $(DXSDK_DIR)Include
        2. 라이브러리 디렉터리 → $(DXSDK_DIR)Lib/x64
    3. C/C++ → 일반 → 추가 포함 디렉터리 → 
        1. ../Header;
        2. ../../Base
        3. ../../Reference/Header
    4. 링커 → 일반 → 추가 라이브러리 디렉터리 → ../../Reference/Library
    5. 링커 → 입력 → 추가 종속성 → 
        1. d3d9.lib
        2. d3dx9.lib
        3. dxguid.lib
        4. dinput8.lib
        5. Engine.lib
9. 01. Engine 폴더에서 추가 → 새 프로젝트 → Window 데스크탑 마법사 → 프로젝트 이름은 Engine으로 → 동적 연결 라이브러리와 빈 프로젝트 설정

11. Engine 폴더에서 기존에 있던 파일들은 Include 폴더로 이동
12. 01. Engine 솔루션 폴더에서 추가 → 기존 프로젝트 → Engine/Include/.vcxproj 선택
13. Engine 프로젝트 경로 설정 (모든 구성으로 설정)
    1. 일반 → 출력 디렉터리 → ../Bin\
    2. VC++ 디렉터리 →
        1. 포함 디렉터리 → $(DXSDK_DIR)Include
        2. 라이브러리 디렉터리 → $(DXSDK_DIR)Lib/x64
    3. 코드가 하나도 없으면 C/C++ 탭이 생기지 않으므로 아무 클래스나 만들기
    4. C/C++ 일반 → 추가 포함 디렉터리 →
        1. ../Header;
        2. ../../Base
    5. 방금 생성한 클래스 삭제
    6. 링커 → 입력 → 추가 종속성 →

        2. d3dx9.lib

    2. Client/Code
    3. Client/Header

        1. pch.h
        2. Client.cpp
    5. Engine/Code
    6. Engine/Header

<details>
  <summary>스왑 체인 기법</summary>

> 스왑 체인 기법

Swap Chain은 **화면이 깜빡이는(Flickering) 현상을 방지하기 위해 사용하는 렌더링 방식**이다.

하나의 버퍼에 바로 화면을 그리면 사용자가 그리는 과정을 그대로 보게 되므로 화면이 깜빡이거나 깨져 보일 수 있다.

이를 해결하기 위해 **Front Buffer(전면 버퍼)** 와 **Back Buffer(후면 버퍼)** 를 사용한다.

* **Front Buffer** : 현재 사용자가 보고 있는 화면
* **Back Buffer** : GPU가 다음 프레임을 그리는 작업 공간

---

> 동작 과정

- 1.Back Buffer 초기화

새로운 프레임을 그리기 위해 Back Buffer를 초기화한다.

```cpp
Clear();
```

Color Buffer, Depth Buffer, Stencil Buffer를 모두 초기 상태로 만든다.


- 2.Back Buffer에 렌더링

GPU는 사용자가 보지 않는 Back Buffer에 모든 객체를 그린다.

```text
배경
 ↓
지형
 ↓
플레이어
 ↓
몬스터
 ↓
UI
```

이 과정에서 사용자는 아직 아무것도 볼 수 없다.


- 3.렌더링 종료

```cpp
EndScene();
```

이번 프레임의 모든 Draw 명령이 끝났음을 GPU에 알린다.

이 시점에서도 아직 화면은 변경되지 않는다.

---

- 4.Present()

```cpp
Present();
```

완성된 Back Buffer를 화면에 출력한다.

이때 **버퍼의 내용을 복사하는 것이 아니라 Front Buffer와 Back Buffer의 역할을 교체(Swap)** 한다.

---

> 버퍼 역할 변화

초기 상태

```text
Front(사용자 화면) → Buffer A 

Back(GPU가 렌더링) → Buffer B 
```

`Present()` 호출 후

```text
Front(사용자 화면)  → Buffer B 

Back(GPU가 렌더링)  → Buffer A 
```

다음 프레임에서는 다시 Buffer A를 `Clear()`한 후 새로운 화면을 그리고, `Present()`를 호출하면 역할이 다시 교체된다.

즉, **두 버퍼는 모두 동일한 화면 버퍼이며, 매 프레임마다 Front와 Back의 역할만 번갈아 수행한다.**


> 사용하는 이유

만약 Front Buffer에 직접 렌더링하면 사용자는 그리는 과정을 그대로 보게 된다.

```text
배경
 ↓
플레이어
 ↓
몬스터
 ↓
UI
```

이 과정이 화면에 그대로 나타나면서 **Flickering(깜빡임)** 이 발생한다.

Back Buffer에서 모든 렌더링을 완료한 후 한 번에 화면을 교체하면 사용자는 완성된 프레임만 보게 되므로 부드러운 화면을 출력할 수 있다.

---

> 핵심 정리

* Front Buffer는 현재 화면에 출력되는 버퍼이다.
* Back Buffer는 다음 프레임을 렌더링하는 버퍼이다.
* GPU는 Back Buffer에 모든 객체를 그린다.
* `EndScene()`은 렌더링 명령의 종료를 알린다.
* `Present()`는 Front Buffer와 Back Buffer의 **역할을 교체(Swap)** 하여 완성된 화면을 출력한다.
* 두 버퍼는 매 프레임마다 Front와 Back 역할을 번갈아 수행하며 재사용된다.
* 이를 통해 Flickering 없이 부드러운 화면을 출력할 수 있다.

</details>

### 3일차 TimerMgr, FrameMgr, Managment 클래스

<details>
	<summary>TimerMgr / FrameMgr</summary>

> Timer

- Update간격을 측정하는 m_fTimeDelta를 저장하는 용도로 사용함
- 컴퓨터 성능에 따라 프로그램 Update 간격이 다를 수 있고 이를 해결하기 위해 이동 거리나 회전각도에 m_fTimeDelat를 곱해주기 위해 사용

> TimerMgr

- 여러 타이머들을 map컨테이너에 저장하여 관리함
- Get_TimeDelta(const _tchar* pTimerTag) 	: 타이머클래스를 가져옴
- Set_TimeDelta(const _tchar* pTimerTag) 	: 타이머클래스의 타이머 간격(m_fTimeDelat)을 측정함
- Ready_Timer(const _tchar* pTimerTag) 		: 타이머클래스를를 생성하고 map컨테이너에 추가함

> Frame

- IsPermit_Call() 함수를 사용하는 것이 주요 목적.  
- m_fAccTimeDelta	: Timer의 m_fTimeDelta값만큼 누적 시킬 값.
- m_fCallLimit		: m_fAccTimeDelta값의 최대값.

- Ready_Frame(const _float& fCallLimit) 	: m_fCallLimit을 초기화.
- IsPermit_Call(const _float& fTimeDelta) 	: m_fAccTimeDelta를 Timer의 m_fTimeDelta값만큼 증가시키고 m_fCallLimit을 넘어가면 return true;

> FrameMgr

- Fame클래스를 생성하고 관리하는 역할
- Ready_Frame(const _tchar* pFrameTag, const _float& fCallLimit)	: 프레임을 생성하고 map컨테이너에 추가함
- IsPermit_Call(const _tchar* pFrameTag, const _float& fTimeDelta)	: 프레임의 IsPermit_Call()함수를 호출하고 프레임의 IsPermit_Call()함수의 반환값을 그대로 반환함

> 사용 예시

```cpp
게임 루프 시작
        │
        ▼
Timer_Immediate TimeDelta 측정
        │
        ▼
Frame에 TimeDelta 누적
        │
        ▼
60FPS 시간이 되었는가?
        │
 ┌──────┴──────┐
 │             │
아니오        예
 │             │
 │             ▼
 │      fTimer_FPS60 측정
 │             │
 │             ▼
 │      Update(fTimer_FPS60)
 │             │
 │             ▼
 │       LateUpdate()
 │             │
 │             ▼
 │          Render()
 │
 └──────────────→ 다음 루프
```

{
    if (PeekMessage(&msg, nullptr, 0, 0, PM_REMOVE))

        if (!TranslateAccelerator(msg.hwnd, hAccelTable, &msg))

    else
    {
        CTimerMgr::GetInstance()->Set_TimeDelta(L"Timer_Immediate");
        _float fTimer_Immediate = CTimerMgr::GetInstance()->Get_TimeDelta(L"Timer_Immediate");

        if (CFrameMgr::GetInstance()->IsPermit_Call(L"Frame60", fTimer_Immediate))
        {
            CTimerMgr::GetInstance()->Set_TimeDelta(L"Timer_FPS60");
            _float fTimer_FPS60 = CTimerMgr::GetInstance()->Get_TimeDelta(L"Timer_FPS60");

            pMainApp->Update_MaintApp(fTimer_FPS60);
            pMainApp->LateUpdate_MainApp(fTimer_FPS60);
            pMainApp->Render_MainApp();
        }
    }      
}
