# 1110_Anim1 총정리 — 애니메이션 모델 준비 (뼈 데이터 / 스키닝 데이터)

> 1109_ModelTex → 1110_Anim1 비교. 변경은 **Engine에만** 있고 Client는 그대로다.

| 구분 | 파일 |
|---|---|
| 신규 | `Bone.h`, `Bone.cpp` |
| 수정 | `Engine_Enum.h`, `Engine_Struct.h`, `Model.h/.cpp`, `Mesh.h/.cpp`, `Engine.vcxproj(.filters)` |

이번 수업은 애니메이션을 **재생**하는 단계가 아니라, 재생에 필요한 **데이터를 준비**하는 단계다.
- 모델을 정적 / 애니메이션 두 종류로 나눠서 불러온다.
- 뼈 계층 구조를 읽어서 저장한다.
- 정점마다 어떤 뼈의 영향을 받는지 기록한다.

---

## 1. 배경 개념

### 1-1. 스키닝
정적 모델은 정점이 변하지 않는다. 그래서 노드 행렬을 로드할 때 정점에 미리 곱해 굽는 방식(`aiProcess_PreTransformVertices`)으로 충분하다.

애니메이션 모델은 이렇게 움직인다.
1. 모델 안에 **뼈(행렬)** 를 둔다.
2. 정점마다 "몇 번 뼈의 영향을 몇 % 받는다"를 적어 둔다.
3. 매 프레임 **뼈 행렬만** 갱신해서 GPU로 보낸다.
4. 정점 셰이더가 정점마다 최대 4개 뼈 행렬을 가중치로 섞어서 곱한다.

```
최종 위치 = Σ (뼈 행렬[k] × 위치) × 가중치[k]     (k = 최대 4개)
```

### 1-2. 뼈는 계층 구조
어깨가 돌면 팔과 손도 따라와야 한다. 그래서 각 뼈는 **부모 기준 로컬 행렬**만 가지고, 최종 행렬은 누적해서 구한다.
```
Combined = 내 로컬 행렬 × 부모의 Combined
```

## 2. Assimp 데이터 구조와 역할 구분

```
aiScene
 ├ mRootNode : aiNode*            ← 노드 트리 = 뼈대
 │    ├ mName, mTransformation(로컬 행렬)
 │    └ mChildren
 ├ mMeshes[i] : aiMesh*
 │    ├ mVertices, mNormals ...   ← 정점 정보 (수천~수만 개)
 │    └ mBones[j] : aiBone*       ← 이 메시를 뼈대에 붙이는 연결 정보
 │          ├ mName                    (노드 이름과 같음)
 │          ├ mNumWeights / mWeights[k] = { mVertexId, mWeight }
 │          └ mOffsetMatrix
 └ mAnimations[]                  ← (다음 수업)
```

**두 구조는 역할이 다르다**
| | 들어 있는 것 | 역할 |
|---|---|---|
| **aiNode** | 로컬 행렬, 부모-자식 관계 | **움직이는 뼈대.** 애니메이션이 이 행렬을 바꿈 |
| **aiBone** | 이름, (정점 번호, 가중치) 목록, OffsetMatrix | **연결 정보.** "이 메시의 어떤 정점이 어떤 노드를 얼마나 따라가는가" |

Assimp의 `aiBone`은 이름과 달리 계층을 가진 뼈가 아니라 **스킨 연결 정보**다. 실제로 움직이는 행렬은 노드에서 나온다.

**엔진 클래스와의 관계**
- **aiNode → CBone** : 1:1 변환. `CBone`은 이름은 Bone이지만 사실상 **노드**다(Root, 메시 노드, 더미 노드까지 전부 포함).
- **aiBone →(이름)→ CBone** : 같은 타입도, 같은 데이터도 아니다. 이름으로 **찾아가는** 관계이고, 여러 메시의 aiBone이 같은 CBone 하나를 가리킬 수 있다(N:1).
- **aiBone의 내용은 CBone에 저장되지 않는다.** 로드할 때 쪼개져서 CMesh와 정점 버퍼로 옮겨진다.

| aiBone 정보 | 옮겨지는 곳 |
|---|---|
| `mName` → 찾은 CBone 번호 | `CMesh::m_BoneIndices` |
| `mWeights` | 정점의 `vBlendIndex` / `vBlendWeight` |
| `mOffsetMatrix` | (다음 수업) CMesh 쪽 |

**비유 — 마리오네트 인형**
- CBone = 나무 뼈대 (실을 당기면 움직임)
- 메시 = 뼈대 위에 씌운 천
- aiBone = 천을 뼈대에 꿰매는 **바느질 설명서**. 꿰맬 때(로드할 때)만 쓰고 끝
- 정점 BlendIndex/Weight = 실제로 꿰맨 바늘땀
- m_BoneIndices = 천 안쪽의 라벨 ("이 천의 2번 = 뼈대의 5번")

## 3. 수업 진행 순서대로 코드 따라가기

### STEP 1. 모델 타입 열거형
`Engine_Enum.h`
```cpp

```
모델을 만들 때 종류를 지정한다. 이 값에 따라 세 가지가 달라진다.

### STEP 2. `CModel::Create`에 타입 전달
`Model.h`
```cpp
static shared_ptr<CModel> Create(ComPtr<ID3D11Device> pDevice, ComPtr<ID3D11DeviceContext> pContext,
                                 MODEL eType, const char_t* pModelFilePath,
                                 fmatrix_t PreTransformMatrix = XMMatrixIdentity());
MODEL m_eType = { MODEL::END };
```
받은 타입을 `m_eType`에 저장해 두고, 메시를 만들 때 다시 넘긴다.

### STEP 3. 타입에 따라 Assimp 옵션 분기 ★
`Model.cpp` — `Initialize_Prototype`
```cpp
m_eType = eType;

uint32_t iFlag = { aiProcess_ConvertToLeftHanded | aiProcessPreset_TargetRealtime_Fast };

if (MODEL::NONANIM == m_eType)
    iFlag |= aiProcess_PreTransformVertices;
```
- `ConvertToLeftHanded` : FBX(오른손 좌표계) → DX(왼손 좌표계)
- `TargetRealtime_Fast` : 삼각형 분할, 탄젠트 계산 등 실시간용 기본 처리
- `PreTransformVertices`는 노드 행렬을 정점에 굽고 **노드 트리를 없애는** 옵션이다. 애니메이션 모델에 쓰면 뼈대가 사라지므로 정적 모델에만 붙인다.

### STEP 4. `CBone` 클래스
`Bone.h`
```cpp
class CBone final
{
private:
    CBone();
public:
    virtual ~CBone() = default;

public:
    HRESULT Initialize(const aiNode* pAINode, int32_t iParentBoneIndex);
    bool_t Compare_Name(const char_t* pBoneName) const {
        return !strcmp(pBoneName, m_szName);
    }

private:
    char_t      m_szName[MAX_PATH] = {""};       // aiBone과 연결할 이름 키
    float4x4_t  m_TransformationMatrix = {};      // 부모 기준 로컬 행렬 (애니메이션이 덮어씀)
    float4x4_t  m_CombinedTransformationMatrix = {}; // 로컬 × 부모 Combined (다음 수업에서 계산)
    int32_t     m_iParentIndex = { -1 };          // 부모가 m_Bones의 몇 번째인지

public:
    static shared_ptr<CBone> Create(const aiNode* pAINode, int32_t iParentBoneIndex);
};
```
- GPU 자원이 아니라 행렬 데이터라서 컴포넌트를 상속하지 않고, Device도 받지 않는다.
- **부모를 인덱스로 저장하는 이유:** 순환 참조가 없고, 모델을 Clone해서 배열을 복사해도 인덱스는 그대로 유효하다.

`Bone.cpp`
```cpp
strcpy_s(m_szName, pAINode->mName.C_Str());
m_iParentIndex = iParentBoneIndex;
memcpy(&m_TransformationMatrix, &pAINode->mTransformation, sizeof(float4x4_t));
XMStoreFloat4x4(&m_TransformationMatrix, XMMatrixTranspose(XMLoadFloat4x4(&m_TransformationMatrix)));
XMStoreFloat4x4(&m_CombinedTransformationMatrix, XMMatrixIdentity());
```
- **Transpose하는 이유:** Assimp 행렬은 열 벡터 기준(이동값이 4열), DirectXMath는 행 벡터 기준(이동값이 4행)이다. 전치해서 맞춘다.
- Combined는 아직 계산하지 않으므로 항등행렬로 둔다.

### STEP 5. `Ready_Bones` — 노드 트리를 재귀로 돌며 뼈 목록 만들기
`Model.cpp`
```cpp
HRESULT CModel::Ready_Bones(const aiNode* pAINode, int32_t iPIndex)
{
    auto pBone = CBone::Create(pAINode, iPIndex);   // ① 현재 노드로 뼈 생성
    if (nullptr == pBone)
        return E_FAIL;

    m_Bones.push_back(pBone);                       // ② 목록 끝에 추가

    int32_t iParentIndex = { m_Bones.size() - 1 };  // ③ 방금 추가한 뼈의 인덱스

    for (uint32_t i = 0; i < pAINode->mNumChildren; ++i)
        Ready_Bones(pAINode->mChildren[i], iParentIndex);   // ④ 자식에게 "네 부모는 나"

    return S_OK;
}
```
`Ready_Bones(mRootNode, -1)`로 시작한다. 깊이 우선으로 추가하므로 **부모가 항상 자식보다 앞 번호**다. 그래서 나중에 Combined를 계산할 때 0번부터 한 번만 돌면 된다.

### STEP 6. 애니메이션용 정점 구조체 `VTXANIMMESH`
`Engine_Struct.h`
```cpp
XMFLOAT3 vPosition, vNormal, vTangent, vBinormal;   // 0, 12, 24, 36
XMFLOAT2 vTexcoord;                                 // 48
XMUINT4  vBlendIndex;                               // 56 → 영향을 주는 뼈 번호 최대 4개
XMFLOAT4 vBlendWeight;                              // 72 → 각 뼈의 영향 비율 (총 88바이트)

{"BLENDINDEX",  0, DXGI_FORMAT_R32G32B32A32_UINT,  0, 56, D3D11_INPUT_PER_VERTEX_DATA, 0},
{"BLENDWEIGHT", 0, DXGI_FORMAT_R32G32B32A32_FLOAT, 0, 72, D3D11_INPUT_PER_VERTEX_DATA, 0},
```
- `BLENDINDEX`는 정수 인덱스라서 `UINT` 포맷이다(FLOAT면 셰이더에서 배열 인덱스로 바로 못 씀).
- 시맨틱 이름은 나중에 만들 애니메이션 정점 셰이더의 입력과 같아야 한다.

#### [보충] 정점당 4개 제한
- 4개는 DirectX나 FBX의 제한이 아니라 **정점 구조체를 4칸으로 정한 결과**다. `uint4`/`float4` 한 칸에 맞고, 품질과 성능의 균형이 좋아서 게임 업계 표준이다.
- 원본 데이터(Maya, Blender)에는 정점당 5개 이상이 있을 수 있다. 그대로 읽으면 5번째 뼈부터 `else`로 가서 w칸을 덮어쓴다.
- **해결 A — `aiProcess_LimitBoneWeights`** : 가중치가 큰 4개만 남기고 정규화한다. 지금 쓰는 `TargetRealtime_Fast` 프리셋에는 이 옵션이 없다(`_Quality`, `_MaxQuality`에는 있음). ANIM일 때 따로 붙여야 한다. 개수는 `AI_CONFIG_PP_LBW_MAX_WEIGHTS`로 바꿀 수 있다.
- **해결 B — 8칸으로 늘리기** : SemanticIndex 0/1로 `BLENDINDEX0`, `BLENDINDEX1`을 둔다. 정점 크기(88B → 120B)와 연산이 늘어난다.
- 참고: Unity는 정점당 1/2/4개 또는 무제한, Unreal은 4개에서 8개, 12개 이상까지 설정 가능하다.

### STEP 8. `Ready_Meshes_For_Anim` 작성 ★
**정점 복사 — 행렬 변환 없음**
```cpp
m_iVertexStride = sizeof VTXANIMMESH;
shared_ptr<VTXANIMMESH[]> pVertices = make_shared<VTXANIMMESH[]>(m_iNumVertices);  // 0으로 초기화

for (uint32_t i = 0; i < m_iNumVertices; i++)
{
    memcpy(&pVertices[i].vPosition, &pAIMesh->mVertices[i],         sizeof float3_t);
    memcpy(&pVertices[i].vNormal,   &pAIMesh->mNormals[i],          sizeof float3_t);
    memcpy(&pVertices[i].vTangent,  &pAIMesh->mTangents[i],         sizeof float3_t);
    memcpy(&pVertices[i].vBinormal, &pAIMesh->mBitangents[i],       sizeof float3_t);
    memcpy(&pVertices[i].vTexcoord, &pAIMesh->mTextureCoords[0][i], sizeof float2_t);
}
```
- 정점은 **바인드 포즈(T자세) 그대로** 둔다. 매 프레임 뼈 행렬로 변환할 것이라 미리 곱하면 이중으로 곱해진다. 그래서 `PreTransformMatrix`를 받지 않는다.
- `make_shared<T[]>`가 0으로 초기화하므로 BlendIndex와 Weight가 0에서 시작한다. 아래 "빈 칸 찾기"가 이 점을 이용한다.

**메시의 뼈를 순회**
```cpp
m_iNumBones = pAIMesh->mNumBones;
for (uint32_t i = 0; i < m_iNumBones; i++)
```
여기서 문제가 생긴다. `aiBone`에는 **이름만** 있어서, 이 뼈가 `m_Bones`의 몇 번인지 알 수 없다.

### STEP 9. `CModel::Get_BoneIndex` — 이름으로 CBone 번호 찾기
`Model.cpp`
```cpp
int32_t CModel::Get_BoneIndex(const char_t* pBoneName)
{
    int32_t iBoneIndex = {};

    auto iter = find_if(m_Bones.begin(), m_Bones.end(), [&](CBone* pBone)->bool_t
    {
        if (true == pBone->Compare_Name(pBoneName))
            return true;

        ++iBoneIndex;
        return false;
    });

    if (iter == m_Bones.end())
        return -1;

    return iBoneIndex;
}
```
메시가 이 함수를 부르려면 모델 객체가 필요하다. 그래서 `CMesh::Create` → `Initialize_Prototype` → `Ready_Meshes_For_Anim`에 **`shared_ptr<CModel> pModel` 매개변수**가 추가되고, `Mesh.cpp`에 `#include "Model.h"`가 들어간다.

#### 9-1. 람다식이란
**이름 없는 함수를 그 자리에서 만들어 쓰는 문법**이다. `find_if`처럼 함수를 인자로 받는 함수에 넘길 때 주로 쓴다. 따로 함수를 선언하지 않아도 되고, 주변 지역 변수를 가져다 쓸 수 있다.

```cpp
[&]  (CBone* pBone)  ->bool_t  { ... }
 ①        ②             ③       ④
```
| 부분 | 이름 | 이 코드에서 |
|---|---|---|
| ① `[&]` | **캡처** | 바깥 지역 변수를 **참조로** 가져다 쓴다 |
| ② `(CBone* pBone)` | 매개변수 | `find_if`가 넘겨 주는 원소 하나 |
| ③ `->bool_t` | 반환 타입 | true/false (생략하면 컴파일러가 추론) |
| ④ `{ ... }` | 본문 | 실제 할 일 |

#### 9-2. 캡처 `[&]` — 이 코드의 핵심
람다 본문은 원래 자기 매개변수만 볼 수 있다. 바깥 변수를 쓰려면 캡처해야 한다. 본문에서 쓰는 바깥 변수는 두 개다.
- `pBoneName` : 찾을 이름 (`Get_BoneIndex`의 매개변수)
- `iBoneIndex` : 몇 번째인지 세는 변수 (`Get_BoneIndex`의 지역 변수)

| 캡처 방식 | 의미 | 이 코드에서 쓰면 |
|---|---|---|
| `[&]` | 모든 바깥 변수를 **참조**로 | `++iBoneIndex`가 **바깥 변수를 실제로 증가** ✔ |
| `[=]` | 모든 바깥 변수를 **값 복사**로 | 복사본은 수정 불가 → `++iBoneIndex` 컴파일 오류 |
| `[&iBoneIndex, pBoneName]` | 하나씩 지정 | 이렇게 써도 됨 (더 명시적) |

람다 안에서 센 값을 람다가 끝난 뒤 `return iBoneIndex;`로 꺼내야 하므로 참조 캡처가 필요하다.

#### 9-3. `find_if`와 람다의 동작
`find_if(시작, 끝, 조건)`은 앞에서부터 원소를 하나씩 조건 함수에 넣어 보고, **처음으로 true가 나온 위치의 반복자**를 돌려준다. 끝까지 없으면 `end()`를 돌려준다.
```cpp
// 내부 동작 (개념)
for (auto it = begin; it != end; ++it)
    if (조건(*it))       // ← 여기서 람다가 호출됨
        return it;       // true면 즉시 멈춤
return end;
```

"L_Arm"(5번)을 찾는 과정:
| 호출 | pBone | 이름 일치? | 람다 동작 | iBoneIndex |
|---|---|---|---|---|
| 1 | m_Bones[0] Root | ✗ | `++` 후 false | 0 → 1 |
| 2 | m_Bones[1] Body_Mesh | ✗ | `++` 후 false | 1 → 2 |
| 3 | m_Bones[2] Jacket_Mesh | ✗ | `++` 후 false | 2 → 3 |
| 4 | m_Bones[3] Hips | ✗ | `++` 후 false | 3 → 4 |
| 5 | m_Bones[4] Spine | ✗ | `++` 후 false | 4 → 5 |
| 6 | m_Bones[5] L_Arm | ✔ | **`++` 없이** true → 멈춤 | **5** |

- 일치했을 때는 `++` **전에** `return true`를 하므로, 멈춘 순간의 `iBoneIndex`가 정확히 그 위치다.
- 끝까지 못 찾으면 `iter == end()` → `-1`을 돌려준다.
- 즉 이 람다는 **"이름이 같은지 판단"** 과 **"지나간 칸 수 세기"** 를 동시에 한다.

#### 9-4. 매개변수 타입 문제
`m_Bones`는 `vector<shared_ptr<CBone>>`이다. 그래서 `find_if`가 넘기는 원소는 **`shared_ptr<CBone>`** 인데, 람다는 `CBone*`을 받게 되어 있다. `shared_ptr`은 일반 포인터로 자동 변환되지 않으므로 컴파일 오류가 난다.
```cpp
[&](const shared_ptr<CBone>& pBone)->bool_t { ... }   // 정확한 타입 (복사 없이 참조)
[&](const auto& pBone)->bool_t { ... }                // C++14 이상, 타입 자동 추론
```
- `const &`로 받는 이유: 값으로 받으면 호출마다 `shared_ptr` 복사로 참조 카운트가 오르내린다.
- `pBone->Compare_Name(...)`은 `shared_ptr`도 `->`를 지원하므로 그대로 동작한다.

#### 9-5. 같은 일을 다른 방식으로
람다는 판단만 하고, 위치는 `distance`로 계산하는 방식:
```cpp
auto iter = find_if(m_Bones.begin(), m_Bones.end(), [&](const shared_ptr<CBone>& pBone) {
    return pBone->Compare_Name(pBoneName);
});
if (iter == m_Bones.end())
    return -1;
return static_cast<int32_t>(distance(m_Bones.begin(), iter));
```
람다가 바깥 변수를 바꾸지 않으므로 의도가 더 분명하다. 수업 코드 방식도 동작은 같다. 다만 `find_if`가 앞에서부터 순서대로 호출한다는 점에 기대는 방식이다.

람다 없이 for문으로:
```cpp
for (size_t i = 0; i < m_Bones.size(); ++i)
    if (m_Bones[i]->Compare_Name(pBoneName))
        return static_cast<int32_t>(i);
return -1;
```

### STEP 10. 인덱스 저장 + 정점 BlendIndex 채우기
**m_BoneIndices 저장**
```cpp
/* 이 메시에게 영향을 주는 뼈의 인덱스 추가 */
int32_t iBoneIndex = pModel->Get_BoneIndex(pAIMesh->mBones[i]->mName.C_Str());
if (-1 == iBoneIndex)
    return E_FAIL;

m_BoneIndices.push_back(iBoneIndex);
```
`m_BoneIndices[메시 안 번호 i] = CModel::m_Bones에서의 번호` 형태의 연결표다. 메시는 **CBone 자체가 아니라 번호만** 들고 있고, CBone은 모델이 소유한다.

**뼈 기준 → 정점 기준으로 뒤집기**
```cpp
for (uint32_t j = 0; j < pAIMesh->mBones[i]->mNumWeights; ++j)
{
    if (0.f == pVertices[pAIMesh->mBones[i]->mWeights[j].mVertexId].vBlendWeight.x)
        pVertices[pAIMesh->mBones[i]->mWeights[j].mVertexId].vBlendIndex.x = i;
    else if (0.f == pVertices[pAIMesh->mBones[i]->mWeights[j].mVertexId].vBlendWeight.y)
        pVertices[pAIMesh->mBones[i]->mWeights[j].mVertexId].vBlendIndex.y = i;
    else if (0.f == pVertices[pAIMesh->mBones[i]->mWeights[j].mVertexId].vBlendWeight.z)
        pVertices[pAIMesh->mBones[i]->mWeights[j].mVertexId].vBlendIndex.z = i;
    else
        pVertices[pAIMesh->mBones[i]->mWeights[j].mVertexId].vBlendIndex.w = i;
}
```
- **`mNumWeights` = 뼈 i가 영향을 주는 정점의 개수**다. `mWeights`는 가중치 숫자만 있는 배열이 아니라 `{ mVertexId, mWeight }` 쌍의 목록이고, `mNumWeights`는 그 길이다.
  ```cpp
  struct aiVertexWeight {
      unsigned int mVertexId;   // 영향을 받는 정점 번호
      float        mWeight;     // 영향 비율
  };
  ```
- 바깥 루프는 뼈를 하나씩, 안쪽 루프는 그 뼈가 영향을 주는 정점을 하나씩 돈다. `mVertexId`로 고칠 정점을 찾아 빈 칸에 `i`를 기록한다.
- 정점 기준으로 돌지 않는 이유: Assimp이 데이터를 **뼈 기준**으로 주기 때문이다. 뼈 기준으로 돌면 목록을 한 번씩만 읽으면 된다.
- 예) `mBones[2] "L_Arm"`, `mNumWeights = 3`, `mWeights = {118, 1.0}, {119, 1.0}, {120, 0.6}` → j 루프 3번, 정점 118/119/120의 빈 칸에 2 기록
- 완성된 형태라면 같은 칸에 `mWeights[j].mWeight`도 함께 저장해야 한다.

마지막으로 `CreateBuffer`로 정점 버퍼를 만든다.

## 4. 메시, 정점, aiBone의 크기 감각

- 메시 하나에 정점이 수천~수만 개 있고, 뼈가 있는 메시라면 aiBone 목록도 함께 있다(정적 메시는 `mNumBones = 0`).
- aiBone 하나는 메시 정점 중 **일부**에 영향을 준다. 헬멧처럼 통째로 머리를 따라가는 메시라면 aiBone 하나가 **전체** 정점에 영향을 줄 수도 있다.
- 여러 aiBone의 범위는 겹친다. 관절 근처 정점은 여러 뼈 목록에 들어 있고, 정점 하나 기준으로 가중치 합은 1이다.
- 보통 모든 정점이 적어도 한 뼈에 들어 있다. 어느 뼈에도 없는 정점은 가중치가 전부 0이라 원점으로 찌그러져 보인다.

**뼈 하나가 담당하는 정점 수** (일반 인간형 캐릭터, 뼈 50~100개 기준, 정점 1만 개일 때)
| 뼈 | 메시 정점 중 비율 | 개수 |
|---|---|---|
| Hips, Spine, Chest | 10 ~ 30% | 1,000 ~ 3,000 |
| 위팔, 허벅지 | 5 ~ 15% | 500 ~ 1,500 |
| 아래팔, 종아리 | 3 ~ 10% | 300 ~ 1,000 |
| 손, 발 | 2 ~ 5% | 200 ~ 500 |
| 손가락 마디 | 0.5 ~ 2% | 50 ~ 200 |
| 얼굴 뼈 | 1% 미만 | 수십 |
| 끝 노드, 보조 뼈 | 0% | 0 |
| 헬멧처럼 통째로 따라가는 메시 | 100% | 전부 |

- 뼈 하나의 평균 비율은 대략 `정점당 평균 뼈 수 ÷ 메시의 뼈 수`다(예: 2 ÷ 60 ≈ 3%).
- 겹침 때문에 모든 뼈의 비율을 합치면 150~300%가 되는 게 정상이다.
- 실제 값 확인: i 루프 안에서 출력해 본다.
  ```cpp
  char szBuf[256];
  sprintf_s(szBuf, "[%u] %s : %u\n", i, pAIMesh->mBones[i]->mName.C_Str(), pAIMesh->mBones[i]->mNumWeights);
  OutputDebugStringA(szBuf);
  ```

## 5. 왜 정점에는 메시 안 번호를 넣는가

**두 종류의 번호**
| | 범위 | 예 |
|---|---|---|
| 모델 전체 번호 | `CModel::m_Bones` 전체 | L_Arm = 5 |
| 메시 안 번호 `i` | 그 메시의 `mBones` | Body에서 L_Arm = 2, Jacket에서 L_Arm = 1 |

정점의 `vBlendIndex`에는 **메시 안 번호**가 들어간다. 셰이더가 꺼내 쓰는 배열도 메시마다 **메시 안 번호 순서로** 만들기 때문에, 정점은 모델 번호를 몰라도 된다. 모델 번호로 바꾸는 일은 그릴 때 `m_BoneIndices`가 뼈 수만큼 한 번만 해 준다.

모델 번호를 정점에 직접 넣는 방법도 가능하다. 다만 그러면 메시마다 **모델 전체 뼈**를 보내야 해서 상수 버퍼 한계(64KB = 행렬 1024개)에 걸릴 수 있고 전송량도 늘어난다. OffsetMatrix도 aiBone(= 메시 안 번호) 단위로 주어지므로, 메시 안 번호를 쓰는 게 구조상 자연스럽다.

**메시가 포인터가 아니라 번호를 들고 있는 이유**
- 모델을 Clone하면 **CBone 목록은 복제본마다 따로**(애니메이션 상태가 다르므로), **메시는 공유**하는 게 보통이다.
- 메시가 CBone 포인터를 들고 있으면 공유된 메시가 프로토타입의 뼈만 가리킨다 → 모든 복제본이 똑같이 움직인다.
- 번호만 들고 있으면 각 복제본이 넘겨 주는 `m_Bones`에서 그 복제본의 뼈를 꺼낸다.

**예시: Body / Jacket 두 메시**
```
노드 트리 → m_Bones
 [0] Root  [1] Body_Mesh  [2] Jacket_Mesh  [3] Hips  [4] Spine
 [5] L_Arm [6] L_Hand     [7] R_Arm        [8] L_Leg
 (0~2번은 어떤 aiBone도 가리키지 않음)

Body->mBones   : Hips, Spine, L_Arm, L_Hand, R_Arm, L_Leg
Jacket->mBones : Spine, L_Arm, R_Arm

Body->mBones[2]   "L_Arm" ─┐
                           ├─▶ m_Bones[5] CBone "L_Arm"
Jacket->mBones[1] "L_Arm" ─┘

Body   m_BoneIndices = {3, 4, 5, 6, 7, 8}
Jacket m_BoneIndices = {4, 5, 7}

Body 정점 120 (손목, L_Arm 60% + L_Hand 40%) : Index (2, 3, 0, 0)  Weight (0.6, 0.4, 0, 0)
Jacket 정점 35 (소매, Spine 30% + L_Arm 70%) : Index (0, 1, 0, 0)  Weight (0.3, 0.7, 0, 0)
```
L_Arm 하나를 회전시키면 `m_Bones[5]`와 자식 `[6]`의 Combined가 바뀐다. Body의 팔과 Jacket의 소매가 **같은 CBone을 공유**하므로 함께 움직이고, 옷과 몸이 따로 놀지 않는다.

## 6. 저장한 데이터가 그리기에서 쓰이는 흐름 (다음 수업 예상)

```
[로드할 때 — 한 번]
  Ready_Bones          : aiNode 트리 → CModel::m_Bones
  Ready_Meshes_For_Anim: aiBone.mName    → m_BoneIndices
                         aiBone.mWeights → 정점 BlendIndex/Weight
                         aiBone.mOffset  → m_OffsetMatrices
                         (이후 aiBone은 쓰지 않음)

[매 프레임]
  CModel : 키프레임 → CBone 로컬 행렬 갱신 → m_Bones를 0번부터 돌며 Combined 계산

[메시마다 그릴 때]
  Client 객체 : for (메시 i) { Bind_Material(i); Render(i); }
  CModel::Render(i) : m_Meshes[i]에 m_Bones를 넘김
  CMesh (CPU) :
      for (j = 0 ~ m_iNumBones)
          m_BoneMatrices[j] = Offset[j] × m_Bones[ m_BoneIndices[j] ]->Combined
      상수 버퍼 갱신 → 바인드 → DrawIndexed

[정점 셰이더 (GPU)]
  BoneMatrix = Σ g_BoneMatrices[BlendIndex.xyzw] × BlendWeight.xyzw
  위치 = 정점 × BoneMatrix × World × View × Proj
```

예상 코드:
```cpp
// CMesh — OffsetMatrix 저장 (m_BoneIndices.push_back 근처)
float4x4_t OffsetMatrix;
memcpy(&OffsetMatrix, &pAIMesh->mBones[i]->mOffsetMatrix, sizeof(float4x4_t));
XMStoreFloat4x4(&OffsetMatrix, XMMatrixTranspose(XMLoadFloat4x4(&OffsetMatrix)));
m_OffsetMatrices.push_back(OffsetMatrix);

// CMesh — 그리기 직전
for (uint32_t i = 0; i < m_iNumBones; ++i)
    XMStoreFloat4x4(&m_BoneMatrices[i],
        XMLoadFloat4x4(&m_OffsetMatrices[i]) *
        XMLoadFloat4x4(Bones[m_BoneIndices[i]]->Get_CombinedTransformationMatrixPtr()));
m_pBoneCB->Bind_Vertex_ShaderResource(ETOUI(VSLOT::BONE), m_BoneMatrices);
```
```hlsl
cbuffer BoneData : register(b2)
{
    row_major matrix g_BoneMatrices[256];
};

matrix BoneMatrix = g_BoneMatrices[In.vBlendIndex.x] * In.vBlendWeight.x
                  + g_BoneMatrices[In.vBlendIndex.y] * In.vBlendWeight.y
                  + g_BoneMatrices[In.vBlendIndex.z] * In.vBlendWeight.z
                  + g_BoneMatrices[In.vBlendIndex.w] * In.vBlendWeight.w;
float4 vPosition = mul(float4(In.vPosition, 1.f), BoneMatrix);
vPosition = mul(vPosition, g_WorldMatrix);   // 이후는 기존 VS_Mesh와 같음
```
- **Offset이 필요한 이유:** T자세의 정점을 "그 뼈를 원점으로 하는 좌표"로 옮겨야 뼈가 회전할 때 정점이 뼈를 중심으로 돈다.
- `row_major`는 기존 `g_WorldMatrix`와 같은 방식이라 C++에서 전치 없이 memcpy하면 된다.
- **상수 버퍼:** 메시마다 쓰는 뼈와 칸 순서가 다르므로 **내용 갱신과 바인드는 메시를 그릴 때마다** 한다. 버퍼 자체는 메시마다 만들어도 되고, 최대 크기 하나를 모델이나 엔진이 들고 같이 써도 된다. `D3D11_MAP_WRITE_DISCARD`를 쓰므로 덮어써도 이전 Draw에 영향이 없다.
- 메시는 복제본끼리 공유되므로 **그리기 직전에 채우고 바로 그려야** 한다. 미리 채워 두고 나중에 한꺼번에 그리면 마지막 복제본 값으로 모두 똑같이 그려진다.

## 7. 숫자로 보는 스키닝

```
어깨(0,0,0) ──── 팔꿈치(2,0,0) ──── 손끝(3,0,0)
   L_Arm (m_Bones[5])     L_Hand (m_Bones[6], 부모 L_Arm)
```
| | 값 |
|---|---|
| m_BoneIndices | {5, 6} |
| 정점 A (3,0,0) | Index (1,0,0,0), Weight (1.0, 0, 0, 0) |
| 정점 B (2.2,0,0) | Index (0,1,0,0), Weight (0.5, 0.5, 0, 0) |
| Offset[0] | 이동(0,0,0) |
| Offset[1] | 이동(-2,0,0) (T자세 위치의 역행렬) |

**애니메이션:** L_Hand를 90° 위로 굽힌다. L_Hand Combined = 90° 회전 후 팔꿈치(2,0,0)로 이동, L_Arm은 그대로다.

**정점 A (L_Hand 100%)**
```
(3,0,0) × Offset[1] → (1,0,0) → 90° 회전 → (0,1,0) → 팔꿈치로 이동 → (2,1,0)
```
손끝이 팔꿈치 위로 올라간다. Offset 없이 바로 회전하면 (2,3,0)이 되어 팔이 엉뚱하게 늘어난다.

**정점 B (L_Arm 50% + L_Hand 50%)**
```
L_Arm  : (2.2, 0,   0)
L_Hand : (0.2,0,0) → 회전 (0,0.2,0) → 이동 (2, 0.2, 0)
섞기   : (2.2,0,0)×0.5 + (2,0.2,0)×0.5 = (2.1, 0.1, 0)
```
두 뼈 사이로 둥글게 접힌다. L_Hand 100%였다면 (2, 0.2, 0)으로 칼로 자른 듯 꺾인다. 이것이 BlendWeight의 역할이다.

```
T자세                         아래팔 90° 굽힘

                                   A (2,1,0)
                                   │
●━━━━━━━━━━━●━━B━━━A           ●━━━━━━━━━━━●╮B(2.1,0.1)
어깨      팔꿈치               어깨      팔꿈치
```

## 8. 현재 코드에서 맞지 않는 부분 (수업 중간 상태)

| 위치 | 문제 | 고치는 방향 |
|---|---|---|
| `Model.cpp` `Initialize_Prototype` | `Ready_Bones`가 `Ready_Meshes`보다 뒤에 실행됨 → `Get_BoneIndex`가 항상 -1 | `Ready_Bones`를 먼저 호출 |
| `Model.cpp` `Ready_Meshes` | `CMesh::Create`에 `pModel` 인자가 없음 | 자기 자신을 `shared_ptr`로 넘기기 (`shared_from_this` 등) |

| `Model.cpp` `Ready_Bones` | `int32_t x = { size() - 1 }` → 축소 변환 컴파일 오류 | `static_cast<int32_t>(...)` |
| `Mesh.cpp` `Ready_Meshes_For_Anim` | `vBlendWeight`를 저장하지 않음 → 모든 뼈가 x칸을 덮어씀 | 같은 칸에 `mWeights[j].mWeight` 저장 |

가독성 참고: 이중 for문 안에서 `pVertices[pAIMesh->mBones[i]->mWeights[j].mVertexId]`가 반복된다. `auto& Weight = ...mWeights[j];`, `auto& Vertex = pVertices[Weight.mVertexId];`처럼 받아 두면 읽기 쉬워진다.

## 9. 한 줄 정리
- **CBone (= 노드)** : 모델이 한 벌 소유하는 **움직이는 뼈대**. 매 프레임 갱신되고, 그릴 때 메시가 행렬을 읽어 감
- **aiBone** : 메시를 뼈대에 붙이는 **연결 정보**. 로드할 때 정점(가중치)과 `m_BoneIndices`(번호)로 옮겨진 뒤 역할이 끝남
- **m_BoneIndices** : 정점의 메시 안 번호를 **모델의 CBone 번호로 바꿔 주는 연결표**
- **정점 최종 위치** : 최대 4개의 `(Offset × Combined)` 행렬을 가중치로 섞어서, GPU 정점 셰이더에서 곱한 결과
